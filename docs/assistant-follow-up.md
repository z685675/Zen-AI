# 智能助手：追加消息与运行中调整

新版智能助手运行任务时，输入框保持可用，发送按钮与 AI 对话保持一致：

- **排队发送**（默认）：等当前任务完成后，按加入顺序逐条发送。适合“完成后再做下一件事”。
- **引导**：先发送消息，再点击这条排队消息旁的“引导”，将它的文字和附件一起交给当前任务。助手会在后续处理步骤中读取补充要求；当前模型请求和工具保持原生执行流程。

“引导”按钮悬浮提示会说明用途。没有运行中的任务时，按钮置灰并说明原因；当前任务暂时不能接收时，明确未提交的消息会保留排队。接收结果不明时不会重复提交。

发送后可继续输入，不必等待当前任务结束。切换会话或页面，待发送内容仍会保留。

## 待发送面板

- 未发送的消息支持编辑、移除；编辑时会放回输入框，确认后重新发送。
- 队列可以暂停或继续，两个按钮均有悬浮说明。暂停队列时，当前任务继续执行，后续消息保留等待；继续队列后，等待当前任务完成，再按顺序发送。点击停止当前任务时，队列同时暂停，避免马上执行下一条。
- 当前任务报错后，队列暂停。先查看执行结果，再决定是否继续剩余消息；失败的消息不会自动重试。
- 重启软件后，保留的队列默认暂停，需要点击“继续队列”。重启前发送状态未确认的消息不会自动重发。
- “收起记录”只隐藏接收记录，不会撤回已经提交的消息。

## 运行中调整的状态

- **已接收**：内容已保存到当前原生会话，等待后续处理；这不代表已经执行完成。
- **已进入后续处理**：已经观察到以补充消息为上下文的后续助手步骤。
- **等待继续**：内容已保存，当前任务已结束，但尚未确认这条补充已进入后续处理。先核对对话结果，再按需点击“准备继续”放回输入框，确认后发送。
- **接收状态待确认**：连接或软件重启使接收结果无法确认。可核对接收状态和对话记录，避免重复发送。
- **未发送**：任务正在启动、已经收尾或输入不符合要求。内容仍保留，可编辑后重新发送。

## 本地验收

1. 在新版智能助手启动一个需要多步处理的任务。
2. 运行时发送两条“排队发送”消息，确认当前任务继续运行，后续消息按顺序执行。
3. 另开任务，发送“先总结，再给出引用”，确认消息先排队；悬停查看提示，再点击该消息旁的“引导”，确认后续处理收到补充要求，同一条消息没有重复发送。
4. 输入下一条消息但不发送，切换会话、切换页面再回来；确认草稿和待发送面板仍在。
5. 队列中有消息时停止任务，确认队列暂停；点击“继续队列”才执行剩余消息。
6. 重启软件，确认保留的队列默认暂停，未确认的发送不会被自动重复执行。

## 实现边界与验证依据

排队发送复用既有正常发送流程，每个会话串行提交；运行中调整使用内置 OpenCode 1.19.4 的原生 `prompt_async`，不新增代理执行循环，不自动重试结果不明的提交。

该原生版本没有独立的 queue/steer 参数。运行中补充会在后续模型步骤读取；任务最后一次读取历史与结束之间存在很窄的窗口，补充可能只保存而未处理。客户端通过持久化消息及助手的 `parentID` 提供接收与进入处理的证据。没有直接处理证据时保留为“等待继续”，需要先核对结果，不据此自动重放。

自动化检查覆盖去重、模糊接收、排队顺序、停止/失败暂停、重启恢复、草稿保留和收尾窗口。另用内置 1.19.4 二进制及本地模拟模型验证了两种场景：第一轮模型回答处理中提交补充，以及工具等待授权时提交补充。两种场景的第二次模型请求均包含补充要求；工具场景还确认保留了正常工具返回结果。同一原生会话内正常结束，未请求付费模型。
