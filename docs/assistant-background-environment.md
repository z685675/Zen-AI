# 新版助手：后台自动准备环境

## 用户体验

- OpenCode 内核和配套资源随 Zen AI 安装包提供，不需要用户安装 OpenCode。
- 软件启动后，后台检查并按需准备 Bun、UV/UVX 和 Zen AI 私有 Python；不要求用户提前打开设置页面。
- 已就绪组件直接复用，不重复下载，不修改系统 Python 或系统环境变量。
- Git 不在环境检测和安装清单中，也不再通过此页面提供系统 Git 安装。已有 Git 不卸载，仓库操作仍可使用它。
- 普通对话、浏览器和已就绪工具不等待环境准备。复杂 Python 任务需要私有 Python 准备完成。
- 首次下载失败时，首次尝试结束后约 1 分钟重试；再次失败，约 5 分钟后再试一次。每次只处理仍未就绪的组件，不无限轮询；重启软件或点击修复可再次尝试。
- 自动准备不弹安装完成/失败通知。设置页显示后台准备状态和检测结果，手动修复只有全部组件就绪时才提示完成。

## 实现边界

- 设置页面与启动预检共享检测缓存、准备状态和单次修复流程，避免重复安装。
- 新版 OpenCode 进程的 PATH 增加应用工具目录。即使进程先启动、工具后完成准备，也可从该目录找到 Bun、UV/UVX。
- 私有 Python 通过现有 `python_execute` 工具运行；不把系统 Python 注入新版内核，也不在每次对话前启动 Python 探测。
- 不改变 OpenCode 原生任务循环、压缩、模型配置或权限机制。第三方 Skill/MCP 的额外依赖不属于自动准备范围。
- 当前自动准备流程随应用启动执行；Bun/UV 下载与私有 Python 准备沿用已有安装器。

## 验证

- 自动化：已有环境复用、启动与手动修复合并、部分失败继续准备其他组件、有限次数重试、恢复后停止重试、可选沙盒联网不影响安装判定。
- 自动化：Git 无检测/安装调用，应用目录来源标记正确，PATH 大小写统一且不带入模型密钥。
- 原生内核本地冒烟：先启动 OpenCode，再向临时工具目录写入测试工具，验证原生命令执行能找到该工具；不调用真实模型、不安装系统组件。
- 手工：在干净 Windows/macOS 用户环境启动，正常导入 Provider 后先发送“你好”，同时观察环境页面逐步就绪；不用安装 Git。
- 手工：准备完成后发送“把这些销售数据按月份汇总，计算每个月的增长率，再做成 Excel”，确认私有 Python 工具和文件输出正常。
- 手工：断网首次启动，确认不会阻止普通界面使用；恢复联网后观察有限重试或点击修复，不要删除真实用户环境来模拟测试。
