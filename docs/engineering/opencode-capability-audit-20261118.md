# 智能助手与 OpenCode 能力对照及补齐建议

日期：2026-11-18。产品基线：Zen AI 1.1.86，内置 OpenCode 1.19.5。

本轮完成代码对照与本地模拟模型验证，未修改应用功能、调用付费模型、启用实验功能或推送代码。报告中的“已具备”表示存在对应接入代码；不代表本轮重新验收了所有真实用户场景。

## 结论

目前使用完整的 OpenCode 原生执行内核，任务执行、工具调用、原生压缩和历史分支已有接入。主要缺口集中在子助手的产品接入、交互式提问和扩展工具，而非基础执行工具被删除。

最需要优先完成的是：子助手授权与共同约束、子助手生命周期和用量归集、结构化问答，以及升级到经过回归的 1.19.6。文件变更清单与可控回退、精选 MCP 接入适合下一阶段。

## 能力对照

| 能力 | 当前接入情况 | 对用户的影响 | 建议 |
|---|---|---|---|
| 原生任务循环、工具调用和失败重试 | 使用原生内核；产品层另有取消、无进展截止和重试等待上限 | 已可完成日常任务 | 保留，避免重写循环 |
| 文件查找、读取、修改、命令执行 | 原生工具已保留，并连接办公文件与浏览器工具 | 基础执行能力已有 | 不属于缺失 |
| Plan / Build | 已映射原生模式，并配置只读权限 | 用户可区分分析和执行 | 保留产品明确的模式切换方式 |
| 原生上下文压缩、长输入处理 | 已接入原生压缩；另有模型容量同步和大输入材料保存 | 支持长任务继续处理 | 继续做场景回归，不另起一套压缩内核 |
| 会话继续、追加引导、重试、删除、分支 | 已接入同一原生会话和原生历史分支 | 用户可以延续和调整任务 | 不误列为缺失 |
| General / Explore 子助手 | 内核提供，普通模式未禁用 task；模型可发起委派 | 基础委派存在，但完整体验尚未接好 | **必须补齐后再推广多助手协作** |
| 子助手授权与稳定行为约束 | 主流程和授权补查只接受父会话 ID；父请求 system 不自动传入新子会话 | 子助手遇到审批可能等待；不能假设它自动知道产品规则和用户专属约束 | **优先修复** |
| 子助手进度、取消、完成判断、用量 | 子事件被过滤，普通工具卡不能完整反映子任务；完成用量按父会话汇总；后台实验未启用 | 难以知道谁在工作、花了多少、是否全部结束 | **与授权修复成套补齐** |
| 交互式澄清问答 | question 权限为 deny，当前 client 标识也不默认开放该工具；没有对应原生问答事件界面 | 助手可以用文字提问，但缺少可暂停、选择、填写并继续执行的原生交互 | **非常值得补充** |
| 自定义 MCP | OpenCode 配置仅连接产品内置 assistant、browser；未读取 session.mcps；新版设置隐藏旧 MCP 入口 | 新助手暂不能直接调用用户另行配置的其他 MCP 服务 | 下一阶段接入经过筛选的服务及明确的外部加载入口 |
| Skill 加载和管理 | 已把启用的内置、外部技能交给原生加载；有技能检查入口 | 已具备主要技能使用能力 | 不需要重做技能系统 |
| 原生插件 | 禁用默认插件和项目自动发现，但启动时实际加载产品自有 completion-guard 插件 | 内部插件机制可用；第三方插件没有产品适配流程 | 精选并固定版本接入，符合现有产品方向 |
| 原生网络搜索与网页读取 | 原生 websearch 被替换为产品搜索；原生 webfetch 仍存在，另有正文、论文和浏览器工具 | 已有搜索与阅读能力 | 不需要仅为“对齐原生”再增加重复入口 |
| 文件变更清单和原生快照回退 | snapshot=false；已有部分覆盖确认及文件备份机制，暂无覆盖所有原生编辑/命令的统一变更清单和回退 | 对话分支不等于恢复磁盘文件，修改多个文件后不够容易核对 | 第二阶段优先评估，按工作区和文件范围实现 |
| 自动格式化、语言服务、代码导航 | formatter=false、lsp=false，部分语言工具也属于实验选项 | 主要影响编程项目，普通办公任务收益有限 | 仅在开发任务有明确需求时增加 |
| 自定义 Agent、原生斜杠命令、项目配置自动发现 | 没有提供对应通用加载界面；项目配置发现被关闭 | 高级用户不能原样搬入整套原生配置 | 按需支持选定能力，不开放任意配置覆盖 |
| 子助手异步后台、Code Mode | 当前 1.x 的对应实验开关未启用 | 少了主助手边工作边等子任务、以及精简工具目录输入的潜在收益 | 在基础生命周期稳定后单独验证 |
| 分享会话、内核自行更新、任意默认插件自动加载 | 主动关闭 | 由产品统一发布和管理 | 保持现状 |

## 本地验证证据

使用实际安装的 1.19.5 可执行文件、现有配置构造函数、现有授权监听器和现有用量汇总器。模型响应由回环地址上的模拟服务提供，使用合成文件，没有访问真实用户材料。

为了隔离测试，关闭了本次探针的产品 MCP 连接，并对合成文件读取增加 ask 权限；这两项是测试覆盖设置，并非修改产品配置。该探针验证原生行为与现有接入函数，未运行完整 Electron 界面。

### 1. 子助手的权限请求未被现有监听器接收

- 原生 general 子助手真实创建了独立会话。
- 子助手发出的 permission.asked 使用自己的 session ID。
- 现有主事件过滤逻辑只接受父会话；原样使用的授权补查监听器运行多个周期后匹配数仍为 0。
- 探针独立拒绝了该合成读取，原生任务随后正常结束。

这说明一旦子任务遇到原生审批，产品接入存在无法展示审批的风险。不能只增加“正在创建子助手”的界面提示就认定功能完整。

代码依据：

- `src/main/services/agents/services/opencode/index.ts:625`：按父会话过滤事件。
- `src/main/services/agents/services/opencode/permissions.ts:27`：补查只接受指定父会话。
- 上游 `packages/opencode/src/tool/task.ts`：创建带 parentID 的独立会话。

### 2. 父请求的专属系统指令没有自动进入子请求

给父请求加入唯一的合成 system 标记后，模拟服务观察到父助手两次请求均包含标记，子助手两次请求均不包含标记。这符合原生子会话独立上下文的设计。

产品需要显式传递稳定的共同约束、当前用户授权和必要的子任务说明。不能依赖主模型每次都在委派文字里重述，也不应直接复制完整父会话造成额外输入开销。

代码依据：

- `src/main/services/agents/services/opencode/index.ts:309`：将产品、用户、工作目录和模式指令组装到父请求 system。
- `src/main/services/agents/services/opencode/config.ts:112`：公共 instructions 为空。
- 上游 `packages/opencode/src/tool/task.ts`：子任务调用没有复制父请求 system。

### 3. 父会话完成用量不包含子助手的模型请求

本次合成响应产生父助手两次、子助手两次模型请求：

| 统计方式 | 输入 Token | 输出 Token |
|---|---:|---:|
| 模拟服务实际返回的所有请求用量 | 600 | 40 |
| 现有父会话历史汇总函数 | 200 | 20 |

当前传输诊断能观察所有经过网关的请求，因此不能据此认定 API 计费遗漏。缺口是产品完成汇报、父子任务归属与诊断总量之间需要统一口径，防止遗漏或重复计数。

代码依据：

- `src/main/services/agents/services/opencode/index.ts:864`：完成事件使用 state.usage()。
- `src/main/services/agents/services/opencode/transform.ts:196`：汇总当前已收集的父会话消息。
- `src/main/services/agents/services/opencode/index.ts:253`：传输观察另有全请求用量通道。

## 建议实施顺序

### 第一阶段：形成可验收的完整协作能力

1. **修复子助手授权和共同约束。** 建立父子会话归属，只处理本任务树的权限；把必要的产品规则和用户约束传给子助手。不同会话的权限不能串用，Plan 的只读限制必须保留。
2. **补齐子任务管理。** 展示子任务名称、进度、结果和失败；停止主任务时验证子任务、工具和请求均结束；父任务只有在必要子任务结束或被明确取消后才能完成。归集全任务用量，并设置独立的子助手并发及预算。普通 1 个、开发者 3 个的现有“对话任务数”规则继续按会话计算，不能误用成任务内请求数限制。
3. **接入结构化问答。** 支持选项和自由输入、等待状态、回答后继续、取消和重新进入会话后的处理。仅开放 question 权限不足以完成接入，还要连接工具注册、事件和界面。
4. **评估并回归升级 1.19.6。** 该版本修复了多图历史使请求过大，以及请求体过大错误触发压缩恢复的问题。同步原生运行依赖后，回归多图、长输入、工具调用、取消和压缩。

第一阶段验收应覆盖：两个独立子任务、子任务申请权限、拒绝后收尾、主任务取消、子任务失败、并发上限、完整用量，以及简单问答不额外创建子助手。

### 第二阶段：补充高价值扩展

- **文件变更清单与可控回退。** 优先解决用户看不清改了哪些文件、需要恢复原件的问题。原生 snapshot 与 Git 工作区相关，不能对所有办公目录直接无条件启用；现有备份机制要继续保留。
- **精选 MCP 服务。** 由产品方选取、固定版本和权限，并提供状态与错误反馈；保留明确的外部加载方式。无需增加插件市场入口。
- **精选子助手角色和工具目录优化。** 先复用 general/explore，待数据证明收益后，再增加专业角色、不同模型或实验 Code Mode。

## 第一阶段实施记录（2026-11-18）

上述四项已在本地实现，验收步骤见 [智能助手协作与问答验收](../testing/opencode-collaboration.md)。审计发现部分保留原始版本和代码位置，作为变更前的证据。

- 父子会话按原生 parentID 核对，子权限归属于当前主会话；共同规则传入 general / explore，Plan 与 Explore 的只读约束保留。
- 补齐最多两个并发的子任务管理、可见进度、停止与旧轮次等待清理；使用完整传输用量汇总全任务，避免遗漏子请求或重复累计。
- 原生 question 接入选项和自由输入表单；跳过问题按空答案继续，返回会话后仍可处理等待中的问题。断线后可恢复漏收的子工具结果。
- 内核与离线依赖同步至 1.19.6。使用实际内核和本地模拟模型验证分工、排队、子授权、选项问答、跳过后交付、跨会话隔离、主任务取消，以及 HTTP 413 原生压缩恢复。

第二阶段的文件变更回退、外部 MCP 和精选角色扩展未在本轮实施；本轮未提交、推送或发布。
