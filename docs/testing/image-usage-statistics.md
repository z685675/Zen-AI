# 图片模型用量统计

## 统计与计费

- 图片模型的用量单位是调用次数，每条消费记录计一次。外部接口一次调用返回多张图片仍计一次；工作台选择多张时会拆成多个单图任务，例如两张对应两次调用。
- “全部”始终显示图片调用次数（无图片记录时为 0）；“AI 对话”和“智能助手”不显示图片卡片、图片次数列、图片趋势或纯图片模型行，服务端查询也排除图片请求。
- 图片模型不再累计到本页的输入、输出、缓存 Token，也不参与文本缓存命中率的完整性判断。
- 汇总、模型列表、每日数据和按周／月聚合使用同一口径。图片趋势使用独立坐标，纵轴为整数次数。
- 统计单位与 API 定价配置独立。修改显示不会修改实际扣费；如需按次扣费，管理员仍需在 API 面板为对应模型配置按次价格。实际价格还可能受到数量、尺寸和分组倍率影响。
- 仅统计现有消费日志；错误和退款日志不作为额外调用累计。历史记录按同一规则重新查询，无需迁移数据库。

## 识别与兼容

- 优先识别日志中的图片生成、编辑、变体接口路径，也支持已知图片模型名称和映射后的上游模型名称。
- 普通视觉模型读取输入图片，或文本模型使用图片工具，不会因此把整个文本请求改记为图片模型调用。
- API 的 `/api/usage/token/statistics` 在汇总、模型和日期指标中新增 `image_request_count`，`request_count` 继续表示所有消费请求数。
- 图片 Token 的原始消费日志和实际结算保持原样，本次调整作用于用量统计接口的展示指标。
- 需要部署 Zen-API 并发布 Zen-AI 客户端。新客户端兼容未返回新字段的旧服务端，但旧服务端仍使用原来的 Token 统计口径。
- 使用自定义名称且历史日志缺少接口路径和上游映射名时，无法可靠识别图片请求；应核对对应日志，避免将普通文本请求误记为图片调用。

## 验收

1. 同一密钥调用一次文本模型，再在工作台选择生成两张图片，等待两个任务结束。
2. 进入“我的用量”，选择“全部”和相同服务、时间范围：图片调用次数应为 2，文本 Token 仅包含文本模型的用量。切换“AI 对话”和“智能助手”后，图片统计应隐藏；切回“全部”应恢复。
3. 图片模型行仅显示调用次数，Token、缓存和命中率列显示横线；文本模型保持原显示。
4. 对照消费日志检查 OpenAI 图片接口与 Gemini 图片模型，确认都计入次数。
5. 切换按日、周、月，次数总和不变；悬停或键盘聚焦图片趋势，提示中只显示对应日期的调用次数。
6. 只保留图片记录的日期范围：显示图片次数卡片和趋势，不显示 Token 汇总卡片；不能显示为“没有用量记录”。
7. 混合文本和图片的日期范围中，已有完整缓存数据的文本请求仍应显示正确命中率。
8. 使用不同用户或密钥查询，确认不会混入其他密钥的记录。

## 工作台多张生成

- 原逻辑把选择的数量写入单次请求的 `n`，所以生成两张时 API 只有一条调用日志。截图中的“已保存 1 / 2 张”对应上游只返回一张的情况，程序已保留该图片，并没有把两张结果只展示一张。
- 新逻辑在提交前把数量展开为独立任务，每个任务都传 `n=1`，使用不同任务 ID，并共享本批 ID。每个任务有自己的消费记录、结果和状态；多模型比较按“模型数 × 每模型张数”展开。
- 提交前显示总调用数和分别计费提示。最多同时执行两个任务，其余排队；一批最多四个模型、每模型四张，共十六个单图任务。
- 一次提交只在历史中显示一条记录，批次分页也不会拆开同一次提交。上方缩略图可横向滚动，下方只展示一张大图，支持前后翻页及键盘左右键，包含当前图片的服务商、模型、状态和任务诊断。
- 保存、复制和用作参考图按钮独立于图片预览区域，始终操作当前页。预览高度受窗口限制，任务信息在主区域内滚动，避免图片把按钮裁掉。
- 运行中、失败的请求保留自己的缩略图位置；单张结果读取失败也不影响其他图片。旧版单任务返回多张图片的记录同样支持翻页；没有批次 ID 的旧记录不会被猜测合并。
- 复用参数恢复本批模型选择和每模型张数；删除记录会删除整批已结束任务及其专属本地图片。界面合并不改变各请求的调用次数、计费和诊断 ID。
- 历史上的少图结果和不确定任务保持原状态，不会自动补发付费请求。用户主动生成会创建新任务。

验收：选择 GPT 图片模型、生成张数为 2，应看到提交两次调用的提示，最终两个任务各有一张图片，并合并为一条含两张缩略图的历史记录。选两个模型各两张时应显示四次调用，API 应有四条相应消费记录；点击缩略图或前后按钮应切换图片、模型和诊断信息，不应重新调用模型。使用竖图、横图、较小窗口及深色主题检查保存、复制按钮均可完整显示。可用每次只返回一张图片的测试服务复现，确认每次实际收到的 `n` 均为 1。
