# 本轮诊断包：成功、缓慢、执行中与失败场景

## 用途与入口

AI 对话和新版助手现在都可以导出某一轮的诊断 ZIP，不要求先报错。

- 回答结束后：回答下方的「更多」→「导出本轮诊断包」。
- 回答仍在进行：消息旁的「导出本轮诊断包」。新版助手也可使用会话右上角的「更多」导出当前轮。
- 失败时：原有错误诊断导出仍保留；普通本轮导出同样可用。

导出不会重新提问、重新执行任务或调用模型分析，也不会自动上传。若 Provider 支持 Zen API 诊断接口，会进行有超时上限的只读查询，以补充后台接收、渠道尝试和返回证据。

## 隐私

确认窗口默认不勾选「包含本轮对话及工具内容」。默认只导出诊断元数据，不含对话正文、工具参数/结果、原附件或完整历史。系统版本、本机运行组件路径、模型/Provider 标识、请求编号、工具名称等诊断信息仍会包含，应仅交给可信的排查人员。

确需排查具体内容时才勾选该项。敏感凭据仍会脱敏，长内容会按有界规则截断；导出前请确认本轮没有不愿分享的个人信息。原有错误导出沿用其已有内容及隐私提示。

## 优先查看

1. `本轮耗时报告.md`：结果、完成用时、首次内容/正文、HTTP 与工具时间线、最长已观测阶段及缺项。
2. `performance.json`：同一份结构化时序数据。
3. `zen-api-evidence.json`：后台关联证据（如果接口、权限和记录可用）。
4. `timeline.json`、`collection-manifest.json`：原始脱敏事件，以及过期、截断、采集失败情况。

输入 Token 包含缓存读取 Token，缓存不再重复加到输入中。请求、工具、压缩及用户等待可能并行或重叠，不能把所有阶段时长直接相加。首批网络数据不等于模型首字；首次内容可能只是思考，首次正文另行记录。

「回复结束至界面提交」只采纳同一消息组件在持续可见期间观察到本轮从执行中变为完成、失败或停止的 React 提交。切换会话后重新挂载、窗口隐藏期间完成、缺少结束时间或旧版未验证的 `render-committed` 事件均显示「未采集」，不会补算为几分钟的界面延迟。它不代表屏幕绘制时间，也不计入模型首字或请求完成用时；有有效连续观察证据的真实长延迟仍会保留。

## 快速人工验收

每项在 AI 对话、新版助手各测一次，涉及工具的项只测新版助手。不要求使用特定模型。

### 1. 成功回答

提示词：

```text
请给我三个适合下班后放松的小建议，每条不超过两句话。
```

回答结束后导出。应看到成功状态、当前模型和 Token；有记录的阶段显示耗时，缺项写明「未记录」。未勾选内容时，ZIP 内不应出现这段问题或回答正文。

### 2. 执行中与手动停止

提示词：

```text
帮我设计一份七天的学习计划，每天安排上午、下午和晚上，并解释安排的理由。
```

等待期间导出一次，再手动停止并导出。执行中包应显示快照状态，未结束阶段不应被写成失败或零耗时；停止后的包应与实际状态一致，导出本身不能重试任务。

### 3. 工具和文件

提示词（仅新版助手）：

```text
帮我新建一份简单的周计划表，安排周一到周五每天一项工作，保存成 Excel，给我打开文件的入口。
```

检查任务正常产出，导出后能看到已观测的工具起止。如果出现权限确认，等待期间导出，报告应将用户等待与模型/工具耗时区分；重叠时不宣称已经精确扣除了等待时间。

### 4. 选择正确的一轮和隐私选项

在同一会话连续发两条不同问题。分别对两条回答导出，核对消息 ID 和模型，不能总导出最后一轮。打开确认框后切换会话，再确认，仍应导出原先选择的一轮。

另选一轮无敏感内容的回答，勾选包含内容后导出：应有本轮问题、回答及已加载工具内容，不应自动打包其他轮次完整历史或附件原件。

### 5. 历史记录和无法采集

打开更新之前的旧对话并导出，应允许保存，但明确标注旧请求、缺失或过期记录，不能补造耗时。取消保存或采集失败后应能再次导出，不应锁死按钮，也不应影响继续对话。

界面计时回归：保持当前会话可见直至回复结束，应有经过验证的界面提交记录；执行期间切到其他会话或页面，完成后再返回，不能补记该值。隐藏窗口期间完成再返回同样不补记。重新导出包含旧版 174.85 秒记录的诊断数据时，该项应为「未采集」，旧事件可保留在原始时间线中供核对，但不作为界面卡顿证据。已采集的有效界面提交不能被后来重新打开会话的时间覆盖。

## 判断边界

### 服务器与上游分段计时

客户端和 Zen-API 均更新后，`本轮耗时报告.md` 和 `performance.json.serverRequests` 会按请求编号列出服务器前置处理、各次渠道尝试及 HTTP 计时。AI 对话与新版助手的每次模型请求共用该记录；复杂任务的多次请求、工具和授权等待分开查看。默认不包含内容的导出也保留这些安全计时。

- 服务器前置阶段：请求体就绪、路由就绪、校验、Token 估算和额度准入，均从服务器收到请求起算。
- HTTP：DNS、TCP、TLS、连接复用、连接就绪、发送完成、首字节、发送后等待、响应体读取和结束。连接复用时没有发生的阶段不补零；采用其他传输实现的渠道可能缺少 HTTP 记录。
- 共享 SSE 解析：首个事件、有效内容（正文、思考或工具）、首次正文，及实际首次非心跳转发。内容分类覆盖 OpenAI Chat/Completions/Responses、Anthropic 和 Gemini；未知格式及超过 64 KiB 的单帧不推测内容时间。不会保存帧内容。
- 请求、渠道尝试和 HTTP 调用各用自己的计时起点。不同机器的时间戳不直接相减推算单向网络耗时。API 外耗时只比较匹配请求的完整时长，包含本地、网络及其他前后处理。
- 每次渠道尝试最多保留 8 条 HTTP 记录（最初 2 条和最近 6 条），额外数量明确记录。既有请求、事件和查询上限仍然适用；执行中、旧服务端及未覆盖渠道写明缺项。计时只观测原请求，不增加生成、测速、重试或重放。

验收：在 AI 对话和新版助手分别发送简短问题，再让新版助手完成一次需要工具的任务；导出后核对每次客户端 HTTP 请求与服务器请求编号。用更新前的历史记录确认显示缺项，而不是零耗时。

- 新增时序事件只能覆盖更新后运行的任务，不能恢复过去未采集的信息。
- 事件按最近操作有界保存；长任务中间事件可能被截断，记录丢弃数量。
- 点击发送前后的附件上传、系统实际绘制等未覆盖环节不会被冒充为已测量。
- 客户端时长只能定位「慢在哪个可观测环节」，不保证单凭 ZIP 就判定上游内部根因。后台没有记录不等于请求从未到达；后台写出成功也不等于客户端一定完整收到。

## 同批修复的人工检查

### 默认请求参数升级

升级前，在默认助手设置打开温度、Top-P 和最大输出 Token 限制，并填入容易辨认的值。首次运行包含本次修复的版本后，三个开关应关闭，原数值、模型和对话应保留。之后手动打开并重启，不能再次被关闭。自建角色的独立参数不应被重置。

已经安装的 1.1.74 包不包含这次补丁；需要运行最新开发构建或后续安装包才能验证升级迁移。

### 紧凑执行过程和产出

使用上面的 Excel 提示词。新版助手应显示一条紧凑的「思考与执行」记录，执行中的工具名称仍可见，详细思考、工具输出和单项失败信息按需展开。授权请求不能藏在折叠区域内，应能检查操作内容并同意或拒绝。

任务产生的文件应在回答末尾保留快捷入口；切换会话再返回仍可打开文件和所在文件夹。AI 对话沿用原来的工具/思考展示，不应用新版助手的紧凑布局。

### 长任务与继续执行

新版助手交互任务不再按累计执行15分钟截停：有新的有效思考、正文或工具调用/结果时刷新无进展计时。仅「忙碌」心跳、轮询或断线重连不会刷新。连续15分钟无有效进展仍会暂停；授权/网页登录等待另受累计30分钟保护。底层请求、工具及上游重试仍有各自的保护，不承诺无限等待。

不必为了人工验收故意等待15分钟，自动测试已使用虚拟时间覆盖40分钟持续工作的情况。可以手动停止上面的建表任务，然后点击最新回答操作栏的「继续执行」；因故障暂停的卡片也提供同名按钮。应追加一轮到原会话，保留中断前的文字、文件及结果，由助手先检查现状再补齐。它不是从中断的进程指令位置精确恢复，也不保证模型永不重复操作；既有权限与文件保护仍然生效。

「重试任务」仍是另一种操作，可能回退重做，需确认；不能用它代替继续执行。老回答后面已有新消息或会话仍在运行时，不提供继续旧任务的按钮，避免重复执行和乱序。定时/无人值守任务的既有总时长保护没有因本次交互任务调整而取消。
