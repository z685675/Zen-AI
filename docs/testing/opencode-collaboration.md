# 智能助手协作与问答验收

实现基线：OpenCode 1.19.6。面向新版智能助手，原生 Task 负责执行和等待子任务。未开启实验性后台子助手，也未变更原生任务循环和压缩流程。

## 本次行为

- 普通助手任务可以按需调用 general / explore；简单问答继续直接回答。
- 每轮最多同时执行两个子助手，多出的子任务等待空位；每轮最多接受 16 次委派，达到上限后拒绝额外委派，保留已有执行记录和结果。
- 这是任务内的子助手限制，与普通模式 1 个、开发者模式 3 个同时运行对话的规则分别计算。
- 子助手获得产品规则、用户设置的助手指令、工作目录要求和 Plan / Build 规则。Explore 保持只读，不能因分工扩大文件权限。
- 主界面显示子任务描述、排队、执行、等待授权/回答及终态。子助手工具操作进入执行记录，其独立回答不混入主助手正文。
- 事件连接恢复后，从子会话历史补齐漏收的工具结果和回答记录；不会重复执行任务，也不会把旧一轮的用量重复累计。
- 子助手的原生权限请求归属于当前父会话；其他对话的请求不被接管。已有子助手只允许被原来的父会话继续使用。
- 主任务结束前核对子任务状态。停止主任务会结束原生进程及其请求；跳过重复操作时，旧的子任务排队和问答等待随原生中断清理。
- 完整的传输用量优先用于全任务汇总，不能与原生父子历史再次相加。传输用量不完整时使用已观察的父子会话用量，保留诊断中的完整性信息。
- 原生 question 接入现有问答卡片，支持单选、多选和自定义回答。取消问题使用原生的空答案报告未作答，助手继续执行；停止整个任务仍由停止按钮处理。
- 交互问题显示在当前会话输入区上方；切换对话不丢失正在等待的问题。已有结果中的回答随正常工具记录保存。

## 开发版人工验收

完整退出旧开发进程，再运行 `pnpm dev`。选择支持工具调用的模型。

1. **简单对话**：发送“你好”。应直接回复，不强制创建子助手。
2. **分工与进度**：在工作目录准备两份小文本，让两个子助手分别读取并检查，再由主助手汇总。应看到两项协作任务，最终统一交付。
3. **排队与并发**：明确要求分别检查三份互不关联的材料。观察最多两个子助手执行，多出的委派等待；材料必须独立，避免同时编辑同一文件。
4. **授权**：让子助手读取明确指定的工作目录外文件。应显示针对该文件的授权；拒绝后助手应说明缺口或调整做法，不能悄悄授予更大权限。
5. **问答**：发送“先用选项问答确认报告面向管理层还是技术人员，以及交付 Word 还是 PPT，等我回答后继续”。应出现问答卡片，回答后继续执行。
6. **多选和自由输入**：让助手提供多个可同时选择的选项，并测试自定义回答。包含逗号的选项应作为一项返回，不得拆错。
7. **取消问题**：点击问答卡片的取消。助手可根据已有信息继续或说明仍缺少什么，不应把它当作停止整个任务。
8. **会话切换**：问题等待时切换到其他会话，再返回。问题应仍可回答，其他会话不能替它作答。
9. **停止任务**：在子助手执行或等待回答时停止主任务。协作状态应收尾，模型请求应结束，旧问答不能继续提交。
10. **Plan**：切换 Plan 后要求分析任务，必要时使用 Explore。不得创建交付文件、执行写操作，或通过子助手绕过只读限制。
11. **历史与分支**：完成有子助手参与的任务后分支对话。新分支需要新的子助手，不得直接继续其他父会话的子任务。

## 自动验证

不调用真实 Provider 的原生集成命令：

```powershell
pnpm exec tsx --tsconfig tsconfig.node.json scripts/opencode-collaboration-smoke.ts
pnpm smoke:opencode --context-recovery
```

第一条验证三项分工、两个并发、子权限、问答与取消、共同指令、同父会话继续和跨父会话阻断，以及停止主任务时关闭子模型连接。第二条使用模拟的 HTTP 413 请求体过大错误，验证原生压缩恢复、压缩失败终止和长输入材料读取。

单元及界面测试覆盖父子授权归属、排队取消、总次数限制、取消旧一轮后继续、独立用量归集、问题回复与结束先后顺序、多选格式、重复提交防护，以及切换会话后的表单显示。

2026-11-18 本地检查结果：`pnpm test` 全量 621 个文件通过，7,238 项通过、9 项跳过；随后断线恢复与跳过问题的增量专项 81 项通过。`pnpm lint`、`pnpm format` 和上述两项实际内核集成检查均通过。实际模型与桌面界面的人工验收按上表进行。
