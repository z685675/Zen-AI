# 模型日 Token 额度：设置与人工验收

## 部署与设置

先更新 Zen API，再使用含本功能的 Zen AI 开发版/新版安装包。尚未发布；已经安装的旧版本不会因本地代码变更自动获得新功能。

AI 对话与新版智能助手发送前不再访问独立的 `/api/usage/token/model-daily/turn` 额度接口。首次正式模型请求在 API 内部完成鉴权、额度准入及任务授权；同一任务的后续调用复用授权，包括 AI 对话的上下文压缩和助手的工具循环。客户端在内存里生成私有随机凭证，只有经过服务端首次准入后才有效，不会写入消息、日志或转发给上游。

在 API 面板“密钥”中新增或编辑一个**专用测试密钥**，找到“模型每日 Token 上限”：

1. 添加实际使用的完整模型 ID，填写每日 Token 数，例如 `10000`；不要填写金额。
2. 同一个密钥可添加多个模型；未添加的模型不限额。
3. default、vip、svip 仅决定路由，不影响这份日额度；“无限额度”指金额余额，不会取消模型日限制。
4. 输入包含缓存：输入 130000、缓存 120000、输出 10000，日消耗为 140000，不是 260000。
5. 按北京时间每日零点重置。当天修改额度、修改分组或名称不重置已用量。新功能只统计部署后发生的调用，不倒算部署前日志。

## 快速验收

使用测试密钥，不要改正在给正式用户使用的密钥。真实模型调用可能收费。

### AI 对话

模型上限先填 `1`（确保本日此前没有调用）。新建对话发送：

> 请用三句话解释为什么下雨后空气比较清新。

第一轮应正常完成，即使用量超过 1。回答底部应显示“模型名 今日额度已达上限，请切换其他模型使用。”的小提示。再发送：

> 再举一个生活中的例子。

应提示“该模型额度已达到日限额，请切换其他模型使用。”，不反复转圈、不悄悄换模型、不自动换 Key。其他不限额模型仍可用。

### 新版助手

使用另一个测试密钥，或另一个当天尚未使用的模型。上限仍设 `1`，发送：

> 请在当前工作目录新建一份“日额度测试.txt”，写下三条办公室节电建议；再检查文件内容，最后告诉我保存在哪。

第一轮内读取、写入、检查及最终回答都应能完成，不在第二次底层模型调用时突然被额度拦截。随后发送“再补充一条建议”，应被日额度拦截。

### 校园网和额度接口故障

1. 在能复现问题的网络，使用同一个入口、服务商、密钥和模型交替测试，记录准确时间和诊断编号。
2. 查看客户端诊断及 API 请求日志，正式请求应访问 `/v1/chat/completions`、`/v1/responses` 或相应原生模型路径；发出之前不应有 `/model-daily/turn` 请求。仅站点首页能打开不能证明这些 POST 和流式路径都能访问。
3. 在测试环境单独阻断 `/api/usage/token/model-daily/turn` 和 `/turn/state`，保留正式模型路径：新任务应仍能发送，答案应完成。后台续约及结束同步失败不能把答案改成错误，也不能自动重跑收费请求。
4. 阻断正式模型路径，应显示对应连接、超时或实际 HTTP 错误；只有 API 明确返回 `model_daily_token_limit_exceeded` 时才显示日限额耗尽。数据库异常使用 `model_daily_quota_unavailable`（HTTP 503），不会伪装成余额不足。
5. 恢复网络后打开“我的用量”核对服务端计数。结束同步属于尽力通知，失败时不会凭空显示“已超额”；下一次正式请求仍由 API 执行日限额，不会因客户端没显示提示就放行。

正式请求首包不增加独立额度网络往返。结束时最多进行三次短同步以等待结算；每次超时 1.5 秒，仅在返回“仍有请求结算中”时再查，文本已经流式显示，不重新调用模型。没有返回完整计数时不猜测限额状态。历史消息中的“今日”提醒在北京时间零点后隐藏，跨日任务不会误报新一天已超额。

### 设置调整和共享

- 打开“我的用量”：查看“今日模型额度 · 北京时间”，已用可超过上限，剩余最低为 0。
- 提高上限到大于实际已用，下一问应可发出；降低上限不会截断已获准的任务。
- 将密钥从 default 改到有同模型的 vip/svip 组：额度和已用量不应清零。
- 同一个密钥换到另一台电脑也应受限；另一个密钥不受前一个密钥额度影响。
- 删除该模型的额度行再保存：解除限制，但当天用量保留；重新添加不应归零。
- 开发者模式不能绕过服务端额度。耗尽模型仍保留在公共模型列表，不应禁用渠道或触发公共备用模型替换。

## 需要注意的边界

- 这是“最后一问允许跑完”的软上限，不是精确资金封顶；多个同时获准的任务可能各自超额。
- 部署新 API 后，旧客户端依然有服务端单次 HTTP 请求限制，但无法保证多次调用的助手整轮豁免。建议先用新客户端小范围验证，再为正式密钥开启。
- 必须先部署 API 再更新客户端。新客户端不会通过删掉任务头或恢复独立前置校验来兼容旧 API；已有旧 API 不认识新凭证时会拒绝请求，应升级服务端。
- 已获准轮次跨午夜的消耗记入开始日；新问题使用新日额度。
- 凭证后台续约，不新增 15 分钟任务总时限。单个凭证最长 24 小时，极端跨日任务需重新提问继续；不会切断已经输出中的响应。
- 服务端数据库持续异常时保留未结算记录和预留并报告错误，需要运维对账，不会把未知费用当成零。原使用日志清理策略保持独立。
