# AI 对话模型设置验收

普通页面保留默认模型和流式输出；默认助手模板的模型仍由上级模型设置页选择。温度、Top-P、输出长度上限、工具调用方式及自定义参数在高级设置中。高级设置默认折叠，已有角色若启用了覆盖参数，折叠标题仍显示“已自定义”。

温度、Top-P 和输出长度由对应开关及数值控制，自定义参数不能覆盖这三个设置。请求构建时同时过滤标准参数、Provider 命名空间及常见 `extra_body`、`generationConfig`、`options` 容器中的对应字段；保留推理配置、结构化输出 Schema 等无关内容。其他 Provider 专用参数仍需满足服务方要求。

已有自建角色的数值、开关、模型和历史保持不变，统一应用请求校验。之前版本的一次性默认助手修复继续保留，不反复覆盖用户后续的主动选择。点击“重置”会关闭三个覆盖开关、清空自定义参数并恢复工具设置，不修改角色名称、提示词、模型或历史。

重点回归：

- 未展开高级设置时，只有模型选择和流式输出可操作；打开后原设置可用。
- 旧角色带开启的温度、Top-P 或输出上限时，折叠标题显示“已自定义”；重置后显示“默认参数”。
- 开启温度会关闭 Top-P，反之亦然；切换模型不会偷偷改温度数值。
- 关闭流式输出后调整其他设置，流式输出仍保持关闭。
- 自定义 `temperature`、`topP`、`top_p`、`maxOutputTokens`、`max_tokens`、`max_completion_tokens` 等不能绕过开关；同名 JSON Schema 属性保留。
- 开关开启时继续执行模型兼容处理；无效采样数值不发送，无效输出长度回退到默认限制。

相关自动回归位于设置页测试、`model-parameters.test.ts`、`options.test.ts` 和默认助手迁移测试中。无需真实模型请求。

## 默认提示词保护

AI 对话的默认助手及默认助手模板提示词只读；新版官方智能助手的提示词也只读。保留现有正文，不迁移或重写提示词。自建角色仍可编辑提示词。

默认助手的单项、批量及模板设置保存均保留原提示词。新版助手保存模型、权限等设置时不携带只读提示词字段；官方助手的接口仍拒绝提示词修改，服务层的完整替换也不会将省略的提示词清空。

验收时分别打开默认助手模板、AI 对话的默认角色设置、新版助手设置，确认提示词可查看和复制但不可编辑；更改模型等其他设置仍可保存。复制出的自建角色使用独立 ID，仍可编辑自己的提示词。

## MCP 自动发现默认值

未配置 MCP 模式且没有手动选择服务的角色，默认显示“AI 自动发现”；新建默认助手也明确记录此模式。明确保存过的“禁用”或“手动”继续生效，旧配置有服务选择但没有模式时仍按手动处理。不迁移或重写已有角色数据。

自动模式仅在用户已添加且启用了实际 MCP 服务时挂载 Hub。没有启用服务、模型不支持工具或 Hub 工具未加载成功时，不附加自动发现提示词。内部标题生成等没有加载工具的请求同样不附加。发送前不探测所有服务，也不预先发现工具；模型按任务需要再发现和调用，原有工具审批流程保持生效。

手动验收：

- 没有服务或全部停用时，自动模式可普通聊天，请求不带 Hub 工具及其提示词。
- 启用已有服务后，自动模式只挂载 Hub 的发现工具；问候、翻译等可直接回答，需要外部数据或操作时再发现工具。
- 明确禁用的角色仍不挂载 MCP；手动模式仅使用所选且已启用的服务。复制、导入角色时保留其明确配置。
- 工具无法加载或没有可用结果时，不反复发现或声称操作成功；需要审批的工具仍触发原审批流程。
- 新版智能助手的 OpenCode 原生工具不受本次普通 AI 对话设置调整影响。

自动回归覆盖默认助手、模式兼容、服务选择和实际请求构建，位于 `assistantMcpDefaults.test.ts`、`mcpMode.test.ts`、`mcpMode.integration.test.ts`；同时回归现有 MCP 审批测试。
