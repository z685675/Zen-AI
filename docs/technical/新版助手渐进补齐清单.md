# Zen AI 新版助手渐进补齐清单

日期：2026-10-11

范围：新版助手（OpenCode 内核），不包含 AI 对话或老版助手的整体重构。

当前代码参考：Zen AI 1.1.72；OpenCode 固定版本 1.18.35。下方保留各轮开发时的验证记录与状态。

> 第一原则：保留 OpenCode 原生执行机制，Zen AI 只做必要的产品接入。稳定性优先于功能数量。
>
> 本文是逐步评估与验收清单，不是一次性开发授权。初版仅创建清单，后续授权和实现记录见各节；当前仍未改版本号、提交、推送或调用付费模型。

## 一、使用方法与状态约定

- 先完成 A 类稳定基线，再逐项评估 B 类补齐候选；C 类功能另行确认后设计。
- 已接入不等于所有模型、平台和真实渠道都已验收，不重复开发已有能力。
- 用户已反馈部分新版场景基本可用，但不能据此把全部检查项标为通过。
- 每次只处理一个有独立边界的事项；没有明确缺口，不为了打勾而新增逻辑。
- 标记完成时记录：变更范围、自动验证、真实模型与平台结果、未验证范围、回退方式。
- 涉及真实 API、付费请求、外部发布、用户文件修改或第三方接入，测试范围须先确认。
- 项目内本文件为维护源，桌面同名文档为阅读副本；状态变化后同步，避免两份记录不一致。

状态含义：

| 状态 | 含义 |
| --- | --- |
| 已接入，待验收 | 当前有调用链或实现，不表示本轮重新测试通过 |
| 待评估 | 先证明存在缺口，再决定是否开发 |
| 暂缓 | 不是遗漏，不进入当前稳定化阶段 |
| 不迁入 | 保留目标，但不复制老版机制 |
| 已验收 | 必须附验证记录，不能只凭代码存在或模型口头声称 |

## 二、开发边界：哪些由谁负责

2026-10-12 后续调整：弃用助手入口只读，发送按钮灰色不可用，输入框提示“旧助手已停止使用，请切换新智能助手进行使用。”。旧新建、重试及执行入口关闭，开发者模式不能绕过；保留旧历史、复制/导出、文件与“在新版继续”。旧历史查看不需要模型或旧 SDK 依赖。此前新老同时运行的验收改为新版不同会话合计普通 1 / 开发者 3，OpenCode 原生机制不变。

2026-10-12 产品约定：后续开发仅针对新版助手，弃用助手不再维护。旧微信等外部接入、定时任务和心跳已关闭，已有计划暂停、连接断开；保留配置、凭证和历史，但重启不自动恢复，开发者模式也不能绕过。新版这些能力另行开发和验收后才开放，不修改 OpenCode 原生循环和压缩来迁就旧机制。

| 范围 | 主要负责方 | Zen AI 的边界 |
| --- | --- | --- |
| Agent 执行循环、工具选择 | OpenCode | 不额外建立一个任务循环 |
| 原生历史、当前会话压缩、工具结果清理 | OpenCode | 保持显示记录与原生历史一致，不再套 AI 对话 checkpoint |
| 推理重试 | OpenCode | 可观察、可取消；产品时间上限需审查，不能叠加盲重试 |
| 模型和上游渠道 | 已配置 Provider / API 面板 | 客户端复用既有模型政策，不自行创建第二套路由 |
| 技能、文件工具、浏览器 | OpenCode 调用已连接的 Zen 工具 | 按需加载，保留授权、校验和人工交接 |
| 页面状态、产物入口、诊断 | Zen AI | 状态来自真实事件，不修改请求语义来制造进度 |
| 微信、定时、跨会话长期记忆 | 未来独立接入 | 默认不介入普通对话，不用提示词假装已经有能力 |

注意：原生内核能力强，不代表所有上游兼容接口都完全一致。适配缺陷仍需修，但必须用明确证据和最小改动处理。

## 四、A 类：先守住稳定基线

以下未勾选表示尚未在本清单登记验收，不表示代码完全没有实现。

### A01 普通问答与启动速度

- [ ] GPT、Gemini、Claude、Grok 通过实际使用的 Provider 完成简单问答。
- [ ] 分别记录冷启动、同会话后续请求和新会话的首个可见输出时间、完成时间、模型请求次数。
- [ ] 问候不触发文件操作、环境联网探测、技能市场搜索或额外总结请求。
- [ ] 界面等待状态可解释；已有实际可见内容后不继续显示初始空白等待。
- [ ] 相同条件下和改动前基线比较，不把上游波动直接归因于客户端。

验收：无空白成功、无无限等待；若明显变慢，先定位耗时，不用额外请求掩盖原因。具体性能门槛依据实测基线确认。

### A02 工具执行与成果交付

- [ ] 能创建真实文件、读取结果，并显示稳定的文件快捷入口。
- [ ] 切换会话再返回、重启软件后，已保存产物入口仍可用。
- [ ] 文件缺失、路径不可访问、工具报错时，不显示虚假的完成状态。
- [ ] 不因收尾、状态转换或恢复而重复生成文件、下载、提交。

验收：模型说完成时，有对应的可观察结果；复杂内容和排版质量另外验收。

### A03 附件与多文件

- [ ] Word、Excel、PPT、PDF、图片各做一个代表样例；优先覆盖曾引发 Mac 故障的 Excel 场景。
- [ ] 两个及以上附件可区分来源，不静默遗漏。
- [ ] 无法复制、读取、解析或内容过大时，清楚说明处理范围。
- [ ] 文件只按任务需要读取，不把全部附件及其二进制内容塞入每轮请求。
- [ ] 在 Windows 和 Mac ARM 实机检查卡顿、内存与退出情况；Mac x64 按发布支持范围补验。

验收：不崩溃；依据文件内容回答，不能把局部预览当作完整读取。

### A04 浏览器与用户接管

- [ ] 网页总结、登录、滑动验证码/二次验证、下载各覆盖一个样例。
- [ ] 用户完成接管后回到正确的新版会话，不跳到老助手。
- [ ] “稍后”、取消、登录过期、页面失效时状态正确。
- [ ] 允许的网站登录状态按现有浏览器机制复用；不泄露 Cookie，不绕过验证。

验收：需要用户操作时明确交接，交接后能继续，不自动重放已经完成的外部动作。

### A05 原生记忆与自动压缩

- [ ] 同会话连续对话保留约束和最新纠正。
- [ ] 至少覆盖两次连续压缩，以及压缩后继续执行工具任务。
- [ ] 换模型、切回模型、关闭再打开后，继续同一份原生历史。
- [ ] 删除、重试、分支、清空后，模型看到的历史符合对应语义。
- [ ] 不混入 AI 对话 checkpoint，不注入另一套老 SDK 恢复摘要。
- [ ] 压缩后的关键信息遗漏需真实评测，不宣称能保证记住全部细节或固定百分比。

验收：历史一致，最新纠正不被旧结论覆盖；文件原文仍可按需回查。模型预算不等于上游真实支持的上下文容量。

### A06 上游故障与重试边界

- [ ] 本地模拟连接失败、429、503、524、断流、空结果和最后完成事件丢失。
- [ ] 已发出工具动作后发生故障，不盲目重新提交整个任务。
- [ ] 明确失败不伪装为成功；保存已有真实结果并给出可继续的说明。
- [ ] 审查原生重试与 Zen 时间上限是否重叠、误杀正常长任务。
- [ ] 本地模拟与实际上游验收分别记录；不故意使生产渠道被禁用。

验收：有界、可取消、可诊断；客户端没有额外套一轮渠道重试或底座切换。

### A07 停止与再次发送

- [ ] 在启动、等待模型、输出、工具执行、权限等待和浏览器交接期间分别停止。
- [ ] 界面停止传到真实任务，后台不继续无授权执行。
- [ ] 停止后同会话可重新发送，不残留占用锁或旧事件。
- [ ] 切换会话不误取消其他会话任务；重复点击不会提交重复任务。

验收：不假停止、不挂死、不把旧任务输出写入新一轮。

### A08 模型、权限与配置边界

- [ ] 普通模式、开发者模式、远端模型下架、无可用模型分别验收。
- [ ] 接口按 Provider 元数据选择，不按模型品牌猜协议。
- [ ] 计划模式不执行写入或命令；拒绝授权后不换工具偷偷完成。
- [ ] 不读取用户个人 OpenCode 账号、插件或未授权配置。
- [ ] 文件、网页和迁移记录中的指令不会自动获得新操作授权。

验收：模型政策、权限与实际请求一致；不通过扩大权限来修复一般调用问题。

### A09 新老过渡与历史安全

- [ ] “在新版继续”不修改旧记录，不重放旧工具。
- [ ] 同一源快照重复操作幂等；正在执行的旧任务禁止迁移。
- [ ] 失败只清理新副本；缺失附件明确提示。
- [ ] 长历史档案可回查，历史副本只读，新消息正常执行。
- [ ] 分支及迁移不被误解为文件系统快照，已有生成文件不自动回滚。

验收：旧数据可回顾，新副本可继续，故障不损坏原会话。

### A10 诊断、安装包与网络

- [ ] 区分界面、本机服务、OpenCode、Provider / API 面板、上游各阶段证据；证据不足标为未知。
- [ ] 有关联请求编号和时间，脱敏 Key、Cookie、私密附件内容。
- [ ] 直连、应用配置的代理、本机存在但应用未启用的代理分别核对，不擅自改网络。
- [ ] 安装包实测启动、文件工具、附件和停止；开发环境通过不能替代安装包验收。
- [ ] 固定依赖、架构二进制、离线资源和许可证完整，启动不偷偷下载。

验收：诊断能缩小问题范围，但不承诺仅凭一个包就能准确确认所有故障根因。

### 2026-10-12 第一批实现记录

用户已授权补齐 B01、B03、B04，当前代码已接入，真实模型效果仍待验收：

- B01：新版使用独立、稳定的精简任务约定，补上真实执行、失败不冒充成功、必要询问、已有授权不重复询问、实际来源、按现状续做等规则。不搬旧长提示词，不新增问候前的探测或隐藏模型请求。
- B03：脚本等其他路径的最终产物通过 present_files 时，复用已有格式和关系校验，并补 Word 正文、Excel 工作表/数据/错误/公式缓存、PPT 实际页绑定、PDF 内容流等基础检查。错误包含文件路径；整批失败不发布成功卡片、不删除已有产物。create_file 的原有生成与校验流程不变，未修改的产物无需重复登记。
- 校验结果区分 structure-and-content（结构与基础内容）、structure-only（例如公式缺少缓存结果）和 existence-only（未知格式或超大文件）。目录是 directory-exists。部分检查不完整时不显示内容已验证；检查通过也不保证事实、公式重算、排版或用户全部要求都正确，仍按适用 Skill 做特性检查并如实披露。
- 自动内容检查上限为单文件 32 MiB；Office 包最多 5000 个条目、声明展开总量 64 MiB。超大文件保留打开入口但不标记内容已验证；异常展开包拒绝自动交付。检查不启动 Office、不安装依赖、不执行产物、不请求另一个模型。
- B04：沿用已有附件路径和复制失败清单，增加多附件清点、来源对应、按需分批读取、数据单位/冲突处理、预览/OCR 的局限与遗漏披露规则。不增加另一套附件预读或每轮全量读取。是否选对文件、理解正确，仍需真实模型任务验收；提示约定不是百分之百不遗漏的保证。
- OpenCode 的工具选择、执行循环、重试、压缩、原生历史、模型路由与权限配置保持原样。只补产品任务约定与交付工具；不启用微信、定时、心跳或旧助手执行。
