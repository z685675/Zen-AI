# 新版助手：会话成果与缓存用量诊断

日期：2026-10-12。适用：本地开发版 1.1.71 的 OpenCode 新版助手。未改版本、提交、推送或发版；不代表已安装的 71 包包含本次改动。

## 1. 范围与稳定性边界

用户授权补齐第 3、4 项：当前会话成果集中查看、缓存与请求用量诊断。仅增加展示与被动观察，不修改原生执行循环、压缩、重试或权限，不增加模型/探活/审核请求，不在新版开放旧微信或定时任务。不改变 Redux 状态结构、数据库 schema 或冻结的 messageThunk.ts。

## 2. 会话成果

- 在新版助手的会话顶部增加“成果 · 数量”，打开右侧列表，可按文件名/路径搜索。多于 15 项分页。
- 从本会话已保存的消息块重新聚合，不扫描磁盘、不扫描其他会话、不新建成果数据库。
- 只收录完成且成功的受认可文件工具的结构化输出；输入附件、普通文本路径、终端命令、失败/取消/未完成工具不自动成为成果。
- Windows 路径大小写及斜杠归一去重；Unix 路径区分大小写。同一路径指向最近登记的回答，显示登记回答数，不冒充多个历史文件版本。
- 支持实际打开、定位文件、跳回对应回答。定位旧消息时先展开相应历史页、选择对应回答，再滚动；无需展开工具才能找入口。
- 文件夹直接打开，文件可显示所在目录。保留既有消息级快捷入口。
- 文件移走、删除或打不开时提示失败，保留历史入口；不自动重建、下载或执行文件。列表不是快照，也不保证磁盘文件仍存在。
- 删除回答、重试裁剪或分支以后，只根据当前保留的记录聚合；不自动删除或回滚真实文件。

## 3. 用量来源与统计口径

回答下仍保持原来的简洁输入/输出/缓存和首字/用时，新增“详情”按钮。详情按需打开，只读显示：模型和 Provider 标识、任务结果、报告用量的请求数、输入/输出/缓存读取/缓存写入/推理、整轮缓存读取率、请求/原生重试/工具次数、未完成工具和耗时。

### 两套来源分开看，不能相加

1. 简洁栏来自原生本轮回答记录。按原生 step-finish 的唯一 part ID 统计，避免只取消息的最后一段，避免重复快照/历史补读重复计数；缺少 step 时兼容原有消息 tokens。原生文本输出与推理分开存储，因此显示输出时包含推理一次。
2. 详情来自本轮本地转发桥观察到的上游响应。可能包括原生压缩、工具后的多次推理或子任务；不一定与主回答范围相同。每个请求只保留最后的对应 usage 数字，再汇总，不把累计 SSE 帧重复相加。与原生回答总数不能再次相加。

不为了诊断修改请求、响应正文或协议。只读取上游已报告的数据，不估算附件/工具文本 Token。原生缺省的零不证明上游真的报告了零；本批回答不再因原生用量为零就触发本地全文估算来替换统计。

### 识别的格式

- OpenAI 兼容：prompt_tokens、completion_tokens、prompt_tokens_details.cached_tokens 等标准数字字段。GPT、Gemini、Claude、Grok 经此格式转换时共用解析，不按模型名猜协议。
- Responses：usage 或 response.usage 中 input_tokens/output_tokens 和细分缓存/推理。
- Anthropic：合并 message_start 与 message_delta 的 usage；输入包含普通输入、缓存读与缓存写，各只计一次。
- Gemini 原生：usageMetadata 中输入、缓存、候选输出和独立 thoughts；候选与推理输出合计。
- 不认识的格式、未报告的字段或异常数字标为未知。不承诺覆盖所有上游私有扩展。

### 缓存读取率

整轮读取率 = 缓存读取合计 / 输入合计。仅当全部上游请求都有对应输入和缓存读取数据、响应完整、观测请求数吻合、读取量不超过输入量且输入非零时显示。显式零可显示 0%；缺失或部分请求未报告不当零、不推算整轮率。读取与写入不重复合并成“缓存命中”。

简洁栏若无法证实原生缓存统计与上游完整报告一致，显示“—”，详情仍可查看已报告部分。没有缓存并不证明软件关闭缓存；没有字段也不证明上游未命中。这里不推断看不到的路由渠道或故障根因。

## 4. 耗时、费用、保存与安全

- 首字/整轮用时沿用现有消息计时。内核准备、上游响应头等待、已结束请求、已完成工具的时间来自现有事件。响应头等待不是首字时间，阶段可能重叠，不能相加。此前附件保存/前端延迟不包含在内核准备里。
- 手动停止或失败仍可留下已经观察到的数据；尚未收尾的请求可能未计入，因此明确标为不完整，不声称零费用或未收费。
- 没有可靠价格/账单就不编造金额；实际费用及失败请求收费由服务商决定。
- 新增字段保存在既有消息 providerMetadata JSON 中，正常终态保存同时写入时间，避免并行保存旧元数据覆盖最终结果。诊断包既有运行记录也带 content-free 用量汇总。
- 历史消息没有本次观测时，不伪造新详情；成功、失败和停止后新的记录按现有历史保存机制重建入口。
- 观察器临时缓冲有界（SSE 单帧 256K 字符、JSON 1M 字符，分块处理），超限跳过并标不完整；不保留正文、附件、请求体、Key、Cookie 或响应全文。解析/记录失败不得打断字节转发及清理。
- 功能不会自动切模型/渠道、改提示词、注入无用缓存文本或自动提高缓存率；用于准确看用量和定位额外开销。

## 5. 验证与人工验收

自动检查覆盖：成果范围/路径安全/去重/重建/搜索/实际按钮/缺失文件、分页来源定位及会话隔离；四种 usage 格式、CRLF/UTF-8 分片、多行 SSE、累计去重、超大/无效帧、缺失/显式零、部分请求、缓存率异常；原生多 step 与推理统计；终态元数据共存、诊断不触发模型重提或估算；桥接正文保持原样且请求数不增加。

人工只补桌面《Zen AI新版助手测试清单.md》第18节：成果查找和切回、同模型连续几轮后看详情。实际缓存命中取决于上游，未调用付费模型来证明缓存率；Mac 安装包与四家真实渠道仍需实测。

本轮验证：全量fork三分片共402个不同测试文件，4997项通过、5项跳过；后续元数据白名单与保存断言补修，最终专项4个文件36项通过，不与全量累加。最终lint（含类型/国际化/格式）与Electron构建通过，Windows原生模拟9次请求、0次付费请求。实际四家模型的缓存命中、Mac与安装包尚未实测。

撤回方式：移除成果入口、详情展示和被动观察即可，原生会话/文件/既有诊断不删除；旧元数据字段可保留，旧消息仍可读。
