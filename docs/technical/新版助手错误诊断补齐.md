# 新版助手错误诊断补齐

日期：2026-10-12。范围：OpenCode 新版助手的现有错误 ZIP 导出；不改变原生执行循环、重试、压缩、模型政策或请求内容。不改版本号、不推送、不调用付费模型。

## 已补齐

- 本轮诊断编号在启动进程之前绑定，覆盖工作目录、离线资源、本地网关、执行文件解析、启动监听、健康检查、配置核对及历史绑定阶段。
- 记录执行文件路径、进程编号、预期版本和既有健康检查实际报告的版本。预期版本不等于成功运行的版本，不额外启动版本检查或请求模型。
- 采集本轮观察窗口内的标准错误，支持 UTF-8 / 凭据跨片段；脱敏配置里的 API Key、MCP 凭据、自定义请求头、本地内核密码和转发凭据。保留至多 64 行、8000 字符；单行超过 4096 字符整行丢弃，不截下可能含秘密的中间片段。
- 记录退出码、退出信号、当时是否有任务、是否由产品主动停止和停止原因。主动取消、任务失败后的清理、超时终止和空闲回收不冒充进程意外崩溃。
- 退出事件和管道关闭事件分别记录；最终管道数据在 close 时补入。任务终态后到达的退出/关闭记录也保存到已有诊断快照，沿用最近 100 份快照保留机制。
- 共用内核进程切换到下一轮时清空 stderr 观察缓冲；同一轮重复绑定不清掉启动证据，不混入其他会话。
- 导出环境增加 OpenCode 可执行文件检查：架构、位置、存在/文件类型、大小、Mac 执行权限。Windows 执行权限注明不适用；解析失败明确显示失败。只检查文件，不下载、修复、执行或安装组件。
- ZIP 新增 `opencode-runtime.json`，区分本轮进程证据和导出时环境。旧请求、未采到、采集失败及无 stderr 输出均保留明确状态。
- 明确观察到任务中进程意外退出时，链路结论确认退出发生在本地运行环节；不能仅凭退出码认定根因。一般上游故障继续沿用原有 API / HTTP 证据归因。

## 隔离与隐私边界

诊断观察和快照失败不能阻止正常任务。stderr 脱敏初始化失败时停用该采集器，不冒险记录未脱敏数据。不逐片段写事件，避免日志洪泛；不新增模型请求，不改变转发字节。

不导出完整环境变量、OpenCode 配置、标准输出、附件原件或完整会话档案。原有出错消息及相关用户输入，以及内核主动写入 stderr 的任务文本，仍可能包含个人信息；不是“完全不含用户内容”的包。

标准错误按观察窗口归属，并不保证所有异步底层日志精确对应某个工具。内核没写 stderr、日志被限量截断、历史诊断已过期、软件整个进程闪退等场景可能缺失证据。Mac 原生崩溃根因可能仍需用户提供 `.ips` 报告；本次不自动收集其他应用的系统崩溃文件。

`opencode-runtime.json` 的 `environmentAtExportTime` 不能代表失败当时的文件状态。实际版本来自启动时既有健康检查或复用进程保存的 `process-snapshot.observedVersion`。无实际报告时不伪造版本。

## 验证与使用

自动测试覆盖启动前故障、spawn 失败、异常退出与末尾管道输出、正常停止、跨轮/跨会话隔离、脱敏/洪泛/UTF8、观察器失败隔离、快照重启恢复、环境缺失和 ZIP 文件内容。检查不调用生产 Provider。

开发程序需要重启。实际遇到失败后，在错误卡片点击“导出诊断包”，保存 ZIP；不要求为了测试故意让生产模型出错。手动停止和并发额度提示不是普通失败卡，不能以它们没有导出按钮判定诊断导出失效。

回退只撤回本批进程观察、环境检查和新增 ZIP 文件。无数据库或 Redux 结构变化，不删除原会话/用户成果，也不恢复弃用助手。

最终验证：fork三分片全量406个不同文件、5023项通过、5项跳过；收尾末行容量边界补修后，最终专项21个文件146项通过，两轮数字不累加。最终lint（类型、国际化、格式）、Electron构建和diff检查通过。Windows原生OpenCode本地模拟通过，8次模拟请求、0次付费请求。真实Mac安装包和四家上游不在本地模拟验收范围。未提交、推送或改版本。
