# 新版助手办公文件修改安全

更新日期：2026-10-15。仅作用于 OpenCode 新版助手，不改旧助手、AI 对话、数据库或 OpenCode 原生执行/压缩循环。

## 默认行为

| 用户的任务 | 默认处理 | 是否打断用户 |
| --- | --- | --- |
| 新建 Excel、PPT、Word 等 | 直接制作新文件，重名自动编号 | 不增加安全确认 |
| 分析、读取文件 | 读取需要的部分，不改文件、不复制 | 不增加安全确认 |
| 修改、仿照已有文件 | 修改版另存；脚本编辑前准备独立工作副本 | 不为副本增加确认 |
| 继续修改上轮成果 | 保留上轮结果，另存下一版 | 不为副本增加确认 |
| 明确要求覆盖原件 | 确认准确路径 → 校验原件备份 → 完整写入后替换 | 一次明确覆盖确认，全自动也适用 |
| 删除文件/目录 | 独立确认准确范围，优先可恢复方式 | 不继承编辑授权 |

## 程序保护

- `create_file` / OCR 文本输出默认不覆盖；并发写入和同名文件以实际发布时的独占创建结果为准，保留已有文件，返回最终路径供成果卡片使用。
- `prepare_file_copy` 按授权目录、真实父路径和普通文件校验源与目标，保留扩展名、校验 SHA-256，创建独立字节副本。不会把原件作为硬链接交给脚本修改。
- 默认副本位于工作区 `outputs`，用 `<名称>-edited.<扩展名>` 命名。同名再加编号。副本只是准备，不冒充已经完成的交付；编辑和校验后再 `present_files`。
- 覆盖确认使用关联主窗口的原生弹窗，显示准确文件路径，默认“取消”。拒绝、关闭、90秒未决定、任务取消或没有主窗口均不覆盖。避免 MCP 没有原生工具 ID 时授权卡片不可见的问题。
- 覆盖前备份保留在原件旁 `.zen-backups`，校验原件/备份一致。等待确认、备份期间原件发生变化时拒绝替换，防止覆盖用户新修改。
- 备份和工作副本单次上限128MiB；超限明确报工具限制，不跳过校验、不擅自安装依赖。该限制不是附件读取总量限制。
- 计划模式在原生权限和产品 MCP 两层拒绝变更。普通全自动工作仍可执行，常见删除命令保留原生确认。
- 备份、复制、写入失败或取消时不发布半成品，不自动重试覆盖、恢复原件或删除已有成果；备份不自动清理。

## 不能承诺的边界

这不是操作系统沙箱。程序保护覆盖上述产品文件工具；任意 Python、原生终端或第三方 MCP 仍可能用宿主用户权限写入文件。副本规则会明确提供给模型和工具说明，但不能把提示词或常见命令权限匹配称为所有脚本的强制拦截。不要对不可信第三方技能开启全自动并授予重要目录权限。

不启用依赖 Git 的 OpenCode 快照，不把原生快照当作所有办公文件的完整备份，不增加新的任务规划/重试/压缩机制。

## 最小人工验收

在专门测试目录里进行，不要拿重要文件试删除。

1. 上传一份 Excel：`把这个表按销售额从高到低排序，另存一个修改版给我，原来的别动。` 检查原件字节不变、结果可打开。
2. 对修改版继续说：`再增加一列，算出每行占总销售额的比例。` 检查上一版仍保留。
3. 上传 Word/PPT：`照着这个文件的结构做一个新的版本，主题改为下个月工作计划。` 检查原件不变，不冒充完整保留所有格式；新文件可以打开。
4. `再生成一份同名文件，内容写第二版。` 检查自动编号，旧文件不被覆盖，不弹覆盖确认。
5. `覆盖测试目录中的说明.txt，先备份，内容改为第二版。` 拒绝一次，原件不变；重新明确要求后批准一次，原件更新且备份仍是旧内容。全自动模式同样需要覆盖确认。
6. 确认框打开时停止任务，或直接关闭确认框，原件不变。计划模式不能创建副本或改文件。
7. `删除测试目录里的待删除.txt。` 核对独立授权提示及准确范围，不借机清理整个目录或备份。

自动测试覆盖工具发现/计划禁写、真实 XLSX 副本、交付登记、同名并发、拒绝/取消、越权路径/链接、复制损坏/源变化、备份校验与全自动覆盖确认。真实模型是否遵守副本流程及各平台原生弹窗仍需人工验收。
