# 新版助手：OpenCode 内核接入

日期：2026-10-10。当前版本仍为 1.1.71；本轮为独立预览入口，不替换老助手。

## 产品边界

- 新增 `/new-assistant`，导航入口位于图片生成下面；复用助手页面、输入、附件、状态、工具与文件卡片。
- 通过固定身份 `zen-opencode-default` 选择 OpenCode，模型名称、旧内核 override 都不能改变此归属。为了不改数据库 schema，数据库 agent type 保持 `claude-code`，实际执行内核看 runtime 诊断字段。
- 普通模式复用既有远端可选模型、默认与下架兜底；开发者模式复用 VIP 放行规则。不是另建一份模型名单。
- Provider、Key 与模型仍来自 Zen AI。New API 四家文字模型走 OpenAI 兼容接口；明确声明的原生 Gemini、Anthropic、Responses 接口使用对应适配器。接口以元数据为准，不按品牌猜协议。
- Zen API 本轮没有改动，不需要新增配置面板。当前后台客户端类型识别可能显示未知/兼容客户端，不能据此断言实际走了 Claude Code；以诊断 runtime 为准。
- 新旧会话和原生历史分离，不自动迁移。新版不套用 AI 对话 checkpoint、老 SDK model-keyed resume 或恢复文字。

## 执行链路

`新版助手页面 → 本机已认证的 /v1/new-assistant/agents → 会话服务 → OpenCodeService → 本机 OpenCode 1.18.35 → 本机诊断转发 → 用户 Provider / Zen API → 上游渠道`

OpenCode 使用固定版本的 V1 HTTP/SSE 接口，而非执行 references 中的源码。内核自己的 Agent 循环、工具选择、重试与原生压缩保留；Zen 适配层负责隔离配置、模型入口、进程管理、UI 事件、权限与诊断，不再自行叠加另一套任务重放。

### 一轮任务

1. 解析当前已配置 Provider 与模型，加载启用的全局 Skills 和工作区内置 Skills。
2. 获取或启动本机认证进程，检查版本和实际生效配置。先建立事件订阅，再提交一次 `prompt_async`。
3. 转换文字、推理、工具、权限、重试、压缩等事件到既有界面。完整快照与增量去重，文件工具保留原始 MCP 内容。
4. 明确原生错误直接失败；仅在传输断开时核对已保存的消息是否真的完成。不把明确的失败伪装成成功，不自动重发整个工具任务。
5. 任务结束释放进程；最多四个实例，空闲五分钟回收。退出应用时只结束本应用管理的进程树。

## Skills 与工具

- 共用启用的全局 Skills；内置 Office 等 Skills 复制到独立工作区，按需由原生 skill 工具读取。
- 接通现有 assistant MCP 与持久 browser MCP。名称保持 `mcp__assistant__create_file`、`mcp__assistant__python_execute`、`mcp__assistant__present_files`、`mcp__browser__open` 等，兼容既有指南。
- Office 生成/校验、托管 Python、OCR、文件卡片使用已有实现，不靠模型输出扩展名伪造文件。
- 附件先复制到工作区，供工具按需读取；复制失败才使用有界文字提取兜底。不是一次把所有文件全量塞进提示词。
- 默认权限为确认模式，支持既有单次批准/拒绝；用户明确选择绕过模式时遵循现有设定。计划模式禁止写文件、执行命令及可变 MCP 操作。
- 登录、滑动验证码、授权和付款由浏览器工具提示用户接管，不绕过安全验证。Cookie 沿用 Zen 浏览器的持久管理。
- 定时任务、微信/IM、Soul/Heartbeat、第三方自定义 MCP、旧 SDK 高级选项暂未接通，新版隐藏相应入口。不得把它们当作已实现功能宣传。

## 原生记忆与一致性

- 原生根目录：`{Data}/OpenCode/<sha256(Zen会话ID)>`。`binding.json` 原子保存 native session ID，不保存 Provider Key。
- 换模型、Key 或配置需要重启进程时，继续同一数据库和 native session ID；换模型不会切回一份旧模型的残缺历史。
- 原生压缩与工具结果清理开启。未知别名用 128K 保守预算；已知模型预算最高 200K，不能据此保证上游真实支持 200K。
- 回答下方支持重试、分支、单条删除，直接操作原生历史并同步展示记录；任务运行期间禁用。新消息保存精确原生用户消息 ID，旧预览记录无法可靠对应时拒绝猜测。直接编辑、消息组和批量删除仍未开放；复制、导出与补充指令正常保留。
- 重试保留目标问题之前的历史及目标问题，移除原回答和后续问答后重新执行。删除回答会移除该轮原生助手/工具步骤，并清除可能保留已删内容的后续压缩摘要。所有历史修改先在原生副本上完成，再切换绑定、事务写入展示记录；写入失败恢复旧绑定。
- 分支在停止源进程并等待数据库退出后复制独立原生数据，保留截至所选回答的记录，消息/块 ID 重新编号。原会话不变；分支继承同一授权工作目录，文件不复制也不回滚。重试文件/外部任务可能重新执行相关动作，确认时明确提示。
- 清空会话先归档原生历史，再删除后台展示消息，最后清理界面。过程中保持会话锁，活动任务返回冲突，不能只清空屏幕；展示清理失败尝试恢复原生归档。
- 删除会话同样在锁内归档原生数据后删除会话记录。归档名称为 `archived-<hash>-<uuid>`，保留在应用数据目录供人工恢复，不自动删除用户文件。

## 网络、诊断与安全

- 本机随机端口、Basic auth、私有 HOME/XDG；禁个人 OpenCode 账号/配置、项目配置、默认插件、自动更新及启动下载。
- 离线插件依赖真实随包提供，启动缺失则给出明确修复信息，不创建空 node_modules 来伪装安装成功。
- 诊断转发只代理固定 Provider 路径，检查随机令牌，原样转发请求体及 SSE，复用主进程代理设置。令牌不发送上游；不跟随上游重定向，也不把 Location 交给原生客户端绕过检查。
- 每轮关联 `X-Zen-Diagnostic-Operation`，记录头部、状态、request ID / trace ID、完成/取消/失败；由中央诊断脱敏。新请求编号无需修改配置或重启进程。
- 连接错误保留 DNS、超时、TLS 等底层原因、是否收到真实响应头及失败阶段，跨 SSE 和错误序列化传到诊断界面；真实上游错误与网关合成响应分开。重试恢复后清理旧连接证据，避免污染后续请求。仅有泛泛 fetch 失败时不推断服务是否收到请求，不修改代理、DNS 或 TLS 校验。
- 浏览器人工登录/验证后的“继续对话”按任务 agentId 恢复原会话并导航新版或老入口；“稍后”不强行跳转，不依赖当前可见入口猜测任务归属。
- 请求体有 64MiB 安全上限并流式转发；背压、断开和取消会传递。网关不另行盲重试。
- 内核事件握手 15 秒；Provider 头部与流空闲 60 秒，请求超时 180 秒；重试预算最多三次/120秒，真实进展后重置；总任务 15 分钟。边界不是回复速度承诺，仍受上游性能影响。

固定依赖、运行资源和打包脚本负责复制一个目标架构二进制，并校验 PE/Mach-O/ELF。x64 优先 baseline；macOS/Linux 保留执行权限。许可证位于 `resources/licenses`，离线依赖声明在打包前生成。新增完整内核必然增加包体，不作体积不变承诺。

打包时由 after-pack 将真实离线依赖树完整复制到 `process.resourcesPath/opencode-runtime`，包含 `package.json`、`package-lock.json` 和插件依赖；不依赖 ASAR 的依赖收集器保留 lockfile。许可证同样复制到资源根下的 `licenses`，ASAR 排除对应重复副本。包资源检查和 packaged smoke 一并校验这些实际资源，避免开发成功但安装包启动失败。

### 2026-10-11：跨层取消回归

用户诊断 `ZEN-20261011-093703-DD569A` 暴露了界面停止后原生任务未取消的共用链路问题：HTTP abort 监听同步取消 reader，reader 清理移除尚未执行的父级 abort 转发器，留下 active lease。`SessionMessageService` 的 cancel 现在在清理前显式调用转发器，即使父级已经 aborted。测试用真实 HTTP abort 控制器复现顺序，并覆盖 OpenCode/Codex/Claude Code 的取消后继续；不能只测试 `/session/:id/abort` 来替代整个链路。

本机会话占用错误标记为 `OpenCodeSessionBusyError`、`runtime-startup`、`opencode`，诊断可识别为客户端运行环节，不证明该轮上游已收到请求。原生 smoke 同时补测取消后同会话再次回复及历史保留。相关回归66个文件、651项通过；Windows真实内核 smoke 使用8次本地模拟请求通过，无真实/付费请求。10月10日的本地解包程序须重新构建才包含本次修复。
