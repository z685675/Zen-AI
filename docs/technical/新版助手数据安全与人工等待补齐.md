# 新版助手数据安全与人工等待补齐

日期：2026-10-13。只补齐产品外围边界，不移植旧助手执行/重试/压缩循环，不新增模型请求，不修改 Redux 结构或数据库 schema。

## 1. 备份、恢复、清空的任务保护

- 主进程使用同一全局门闩，原生任务预留、运行中的会话、历史接续和技能文件变更均参与忙碌判断；检查与占用同步完成。
- 有活跃任务就拒绝数据操作，提示先停止或等待；不替用户自动停止、重跑任务。后台自动备份遇到忙碌也应跳过/失败，不强行备份。
- 恢复/清空由 renderer 先获取归属当前窗口的 token，再进行主进程文件操作和 IndexedDB/localStorage 修改。拒绝准入时不执行这些修改。
- 操作期间拒绝新任务、原生历史变更和技能变更，也禁止经 DatabaseManager 重新打开助手数据库。只关闭空闲原生进程并等待其退出；恢复/清空关闭助手数据库。
- 错误 token、其他窗口或旧 token 不能结束当前操作。窗口关闭/renderer 崩溃时自动释放；如果主进程复制还在运行，等复制结束后清理并释放。重复结束共享同一清理 Promise。
- 失败只清理本次主进程登记的 staging 路径，不删除本机活跃数据、不清理无关既有标记；成功重启申请后保留本次 staging，下一次启动交换目录。
- 本机制保证助手数据操作的互斥，不宣称所有应用数据、外部文件或正在运行的普通 AI 对话拥有跨库原子快照。

## 2. 精简备份的内容与恢复语义

| 内容 | 精简备份 | 完整备份 |
| --- | --- | --- |
| 显示聊天记录、设置、助手 SQLite 记录 | 保留 | 保留 |
| 当前 OpenCode 会话的 binding.json 和 data 原生记录 | 保留 | 保留 |
| 本地技能文件 | 保留 | 保留 |
| 图片、附件、工作区成果、知识库等大文件 | 省略 | 保留 Data 中的文件 |
| 原生缓存、运行配置和归档副本 | 省略 | 保留 Data 中的文件 |

- 不直接热复制 agents.db/-wal/-shm/-journal；用独立 SQLite 连接执行 VACUUM INTO，保存可读取的一致性助手数据库快照，不跑 schema 迁移。
- 内核空闲进程退出后再复制原生 data，避免复制仍在写入的原生数据库。备份复制不跟随符号链接。
- v6 metadata.json 增加 dataMode=slim/full 和 assistantDataIncluded；v5 ZIP 保留旧 data.json，另加 assistant-data.json 描述 Data 模式。没有新字段的旧包保持旧语义。
- 精简恢复先复制本机现有 Data 到 staging，再覆盖备份包含的记录/技能。被恢复的同 key 原生目录整体替换，助手数据库旧 WAL/SHM/journal 不混入新快照。省略文件不等于删除指令，本机已有附件与成果文件继续保留。
- 完整恢复按完整包替换 Data；不要期待保留目标电脑额外的历史或文件。没有 Data 内容的旧包不清空现有 Data。
- 所有平台均先暂存为 .restore，避免在活着的数据库下直接替换。启动交换先保留原目录，全部成功后再清理原目录；普通失败反向回退并保留 staging。回退本身失败时保留剩余副本并记录错误，不继续删除。
- 换电脑恢复精简包时，没有备份的文件依然可能无法打开。外部工作目录本来就不属于 Data；旧绝对路径、不同系统路径或 OpenCode 工作区绑定不匹配不会被本次自动猜测改写，也不会静默清空原生历史。跨机继续任务仍需单独验证。
- 不承诺强杀/断电或磁盘损坏时跨 IndexedDB、Local Storage、助手与原生数据库的完全原子恢复。备份包含敏感设置/凭据，请勿把完整备份当成脱敏诊断包分享。

## 3. 新版消息不能只删显示记录

- 旧消息删除 HTTP 接口对新版会话返回 409/native_history_required。
- SessionMessageService 再加一层同样的检查，不能经其他调用入口绕过。
- 新版仍使用已实现的原生历史删除/重试/分支入口，保证显示记录与内核历史一起处理；旧助手保留历史查看/删除能力，但不能执行任务。

## 4. 实际执行与人工等待分开计时

- 实际执行累计上限保持 15 分钟；人工授权、浏览器 wait_for_user 等待不占用该预算。
- 人工等待累计上限为 30 分钟，多次等待共享预算，不在每次等待后重置。并发/重复事件用 ID 去重，重叠时间只计算一次；所有等待解除才恢复执行计时。
- 使用单调时钟，系统时间变化不影响累计预算。切换阶段时也检查上一阶段是否已耗尽，避免临界点绕过超时。
- 原生 permission.asked 的等待到授权回复完成、浏览器等待工具从 tool-call 到 tool-result/tool-error，均进入上述阶段。其他工具自己的超时/上游超时仍有效，30 分钟不是保证每种工具必定允许等满 30 分钟。
- 等待期间仍可停止。超时通过现有取消链路退出，使用 agent_human_wait_timeout / agent_execution_timeout 区分原因，保留已保存历史/成果，不自动重提任务。原生重试保护不变。
- 用户提示和诊断按精确本地原因区分“执行时间达到上限”与“等待时间达到上限”，不误归为未知异常、网络故障或内核启动失败。服务是否收到请求、是否开始生成在证据不足时保持未确认，不根据超时原因猜测。

## 5. 验证与交付边界

- 专项覆盖准入拒绝、窗口关闭、重复结束、token 隔离、复制未结束、只清理登记路径、可读 SQLite 快照、精简覆盖及 WAL、恢复失败与重启失败、旧删除接口和服务防线。
- 计时专项及 OpenCode 适配层用虚拟时钟验证长人工等待、恢复执行、等待上限、取消及仅一次 prompt_async。
- 真实 SQLite 用临时目录/子进程验证并回收，避免 Windows libsql 原生句柄残留影响测试清理；无真实或付费模型请求。
- 最终全量、lint、构建与原生本地模拟结果记录在渐进清单第十六节。真实 Mac、生产模型、跨电脑路径迁移与安装包不由 Windows 本地模拟证明。
- 桌面《Zen AI新版助手测试清单》第21节提供用户提示词。恢复/清空有破坏性，必须使用可丢弃测试数据，禁止用主力数据直接清空验收。

本批未改 API 面板、内核版本、Zen AI 版本号，未提交、推送或发布。
