# 新版助手附件读取与接收稳定性

日期：2026-10-15。范围：OpenCode 新版助手；不改旧助手、AI 对话或 API 面板，不替换 OpenCode 原生任务循环和压缩。

## 已确认的问题

- 诊断包中约 9.88 MB 的 PDF 经原生 `read` 转为约 13.17 MB Base64，超过 Zen AI 原有 800 万字符的未完成 SSE 帧限制，导致客户端停止原本已成功请求模型的任务。
- 旧限制与网络分块有关：完整帧单块到达可能通过，分块到达反而失败。
- 原生 `read` 的 `limit` 控制文本行数，不控制 PDF 页数。Office 文件是二进制文件，不能靠原生文本 `read` 直接解析。
- 当前兼容 Provider 配置声明文本/图片输入，并未统一声明 PDF 输入。只放大接收限制，不能解决所有上游不支持原始 PDF 的问题。

## 实现边界

### 接收与恢复

- 按字节增量识别 SSE 帧，支持 LF/CRLF/CR、跨块 UTF-8、多行 data。避免每个分块都重新拼接、扫描整段 Base64。
- 单帧上限 64 MiB，一次完整到达与分块到达使用相同限制。这是本地事件传输保护，不是附件累计上传上限，更不是模型上下文窗口。
- 不在本轮显示状态中常驻保存原生工具的二进制附件；原始文件和原生历史仍由原有存储管理。
- 本地事件连接断开后核对原生状态。已完成则恢复结果；仍在执行则最多重连两次，恢复消息和待处理授权。不会重新发送 `prompt_async`，避免重复写文件、下载或计费。
- 取消、原生任务失败、授权失败和模型错误不当作事件连接故障重试。

### 读取与图片

- 图片使用 OpenCode 1.18.35 原生缩放：最长宽/高 2000 像素、Base64 最大 5 MiB。不是把所有文件强制压成 5 MB，也不保证细小文字在缩放后仍可辨认。
- 新工具 `mcp__assistant__read_document` 用于 PDF 提取文字、DOCX、XLSX、PPTX，以及 UTF-8/BOM 标记 UTF-16 文本、JSON、CSV 等。
- 按页、章节、字符预算返回，提供来源位置、是否部分读取、下一段游标。长单行 JSON 不按文本行直接截掉后半段。
- 每次请求重新检查授权路径和文件版本；游标不授予访问权限，过期/文件改变后必须重新读取。
- PDF 分页提取在有限内存、有超时和取消支持的工作线程中执行。无可提取文字的页明确提示 OCR；不把扫描件或空白页伪装成已完整读懂。
- Office 复用现有结构化解析器，并对文件、ZIP 实际展开、条目、XML、输出和并发设置有限保护。超过保护范围会返回工具错误和拆分建议，不会偷偷截掉内容后宣称成功。
- 单份文档最多 64 MiB，文本文件最多 256 MiB；不是多附件总量 10 MB 上限。Office 最多 4096 条 ZIP 目录项，每个参与解析的 XML 最多 8 MiB、总计 24 MiB；二进制媒体不展开。读取工作线程超时 15 秒，最多并发 2 次。单次返回最多 24000 字符，较大内容通过游标继续读取。
- 文本提取不是版式审阅，不包含全部图片、批注或嵌入对象。公式和关键统计应回到真实数据核验；旧式 Office、加密文件或非受支持格式不承诺通用解析。
- 模型仍负责按用户任务决定读取哪些页/章节，不能保证每次都自动遍历所有文件；提示合同要求逐项交代遗漏、部分读取和解析失败。

### 原生压缩防错

- 继续使用原生摘要、最近消息保留和旧工具输出裁剪，不再创建另一套 checkpoint 或总结模型轮询。
- 摘要请求失败时，原生错误记录不是有效压缩边界，原始历史仍在。
- 针对“原生摘要结束且无错误，但摘要文字为空”的边界补校验：丢弃该无效摘要及其压缩标记，不删除普通消息、附件或非空摘要。
- 执行中发现空摘要会停止本次任务并提示重试，不自动重放已执行操作；下一次发起前也检查遗留空摘要。不能保证异常前上游尚未产生任何费用。
- 不承诺记住全部文件细节。原始路径、页码、表格范围等保留为按需重新读取的依据。

所有原生集成验证使用固定内核、隔离配置及本机模拟 API，不使用用户密钥，不产生付费模型调用。

```powershell
corepack pnpm smoke:opencode
```

实际验证包括：约 23 MB PNG、22 MB JPEG 原生缩放；多图与文本同轮；约 9.9 MB PDF 生成约 13.2 MB 事件；摘要不携带 Base64；保留最近对话和文件路径；压缩失败后继续发送原始历史；空摘要撤销后恢复上下文；事件重连不重复提交任务。

这些验证不等于 Mac 实机、真实上游网关或模型理解质量验收。

## 用户复测

无需指定工具名称，使用自己的脱敏文件。测试失败时导出诊断 ZIP，并注明操作系统、模型、文件类型和大小。

1. 上传原先失败的那批 PDF：
   > 请先列出我上传了哪些文件，再分别概括每份材料的主要内容。如果有哪份没有读完或读取失败，请明确说出来，不要猜。

2. 同轮上传 PDF、Word、Excel、PPT，总大小超过 10 MB：
   > 这些是同一个项目的资料。请对比它们，整理项目目标、预算、进度和相互矛盾的地方，并注明分别来自哪个文件的哪一页、哪张表或哪一页幻灯片。

3. 上传较大 JPG/PNG 或扫描 PDF：
   > 请读出其中的关键数字和注意事项。小字看不清、空白或无法识别的部分请说明，不要自行补全。

4. 上传长单行 JSON，末尾放一个容易核对的标记：
   > 请找到文件最后的测试标记，告诉我它的实际值。然后说明你读取了哪些范围。

5. 多轮修改要求，触发原生整理后继续：
   > 之前预算作废，以这轮的 8 万元为准。请保留原文件中的其他约束。
   > 现在请复述最新预算和仍有效的约束，并说明依据哪些资料；不确定的细节请重新检查文件。

6. 文件读取中点击停止，随后继续：
   > 接着处理刚才的资料，只补还没完成的部分，不要重新生成已经完成的文件。

预期：不闪退、不因合法大事件中断；部分读取有说明；可以停止、继续；旧记录和原始附件仍可访问；不把未完成任务显示为成功。
