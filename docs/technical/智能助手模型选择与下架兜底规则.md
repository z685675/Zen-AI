# 智能助手模型选择与下架兜底规则

## 适用范围

此修复发生于 1.1.71 发版之后，不包含在已生成的 1.1.71 安装包内。

## 规则

1. 普通模式的可选模型由 API 面板的非开发者名单控制，客户端筛选、会话创建、会话修复与发送前校验使用同一套判断。
2. 开发者/VIP 模式绕过客户端的远端选择限制，允许使用各已启用 Provider 中已导入的可用模型。旧配置中的 `developerAllowlist` 和 `developerModeBypassAllowlist` 不再影响这一模式；保留字段以兼容协议。
3. 开发者模式不强制覆盖仍可用的用户默认模型。普通模式保留已有的远端版本发布覆盖规则，同一版本反复拉取不反复重置用户选择。
4. 默认模型不是仅用于推荐。会话模型不存在、所属 Provider 关闭或普通模式不再允许该模型时，必须修复会话模型：同名模型仍存在于其他已启用 Provider 时优先保持同一模型；否则优先选择远端 `assistantNewSession`，然后 `assistant`，之后按备用模型顺序尝试。
5. 远端默认和备用都未导入或不可选择时，最后使用列表内其他符合当前模式的可用模型；没有任何可用模型时才提示用户配置。不会发送空模型或编造固定内置模型。
6. 此可用性判断基于客户端已导入的模型列表，不等于发出请求实测上游健康；不把一次网络或上游临时失败直接当成永久下架。
7. 真正的服务端访问权限、余额、渠道上下架及全局强制禁用仍由各 Provider 服务端执行。客户端开发者开关不能绕过服务端鉴权。

## 一致性修复

- 新建会话使用真实开发者状态，不再硬编码为普通模式。
- 模型校验不截断至前 1000 个，使用本地模型接口的完整列表。
- 去除重复的空会话修复流程，使用统一兜底顺序。
- 会话、模型、开发者开关、远端规则或 Provider 列表发生变化后重新检查；不覆盖生成中的会话。
- 用户切换会话或模型时，作废旧的异步检查结果，避免过期结果覆盖新选择。
- 输入框随 Provider 启用状态及模型列表变化更新，发送前再次检查权限，草稿不会在校验失败时被清空。

## 手动验收

1. 普通模式：下拉只显示面板放行的模型。选择其中一个，新建会话，发送“你好，请简单介绍一下你可以做什么”，应正常发送。
2. 开发者模式：选择个人 Provider 的 Claude 或其他不在普通名单中的模型，新建并发送同样的问题，不应被普通名单拦截。
3. 发布新的远端默认模型：开发者当前模型仍可用时不被强制换掉；普通模式按既有发布覆盖设置处理。
4. 移除当前会话模型：当远端默认模型已导入且可选，应切换至该默认，保留旧会话消息，而非优先选其他备用。
5. 关闭所属 Provider：不应继续提交旧模型；其他 Provider 提供同名模型时可保留模型，否则走远端默认及备用。
6. 移除远端默认但保留其他放行模型：仍可正常创建会话，不误报“后台没有配置”。
7. 从开发者切回普通模式：超出普通名单的会话模型应修复为默认/备用，发送不能绕过普通模式限制。
8. 停用所有 Provider：明确提示没有可用模型，不能发出空模型请求；重新启用后不需要重建会话即可恢复检查。
9. 在检查期间快速切换会话或模型：过期检查不能覆盖新选择。

## 自动回归覆盖

策略测试及会话创建测试覆盖普通名单、开发者绕过旧配置、跨 Provider、远端默认缺失、默认优先于备用、关闭默认覆盖后的下架修复、开发者模式切回普通模式，以及无模型时阻止创建。
