# 新版助手微信接入与定时任务开发手册

- 更新日期：2026-10-16
- 核对基线：当前工作区，Zen AI 1.1.73（包含尚未提交的新版助手改动）
- 状态：新版微信／定时任务服务、管理界面、受控工具、电脑续聊和投递链路已接通；最终自动回归和生产构建已通过。真实微信与 macOS 实机验收仍待用户进行，不能按生产环境已验收理解。

本文作为开发、交接和验收的共同依据。第 8 节的勾选表示实现及自动化证据，不表示真实微信／手机文件已验收；实机未完成的项目保持未勾选。第 2 节保留最初源码核对背景，现状以第 12 节为准。

## 1. 已确认的产品定位

### 1.1 一个内核，三个入口

| 入口 | 定位 | 边界 |
| --- | --- | --- |
| 桌面新版助手 | 完整的多步骤任务、文件处理、浏览器操作 | 保持现有计划／执行／全自动和目录授权 |
| 微信助手 | 离开电脑时的轻量问答、简单文件制作和处理 | 不是远程桌面，不默认获得整个电脑的文件或命令权限 |
| 定时助手 | 用户明确创建、按时间执行的任务 | 仅在预先授权的任务与目录范围内工作 |

- 复用 OpenCode 原生执行循环、会话和压缩，不增加第二套 Agent 循环、上下文整理、自动续命或任务重放系统。
- 微信以文字问答为主，不强制把每句话变成复杂任务；允许连续追问，不硬性限制两轮。
- 文件制作必须实际返回文件；本地路径、工具卡片或“已生成”的文字不能代替微信文件交付。
- 普通用户不需要理解预授权工具 ID、自主模式、心跳等术语。
- 本地运行方案需要电脑和 Zen AI 保持运行、联网；锁屏与睡眠不同，睡眠、关机、退出软件时不承诺执行。
- 最小化改动 OpenCode 核心，在消息入口、权限配置、任务调度、结果交付外围实现功能。

### 1.2 旧选项的处理

| 旧版设置 | 新版决策 |
| --- | --- |
| 预授权工具清单 | 不搬旧工具名单，采用新版实际工具与原生权限规则 |
| 自主模式／Soul Mode | 不迁移；多步任务由 OpenCode 负责 |
| 启用心跳＋间隔 | 不默认开启；周期性工作统一为用户创建的定时任务 |
| 长篇旧底层提示词 | 不整体复制，只增加简短、真实的微信／定时入口说明 |
| 全自动权限 | 桌面设置不被修改；后台使用单独、受限的自动执行配置 |

旧助手继续只读，旧微信、旧定时、旧心跳不能通过翻转总开关整体恢复。配置、凭据和历史保留；迁入新版必须由用户确认。

### 2.1 不可直接搬用的关键逻辑

1. 当前旧 `ChannelManager.start()` 会停连接并停用全部渠道；旧 Scheduler 恢复时会暂停全部旧活动任务。接入新版后必须按归属限定范围，不能让旧关闭逻辑误停新版。
2. 旧 `deleteLegacyWechatChannels()` 以旧官方助手 ID 判断记录是否可删除，可能把新版记录当成旧记录。新版不得进入该清理分支；本批不删除用户旧配置。
3. 旧回传按“第一个聊天对象”找收件人，存在错发风险；不能作为新版兜底。
4. 旧桌面完成回调等待微信发送后才关闭流，可能让“模型已回答”被微信断线拖成“仍在处理中”。需解耦。
5. 旧同一渠道的单个 `sessionId` 不能作为不同身份、不同会话的共同上下文。
6. 旧后台允许的系统目录、终端和通用 Python 不符合微信轻量权限边界；不能只改提示词而保留同样的执行面。
7. 旧定时任务默认复用上一轮会话。新版默认每次独立执行，按任务归档，而非无界累积全部运行历史。

## 3. 最小实现架构

```text
微信消息 ── 身份校验／消息去重 ──┐
桌面续聊 ── 精确会话绑定校验 ──┼─ 共享并发与会话串行 ─ OpenCode 原生运行
定时到期 ── 执行时刻去重 ─────┘                         │
                                      持久化本轮消息、结果与成果清单
                                                       │
                                     可靠发件箱 ─ 微信文字／文件发送
```

- 普通桌面会话没有微信绑定，不进入微信发送链路。
- 发送失败只影响交付状态，不能把已完成的模型任务改成模型失败，更不能重新运行模型任务。
- 复用现有 SQLite 渠道、任务、运行记录和会话数据。新增可靠绑定、收件去重、发件箱所需数据时采用最小增量迁移，先备份、测试升级和关闭功能后的兼容行为。
- 不修改现有 Redux 持久化 state 结构或 Dexie／IndexedDB schema，不用提示词或聊天正文偷偷存凭据、授权、投递状态。
- 新增服务名称可以按仓库风格调整；责任边界不能混入 OpenCode 原生执行循环。

## 4. 电脑与微信双向续聊规则

### 4.1 精确绑定

- 首期只开放本人使用的私聊，不开放群聊或任意联系人远程使用。
- 每个绑定至少包含：`channelId`、登录账号标识、接收人标识、Zen `sessionId`、绑定版本、启用状态。
- 每个“登录账号＋接收人”只有一个当前微信会话；旧会话保留，不因打开历史自动改变手机当前会话。
- 进入旧微信会话继续同步前，由用户明确“恢复此会话的微信同步”；其他会话的同步状态相应停用。仅查看历史不触发任何发送。
- 用户在微信明确新建会话后，建立新会话，不覆盖历史；不依赖模型猜测“这句话是不是新话题”而随意清空上下文。
- 绑定切换不能发生在同会话任务执行中；先完成或由用户停止，再切换。已排队消息保留入队时的绑定版本，不能改投新会话。
- 新建分支、复制会话、从旧助手迁移，不自动复制微信投递授权。

### 4.2 电脑续聊的默认回传

在已经授权同步、当前绑定有效的微信会话中：

1. 电脑发出的本轮用户消息写入同一份会话历史，并作为独立消息投递到手机，标注“电脑端消息”。
2. 助手完成后发送本轮最终面向用户的回答，以及本轮已验证、实际登记的成果文件。
3. 不发送隐藏推理、工具参数、日志、密钥、临时文件、本地绝对路径和内部压缩摘要；不把所有历史再发一遍。
4. 用户在电脑添加的输入附件默认只同步附件名称和处理状态，不自动把原文件外发。需要发送原件时由用户明确选择；成果文件按既有同步授权交付。
5. 已确认收到的用户消息或文件不能因为助手回答发送失败而重发。分段、文字、文件分别记录投递状态。
6. 电脑本轮提问和最终回答可以分别到达手机；如果模型失败，明确发送失败状态，不能让手机只收到问题却以为仍会无限等待。
7. 用户手动停止时，最多发送一次“已停止”；如发送部分回答，必须标注未完成，不当成完整结果。

桌面持续显示“此会话同步到微信”的状态，可关闭同步；不能在用户不知情时把普通桌面对话外发。关闭同步立即停止未发送项，不撤回已经发送的消息，也不删除历史。

### 4.3 微信发起的消息与电脑显示

- 手机消息、助手最终回答、附件与成果由主进程可靠写入；窗口关闭到托盘、切换页面、没有订阅、重新进入会话，都能恢复完整记录。
- 实时事件只更新展示，不重复保存同一条消息；不要求网页／渲染窗口在线才能记录。
- 手机与电脑同时发消息：同会话串行，用户看到等待状态；执行前重新取已提交的最新会话状态。不能两个请求同时修改同一个 OpenCode 原生会话。
- 手机收到的“电脑端消息”和助手回复是投递结果，不能再次作为新微信输入触发模型，避免回环。
- 新版本重启后可以恢复用户明确启用且身份未变的新版连接；不能自动恢复旧版停用任务和连接。

### 4.4 历史操作不等于微信撤回

- 本地删除消息、清空历史，不承诺删除手机已经收到的内容。
- 清空会话后失效旧会话的待发项、原生续聊状态与绑定版本，不能旧内容稍后又发到手机。
- 重试生成属于新的明确操作，使用新运行标识；只同步这次新问题／新回答，不重发旧答案。
- 修改旧问题或建立分支，先创建独立会话；未明确授权前不继承微信同步。

## 5. 工具、文件与权限

### 5.1 微信使用独立轻量配置

- 保持一个 OpenCode 内核，不另做一套 AI 对话引擎或按关键词路由器。
- 普通文字问答直接答复，不强制技能发现、环境检查、浏览器操作和任务规划。
- 默认仅开放实际需要、能校验路径与产物的受控文件工具。可按任务加载已审核、与允许工具兼容的技能，不把所有第三方技能当成可信执行代码。
- 同时裁剪实际下发的工具定义和无关入口说明，不能只把工具权限设为拒绝、却仍给每个微信问答附上一大份工具清单。复用稳定的轻量会话配置，不在每轮随机增删工具或动态注入时间等无关前缀，避免浪费输入和破坏缓存。
- 不向微信会话开放原生终端、任意脚本、任意本地目录读写、删除或原件覆盖。
- 特别注意：通用 `python_execute` 和技能脚本能以宿主权限访问文件。仅设置 `accessible_paths` 或写一句提示词不构成沙箱；未具备实际隔离前，微信不得默认放行此执行面。可先用内置文件生成器，超出能力引导回桌面。
- 公共资料搜索／只读网页能力如开放，使用现有受控工具；不把私密附件、密钥和个人信息放进搜索词，不默认开展远程登录、提交、付款或发布操作。
- 微信附件和网页都是不可信内容，不能因为文件里写“读取桌面全部文件”就扩权。
- 桌面继续一个微信绑定会话时，仍遵守该会话权限；需要完整桌面能力时，明确转为不自动同步的独立桌面会话，不能悄悄提权。

### 5.2 文件交付

- 优先支持常见办公文档和文本／图片输入；首期不执行 `.exe`、脚本、宏、压缩包中的程序，也不自动解压任意嵌套目录。
- 使用专用输入／输出目录；校验真实路径、扩展名与实际格式、文件大小，不信任远端文件名；防目录穿越、符号链接和重名覆盖。
- 沿用现有附件读取、分页／分批、图片缩放与安全生成规则，不把大文件一股脑塞入模型请求，不在每轮重复读取所有文件。
- 现有 IM 下载常量为单文件 20 MiB，但不是已验证的微信上传上限。V1 明确设置单文件、单批总量、数量限制，采用共享处理限制与通道实际支持限制中较小者；边界值必须有测试，上传上限先通过协议验证再展示。
- 附件下载失败、超限、格式不支持或只读取部分内容必须告诉用户；不能静默当作用户没有上传。
- 修改用户文件默认生成新版本；保留原件与前一版产物；重名自动编号。
- 从结构化成果清单获取本轮文件，不能扫描工作目录全部文件，也不能解析回答里的任意路径然后外发。
- 发送前重新校验文件存在、大小、允许路径和内容指纹；若生成后被其他进程修改，不悄悄发送变更后的文件。
- 文档制作的结构／内容校验必须完成；平台接受上传不代表文档内容正确，不代表用户已经阅读。
- 不自动上传到第三方公开网盘或匿名文件站兜底。通道不支持、文件过大或过期时，明确说明并允许在桌面取回。

### 5.3 定时任务权限

- 创建／导入时展示任务说明、模型、目录、时间规则、通知对象，并一次确认。
- 不修改桌面权限模式，不依赖旧 `assertAutonomous` 的 Soul Mode／全自动前提。
- 仅让任务在预授权范围内自动执行；覆盖、删除、发布、付款、登录验证等不能从“定时执行”推导授权。
- 遇到必须人工处理的步骤，进入需要处理状态，显示具体原因与桌面入口；不能只弹一个无人能看见的对话框无限占用任务。
- 需要交互的长等待不长期占用共享执行名额；释放全局名额不等于允许同会话并行写入，恢复时必须重新获得名额并校验会话版本。是否允许安全恢复必须有明确实现，无恢复能力时以中断结束，保留成果，用户确认后再继续，不后台重放已完成操作。

## 6. 消息可靠性与去重

### 6.1 收件去重

- 原始消息 ID、账号和接收人标识必须贯穿协议、适配器、处理器和持久化层。
- 收件唯一键至少包含“通道＋账号＋对方＋原始消息 ID”，不能用正文相同判断重复，否则用户连续两次“继续”会被误吞。
- 同一条消息重新轮询、断线重连或重启后重复到达，不重复请求模型。
- V1 按微信协议的单条消息接收一批附件；不同消息作为不同轮次按序处理，不设置旧版固定 8 秒等待，也不猜测跨消息合并。文件后追加要求可作为下一轮继续；若平台把文件拆成多条，则可能产生多轮模型请求，测试时需记录。
- 已开始的任务不被下一条普通消息隐式取消；停止、新会话等控制动作走明确处理逻辑。

### 6.2 发件箱

- 本轮运行标识、消息角色、段号、成果标识、账号／收件人快照和绑定版本组成稳定投递键。
- 本地历史／结果先可靠提交，再创建可恢复的待发记录；二者不能产生“记录说完成但重启后无结果可发”的空档。
- 最小区分：待发送、发送中、平台已接受、发送失败、结果未知、已取消。平台接受不等于手机已读。
- 网络错误时有限退避重试；明确失败可补发，响应丢失而是否送达未知时，不声称严格 exactly-once。平台支持固定客户端消息 ID 或查询时优先使用；否则标记未知，避免无止境自动重发，可由用户确认补发。
- 长回答按平台限制分段，保持 Unicode 字符完整与段落顺序。中途失败只补未确认段，不重发所有段落。
- 文件诊断分别标记上传和消息提交；发件箱按内容指纹与稳定投递 ID 去重，不把重名文件都当同一个文件。V1 不持久复用 CDN 上传凭据：手动补发可再次上传同一份已验证文件，但不重做文件或请求模型。
- 登录失效时停止无效重试并提示重新连接；不丢已完成产物。
- 更换登录账号、收件人、解除绑定、关闭同步后，旧待发项不得投给新身份。恢复时重新验证，不使用“当前第一个联系人”兜底。
- 有界重试和有效期：重启后不突然推送大量过期内容。超过投递窗口或有大量积压时显示数量与时间范围，由用户确认补发或取消。
- 断线恢复后的协议回复时效、`context_token` 失效和主动消息限制必须实测；不能承诺任何时候都能自动主动发送。

### 6.3 执行状态与交付状态分开

| 情况 | 执行状态 | 交付状态 | 后续动作 |
| --- | --- | --- | --- |
| 回答生成、微信发送成功 | 完成 | 平台已接受 | 不再发送、不重跑 |
| 文件生成、微信发送明确失败 | 完成 | 待补发／失败 | 只补发已有文件 |
| 模型在开始回答前失败 | 失败 | 错误通知待发送 | 展示真实错误，不伪造回答 |
| 执行中停止 | 已停止／未完成 | 停止说明 | 不把部分文件作为完整交付 |
| 发送结果未知 | 完成 | 结果未知 | 有幂等保障才安全重试，否则提示确认 |
| 同步被关闭或身份改变 | 完成或保持当前本地状态 | 已取消／需重新授权 | 不转发给其他人 |

## 7. 定时任务：复用基础，修正运行边界

- 复用单次、间隔、Cron 规则；UI 提供每天／每周的易用表单，不要求用户会写 Cron。
- 首期清晰显示按本机时区执行及下一次具体时间，不暗示已有跨时区云调度；系统时区或时钟变化后重新计算并更新展示。
- 任务按计划时间进入执行队列，当前扫描间隔 5 秒，不承诺秒级准点开始；并发满额会继续排队，不把排队时间伪装成模型响应时间。
- 内部记录绝对执行时刻，针对夏令时、时钟前跳／后退测试，不同轮询不能把同一执行时刻运行两遍。
- 调度只检查本地任务表，不因此调用模型；不存在任务就不做模型心跳。
- 本轮任务使用唯一的“任务 ID＋计划执行时刻”占用记录；立即执行／用户重试有独立运行 ID。同任务手动和自动触发也不能同时执行。
- 不能只有内存 `Map` 防重：处理双窗口、重复 IPC、重启和重复定时扫描；任务已占用状态与日志一致提交。
- 默认每次独立会话，按任务归档；连续监测需要的上次结果只保存有限、明确的业务状态，不引入另一套 AI 摘要记忆。
- 普通模式 1 个、开发者模式 3 个共享任务名额；同会话仍最多 1 个。微信／定时等待有界，不挤占已经运行的桌面任务。
- 暂时满额是等待，不是模型失败；不得导致 API 渠道禁用、任务连续失败计数或自动停用模型。
- 睡眠或关闭期间错过的周期任务记录为错过，直接计算下次，不集中补跑；过期的一次性任务标记错过，可手动执行。
- 暂停停止后续触发；如果当前正在运行，UI 明确是否同时停止，取消后等待清理完成再允许恢复／立即执行。
- 编辑任务不改变已经执行的那一轮快照；新设置从下一轮生效。删除执行中任务先停止并结束当前记录，不能产生孤儿进程。
- 模型沿用现有 API 面板策略，在执行前重新解析；默认模型改变、下架或密钥失效有明确原因。不能在执行一半后从头换模型重做已经写文件的步骤。
- 运行失败累计 3 次暂停任务；排队、取消和微信投递失败不计入。V1 人工交互不在后台悬挂：拒绝不可用权限并保留会话，需到独立桌面会话完成；该次后台任务记为未完成。
- 应用退出或崩溃后，把未结束运行标为中断，不自动重放旧操作；未来到期任务可按用户新版授权恢复，旧版任务仍暂停。
- 成功／错误通知只发给任务明确订阅且身份校验通过的目标，不向适配器所有历史联系人广播。定时结果通知不切换用户当前微信聊天会话。

本批不做：群聊、多用户共享控制电脑、其他 IM 平台、关机云执行、任意本地命令、旧助手恢复运行、旧历史自动全量推送微信、第二套上下文压缩、复杂跨设备文件预览编辑。

发布前必须同时满足：

1. 微信普通问答稳定，手机与电脑接续同一绑定会话，其他会话不外泄。
2. 宣称支持的文件格式能真实制作、回传、下载打开；原文件和上一版结果保留。
3. 重连、重启、重复消息、补发不会额外重做模型任务或文件任务。
4. 定时任务可管理、可追踪、可停止，不因旧关闭逻辑失效或误恢复旧任务。
5. 权限不是只写在提示词里，无法满足的隔离能力不对微信开放。
6. 模型完成、文件完成、微信平台接受分别准确显示，不把发送失败误判为模型失败。
7. 旧助手只读及原生 OpenCode 桌面能力无回归，自动化与实机验收分别记录。

## 12. 2026-10-16 实现现状与首期边界

- 设置入口：设置 → 微信与定时任务（新页面），路由 `/settings/assistant-automation`。
- 只有用户明确扫码确认或创建授权任务后才运行；不需要把桌面助手切到全自动，不要求开启旧自主模式、旧预授权或心跳。
- 微信／定时使用独立专用目录和 5 个受控工具：`create_file`、`read_document`、`present_files`、`ocr_file`、`web_search`。不开放通用 Python、第三方技能脚本、终端、浏览器登录和任意目录。
- 常见文件制作使用内置生成器；精细排版、复杂数据脚本或需要登录的网站转到独立桌面会话。不是把微信变成不受限的远程电脑控制器。
- 文件名在磁盘中改为独立随机名称，避免覆盖；不把远端文件名当路径。
- 不做跨微信消息的隐式附件合并。不同消息是不同轮次；可以随后说“按刚才文件继续……”，但可能先收到上一轮回复并产生额外调用。
- 文件交付由新服务直接使用协议层的通用文件方法，旧 WeChatAdapter 与旧调度仍关闭。
- 每段发送最长 60 秒；单文件 20 MiB／单批 40 MiB／最多 6 个是本地保护限制，不是微信平台已确认上限。回复令牌过期会失败，不绕过平台主动消息限制。
- 发送结果未知默认不自动重发。用户确认补发可能仍导致重复消息；稳定客户端消息 ID 不是已验证的严格“恰好一次”保障。
- 任务通知绑定精确授权版本：新建／恢复微信会话或重新登录后，受影响任务显示需要重新确认，请编辑保存。不会悄悄改投新绑定。
- 重试交付不会重新调用模型；手动再次执行任务是新运行，会再次产生模型用量。
- 极端情况下，本地结果已经保存，但创建发件箱记录又发生存储故障：保留完成结果并释放运行名额，不重新请求模型。此时不能承诺手机自动补发，应在电脑取回结果并检查诊断记录。
- 后台任务最多 15 分钟；队列等待最多 10 分钟；超时保留已保存记录，不无限续跑。
- 电脑和软件必须运行并联网；睡眠或关机时无云端代跑。短时间错过会按扫描容差处理，长时间错过记录为错过而不集中补跑。
- 此批仍在本地工作区，安装版 1.1.73 不自动包含这些未发布修改。开发测试需完全退出并重新启动 `pnpm dev`；主进程与 preload 修改不能只靠页面热更新。
- 真机测试步骤和普通用户提示词见同目录《新版助手微信与定时任务人工测试-2026-10-16.md》，桌面另存一份。
