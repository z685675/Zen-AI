# 新老智能助手过渡

实现日期：2026-10-11。第一阶段保留旧入口，按用户要求建立新版独立副本。不隐藏旧入口、不批量搬迁、不强制切换。2026-10-12 起，只开发和扩展新版助手；弃用助手不再维护，微信等外部接入、定时任务及心跳全部停用，已有连接断开、已有计划暂停，配置与历史保留。

## 用户流程

1. 新任务只能在“新版助手”创建；老助手入口仅供查看历史，不能继续发送或执行。
2. 打开老会话，点击顶部或会话右键菜单中的“在新版继续”。确认说明后开始复制。
3. 成功后定位到对应新版副本，不能被首页“恢复最近会话”覆盖。旧消息标记“历史副本”，保留查看、复制、导出和已有文件入口，不可重试、编辑、删除单条或从旧步骤分支。
4. 用户发送新指令才开始工作。复制本身不调用模型、不执行工具、不自动续跑未完成任务。
5. 副本的新消息仍支持新版原生重试、分支和删除。可“查看原会话”；原会话删除时提示，副本仍可使用。

## 弃用助手后台功能停用（2026-10-12）

### 后续调整：旧助手只读

- 输入框禁用，固定占位提示“旧助手已停止使用，请切换新智能助手进行使用。”；发送按钮灰色不可点击，快捷键、粘贴/拖拽附件均不能发起任务。
- 关闭旧助手新建、重试、编辑再发等入口。主进程按新版助手身份准入，旧会话请求在流式响应开始前返回 HTTP 410 / `legacy_assistant_read_only`，不调用模型、不记为模型故障、不占任务名额。开发者模式和底座覆盖不能绕过。
- 原历史、附件、工作区文件、未发送草稿与配置不删除；保留查看、复制、导出、文件打开及“在新版继续”。不自动清理旧空会话或修复其模型，也不因没有模型/旧运行环境缺失阻挡历史查看。本地历史接口服务仍需启用运行。
- 不改 OpenCode 原生执行、重试或压缩。此前“旧版手动聊天保留”的设计及新老并行验收已被本节取代；任务额度继续适用于新版的不同会话（普通 1、开发者 3）。
- 最小验收：重启后打开旧记录，发送按钮置灰、占位文案正确，回车和旧报错重试均不能请求模型；开发者模式相同。复制旧记录到新版后可发新指令，AI 对话与新版发送不受影响。没有可用模型时仍能浏览旧记录。

验证结果（只读调整）：专项 8 个文件、62 项测试通过，覆盖禁用输入、普通/开发者旧任务拦截、410 响应、重试不改写旧历史，以及在新版继续。全量 `pnpm test --pool=forks` 386 个文件通过，4858 项通过、5 项跳过；`pnpm lint`（含类型/国际化）、`pnpm format`、Electron 构建和差异空白检查通过。没有调用真实付费模型，没有执行 macOS 实机或安装包 UI 验收。本次未调整版本、提交、推送或发版。

- 关闭旧助手所有外部连接（微信、Telegram、飞书、QQ、Discord、Slack）和定时任务，包括自动心跳。普通模式和开发者模式同样关闭。
- 开机不恢复旧任务或登录；先取消已有后台执行、断开适配器，再把所有渠道 `isActive` 设为 false、所有 active 计划设为 paused。此前留下的 running/waiting_user 运行日志标为暂停，而非模型故障。
- 后台取消仅针对远程消息/定时任务的控制器；旧版桌面手动执行另由只读准入关闭，新版不受影响。不删除旧聊天、文件、凭证、计划内容、订阅或运行历史。退出/停止不会自动撤销工具已产生的文件或外部操作。
- 移除微信/定时快捷入口和设置导航；已有设置链接展示停用说明，不挂载扫码、连接或运行按钮。旧助手过渡提示明确说明不再维护及功能关闭。
- REST 创建/启用/手动运行返回 410 和 `legacy_automation_disabled`，读取历史/删除自选配置仍可用。服务层阻止任务创建/恢复、渠道创建/启用；旧 MCP 不再声明 cron/notify/config，残留工具调用被拒绝。微信重连 IPC 在任何凭证修改或联网前返回停用结果。
- 此策略为产品边界，不由模型、Provider、远端允许列表或开发者模式改变。新版未来的微信与定时实现需独立设计、验收并重新授权，不能简单打开旧开关。
- 生效条件：运行本次修改后的代码，或用户升级到包含修改的安装包并重启。不能远程停止仍运行旧安装包的用户电脑。本轮不改 API 面板、不改版本、不提交或发布。

最小验收：完整退出并重启软件；确认旧微信/定时入口消失，旧设置地址仅显示停用说明；此前启用的微信不再回复，计划到期不执行；开启开发者模式并重启仍不恢复。旧会话可查看、复制到新版继续，新版手动任务与 Skills 正常使用。

验证结果：新增 6 个文件、24 项停用回归测试，覆盖真实产品策略、后台取消/队列清理、持久状态、REST、MCP 和设置深链。全量 `pnpm test --pool=forks` 384 个文件通过，4846 项通过、5 项跳过；`pnpm lint`（含类型与国际化）、`pnpm format`、Electron 构建和差异空白检查通过。未访问真实微信账号或付费模型，未执行 macOS 实机验证。

## 历史与记忆的区别

- SQLite 深复制全部已保存的展示记录，重新生成消息和块 ID，重映射 askId；不修改原消息。
- 给 OpenCode 用 `noReply: true` 保存 synthetic 背景，旧工具不转换成原生工具调用。
- 长历史采用明确标注有损的本地摘录，优先起始信息和最近消息，最多 24,000 字符，按模型额度进一步收窄。不是 AI 语义总结，不承诺所有细节或百分比准确率。
- 保存分行文字档案 `history.txt` 和结构化备份 `history.json`，需要细节时读取而非猜测。分行避免原生 read 工具截断巨大的单行 JSON；结构化备份保留原文字。档案保留文字、附件引用和历史工具结果，不带旧系统提示、思考过程或 SDK 状态；原展示块另外完整保存。
- 此后使用 OpenCode 原生会话与压缩机制，不套用 AI 对话的 checkpoint。

## 权限与文件边界

- 沿用原会话已授权、存在的工作目录，不扩展用户目录权限，不覆盖旧配置/Skills。缺少新版内置技能时直接读取软件自带资源。
- 生成产物仍共享实际文件；记录独立不代表文件回滚或文件系统快照，须检查当前状态。
- 上传附件仅复制可读的引用文件，不扫描整个目录。真实路径须在原授权根目录或应用上传库内；单文件 64MiB、总复制 256MiB。超限或缺失提示重新上传，不宣称已复制。
- 档案和附件存于原目录 `.zen-ai/continuations/<新版会话ID>/`，预览使用独立路径；删除原会话附件目录不影响已复制附件。
- 原只读模式继续只读，其余权限恢复默认。环境变量、SDK 配置、微信、定时任务、旧授权与登录交接不继承。
- 旧内容是资料而非本轮指令。历史 pending 状态改为 paused，防止误称旧任务仍在运行。

## 一致性与失败保护

- 共享会话活动锁：执行中拒绝迁移；复制中禁止原会话新任务、修改和删除。
- 新建隐藏 preparing 会话；原生背景持久化后，事务重查原会话版本，再写入全部展示记录、变为 ready。半成品不出现在普通/归档列表。
- 来源 ID + 内容版本持久幂等；同一快照复用副本，不把新版分支当迁移目标，不抢回用户已归档的副本。
- HTTP 断开或 120 秒超时取消。提交前失败仅清理新隐藏会话；提交后响应丢失，下次可复用。崩溃留下的 preparing 会话，下次同快照迁移清理后重建。
- 失败后已写入的专属目录保留，避免误删后来放入的文件。删除会话也不递归删除工作目录的档案/产物；需要清理时先备份对应目录。
- 模型按当前远端/开发者规则选择；原模型不可用走现行默认/备用选择，无允许模型时保留原会话并提示配置。
- 历史安全上限：20,000 条消息或 64MiB 展示 JSON，超过则提示导出备份并在新会话提供必要背景。

## 验收范围

### 入口和共享任务额度（2026-10-11 补充）

- 新版助手位于“AI 对话”下方；老版入口改为“弃用助手”，位于主功能列表末尾。名称用琥珀黄色标识，悬停、选中及顶部显示模式也保持标识；保留老会话历史和在新版继续，不允许旧版手动对话，不删除记录。外部接入和定时任务不再运行。
- 对已有自定义布局仅调整新老助手位置，不重置其他功能顺序或显隐偏好。
- 单个客户端内，新版不同会话合计：普通模式最多 1 个运行任务，开发者模式最多 3 个；不同模型和 Provider 共用名额。旧版完全禁止执行，不占名额。AI 对话和图片生成不计入。
- 在主进程任务准入层同步预留名额；旧桌面执行、微信和定时请求先被产品策略拒绝，不修改 OpenCode 原生执行循环、重试、提示词和压缩。历史复制不算执行任务，但仍受同一会话的活动锁保护。
- 启动准备、模型生成、工具执行、等待权限/登录/验证码期间均占名额。完成、失败、停止后释放；已取消请求不占名额；异常启动失败也释放。
- 满额不自动排队或重复请求模型，只提示先完成/停止其他任务后再发；不当成网络或模型故障，不因此累计定时任务模型失败次数。
- 运行中关闭开发者模式不会中断现有任务；只按新上限限制后续提交，直到活动任务数低于 1。开启后后续提交可使用最多 3 个名额。

最小手动验收：

1. 重启开发环境，确认入口顺序和“弃用助手”黄色名称；切换顶部显示，确认名称与颜色一致。
2. 普通模式在新版助手发送“帮我做一份详细的旅行计划”，任务未完成时到新版另一会话发送“你好”，应只提示共用 1 个名额，不发第二条模型请求。
3. 停止第一个任务，再发送第二个，应能执行。打开弃用助手，无论名额是否空闲都不能发送，提示旧助手已停止使用。
4. 开启开发者模式，在新版合计启动 3 个不同会话的任务，第 4 个应提示共用 3 个名额；释放其中一个后第 4 个可执行。弃用助手仍不能执行。
5. 有 2～3 个任务时关闭开发者模式，已有任务继续；剩余任务全部结束前不能再启动新任务。重新开启开发者模式可按 3 个上限提交。
6. 若任务正在等待浏览器登录或权限确认，仍应占名额；不能通过切换入口、模型或 Provider 绕过上限。
