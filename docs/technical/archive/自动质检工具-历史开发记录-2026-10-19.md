# 自动质检工具：使用说明与开发进度

更新：2026-10-19。这是开发项目中的验收工具，不是面向普通用户的新软件，也不在 Zen AI 侧栏增加入口。

## 现在已经可以做什么

- 盘点 Zen AI / Zen API 已有检查，按改动选择相关回归；遇到未知或共享改动扩大检查。
- 串行执行已登记的离线检查与生产构建，汇总报告、失败证据 ZIP 和人工提示词清单。
- 启动独立数据目录中的真实 Electron 页面，自动在 AI 对话、新版助手中输入、发送、等待最终回答，不借用你的历史会话或保存的 Key。
- 快速验收：每个模型在每个选中入口问两轮；新版助手再做一轮真实读取 JSON、计算合计、新建文件，独立检查内容和原件未变。
- 成本验收：同一模型、同一份20轮用户提示词，分别跑两个入口。四大家族、两个入口合计160次用户发问；助手内部请求另行统计，不把调用条数当问题数。
- 测试前从选定Provider获取模型列表，支持搜索、刷新和手动选3个模型；quick/release按关联用例组混用，不在连续记忆中随机换模型。
- 默认无需报价：请求数、Token预留、每轮循环和超时控制测试规模，费用记“未核算”。另保留有报价的money模式，不能拿面板售价冒充采购成本。
- 每条模型请求发送前预留Token；money模式另外预留金额。命名、压缩、工具循环也计入，缺少用量、取消或断流不能当作免费。
- 记录输入、输出、缓存、按问的费用和1/5/10/20轮累计结果。输入包含缓存，不重复累加。
- 手动 GitHub Actions 可选择离线、代码发版检查或模拟界面验收，不配置付费密钥、不自动启动付费测试。
- 整批编排 quality:acceptance：代码门槛 → 金标准文件 → 隔离双入口 → 指定安装包 → 明确批准的真实模型；统一报告与人工签收。前置失败不再花钱继续跑。
- release/deep矩阵已接入：按所选格式上传与独立解析、另存办公文件、累计超过10MiB的双JSON、受损文件、重新加载历史、分块资料与两次更正。
- 深度用例要求实际输入Token与真实checkpoint/原生压缩证据；未达到门槛记“未验证”，不把字符数或普通20轮说成200K压缩通过。
- 可选独立裁判：先用正确/错误/不确定样本校准，再评估合成关键事实，单列调用与子预算；裁判不能覆盖硬失败。
- 导出账单按精确requestId对账；同题库/型号/价格/节奏的前后两批可比较；未知渠道和结算继续标未知。

本次已用自建本地模拟接口跑通实际执行器：双入口5轮、9条底层请求、真实工具执行和独立结果核对，付费请求为0。模拟通过不代表四大家族的真实上游均已通过。

## 最简单的使用方法

在 Zen-AI 项目目录中运行。需要事先安装项目依赖，工具不会偷偷安装依赖或使用你的生产 Key。

### 日常改动，只测相关部分

~~~powershell
pnpm quality:changed --project ai --base HEAD --dry-run
pnpm quality:changed --project ai --base HEAD
~~~

HEAD 表示当前尚未提交的改动。要检验两个版本之间的功能差异，改成明确的旧提交或 tag。两个仓库历史独立，联合选择时分别给基准：

~~~powershell
pnpm quality:changed --base HEAD --api-base HEAD --dry-run
~~~

基准缺失、映射损坏、未知源码或共享配置变化会扩大检查；零测试不会写成产品通过。

### 离线关键回归与发版代码检查

~~~powershell
pnpm quality:offline
pnpm quality:release
~~~

默认联合相邻的 Zen-API 仓库。只有客户端时明确加 --project ai；面板路径不同可以用 --api-root。

~~~powershell
pnpm quality:offline --project ai
pnpm quality:release --project api --api-root "C:/你的目录/Zen-API" --bun "C:/你的目录/bun.exe"
~~~

工具只执行内置命令清单，不提交代码、不打 tag、不部署、不监测安装包构建。

### 不花钱，先测试实际界面与验收工具

先生成开发构建；之后不要边改源码边跑验收。

~~~powershell
pnpm build
pnpm quality:ui
pnpm quality:smoke
~~~

- quality:ui：真实界面 + 本地模拟模型，验证双入口、两轮更正、文件工具、原件保护和正常退出。
- quality:smoke：再覆盖完整的“预览 → 批准摘要 → 实际执行器 → 预算账本 → 成本报告”路径。
- quality:smoke mixed：同一执行器获取本地模型列表、选择3个型号、双入口15轮、真实文件工具和无报价账本。此模式也只连接脚本自己启动的本地服务。
- 这两个命令的模型地址由脚本自己创建，只连本地模拟接口，不读取真实 Key，不发生付费请求。
- 将启动独立测试窗口；不会在你正在使用的会话里发问。生成的数据留在本次报告目录供排查。

## 如何获取模型、选3个并运行验收

### 1. 交互创建配置

先在本机安全输入专用测试Key环境变量，然后运行配置向导。不要把Key发到聊天、写进JSON或命令参数：

~~~powershell
$qualitySecret = Read-Host "专用测试 Key" -AsSecureString
$env:ZEN_QUALITY_SELECTED_KEY = [System.Net.NetworkCredential]::new('', $qualitySecret).Password
pnpm quality:configure
~~~

按提示操作：

1. 填Provider的OpenAI兼容接口地址（含/v1）、测试Key环境变量名和分组备注；默认使用ZEN_QUALITY_SELECTED_KEY，不读取软件保存的日常Key。
2. 获取/models列表，只发GET元数据请求，不做“你好”探活或模型生成。列表支持/关键词搜索、/清空、r刷新；输入3个不同序号确认，q取消。搜索后序号仍按完整列表，不会变号。
3. 选择quick快速验收、release文件/历史/记忆、deep容量压缩，或cost双入口20轮；选择chat / assistant入口。
4. quick/release默认混用：3个模型均跑基础对话；文件读/制作等关联组分配给同一个模型，记忆资料与后续更正不拆开。报告明确实际分配，不把未测组合当作通过。deep/cost逐模型完整执行，不混合分配。
5. 默认最多60条底层请求，每轮8条；单请求输入预留128000、输出2000，累计输入1000000、输出60000 Token。可打开自定义限制；达到任何限制提前停止，未执行项保留。
6. 确认费用未知、按数量限量验收。此步只保存配置，不启动生成；仍要预览并批准摘要后执行。

型号来自实际列表，保留完整ID，不猜别名。少于3个候选会提示检查权限；明显的图片生成/向量/音视频型号不用于文字验收。未知家族由操作者确认，不声称名称能证明能力。配置保存在local/quality-configs，仅保存Key的环境变量名。

默认budget.mode=tokens、acknowledgedUnknownCost=true，不填写prices/currency/maxAmount，也不启用额外付费裁判。数量限制不是人民币支出保证；模型可能忽略输出限制，缺失用量按预留占用。不要将金额未知写成0元。

需要金额控制时，可另建budget.mode=money配置并提供有效报价、currency/maxAmount；旧money配置继续可用。以下估算规则只适用于money模式：

价格必须是该测试 Key 的实际分组/折扣价，并写明来源；不是直接套官网价或公共默认分组价。价格快照默认有效24小时。存在长上下文阶梯的模型应在配置中补全阶梯；缓存写入有不同 TTL 时要核实有效价或选择明确的保守最高价，不能猜测。

tests/quality/live.example.json仍是故意不完整的money占位示例；缺报价会阻塞金额模式，不影响向导创建的无报价限量验收。示例预算不是付费授权。

### 2. 费用是怎样估算的

输入包含缓存读取、缓存写入时：

~~~text
普通输入 = 总输入 - 缓存读取 - 缓存写入
费用 = (普通输入×输入单价
      + 缓存读取×读取单价
      + 缓存写入×写入单价
      + 输出×输出单价) ÷ 1,000,000
~~~

例如仅作算术演示：输入13万，其中缓存读取12万，输出1000；
输入单价2美元、缓存读取0.1美元、输出10美元/百万 Token，且没有独立缓存写入。
费用 = 1万×2/百万 + 12万×0.1/百万 + 1000×10/百万 = 0.042美元。
不是把13万和12万都按普通输入再算一遍。这不是当前模型的官方报价。

执行前显示的是保守预留：不假定缓存必命中，按已核实价格中可能最贵的输入类型和适用阶梯预留。每次返回可靠用量后，释放多余预留；用量或缓存统计缺失时保留该请求的最大预留，并标为“待核实”，不伪造准确费用或0缓存。

预算低于整批保守上界也可以运行，但可能提前停止，未执行部分不会算通过。客户端不能保证上游严格遵守 Token 上限或价格不变；建议专门创建有服务端额度限制的测试 Key。未知渠道、账号和采购价不冒充已知，价格快照估算不等于账单结算。

### 3. 构建后预览，不扣费

~~~powershell
pnpm build
pnpm quality:live --project ai --config "local/quality-configs/你的配置.json" --dry-run
~~~

预览检查模型、用例分配、数量限制、题库、构建和本机OpenCode；money另外检查有效报价。approvalDigest绑定配置、源码、构建、内核与题库；变更后须重新预览。

真实执行走OpenAI兼容chat/completions。文字与工具可直接按Token报价；PNG/JPG读入需明确填写vision.maxImageTokensPerRequest并核实按输入Token计费。外部图片URL、未经批准的媒体、原生Gemini/Anthropic/Responses及音视频不会擅自放行。PDF能否作为文字提取或原生文件发送取决于产品实际链路；未支持的媒体计价会阻塞，不冒充模型能力失败。

### 4. 确认预算后再执行

只在本地终端输入专用测试 Key，不要发到聊天中。Key 只提供给这次父进程网关，界面和 OpenCode 子进程拿到的是本地占位凭据。

~~~powershell
$qualitySecret = Read-Host "专用测试 Key" -AsSecureString
$env:ZEN_QUALITY_SELECTED_KEY = [System.Net.NetworkCredential]::new('', $qualitySecret).Password
try {
  pnpm quality:live --project ai --config "local/quality-configs/你的配置.json" --approve "报告中的完整approvalDigest"
} finally {
  Remove-Item Env:ZEN_QUALITY_SELECTED_KEY -ErrorAction SilentlyContinue
}
~~~

不带完整批准摘要、缺少指定凭据、构建/题库不匹配时拒绝执行；money模式还会拒绝失效报价。不会换其他模型掩盖失败，也不会扫描保存的个人Key。configure用过的环境变量可在同一终端沿用；本次完成后清理，不要打印其值。

Ctrl+C 取消后停止后续请求，清理本次进程；在途请求可能已计费，报告保留其保守预留。不会自动重放整个失败批次。

## 报告在哪里、怎么看

命令结束会打印绝对路径：

~~~text
项目/local/quality-reports/quality-时间-唯一编号/
  report.md / report.json
  manual-checks.md
  检查编号.log / 检查编号.tests.json
  budget.json
  cost-summary.md / cost-summary.json
  live-observations.json
  target-编号-入口/calls.json
  failure-evidence.zip（失败、不完整或取消时）
~~~

- 先看 report.md：已执行项、阻断项、版本和限制。
- 再看 manual-checks.md：剩余人工操作、可复制提示词和预期结果。
- 成本表按模型和入口展示实际尝试/完成的问题数、底层调用、输入/输出/缓存、分轮累计和未知部分。
- 每个入口使用相同题库但独立会话；不同型号交替入口先后，减少固定顺序偏差，不能消除上游渠道变化。
- 本轮问题归属采用隔离任务的活动时间窗口，包含观察到的辅助调用；不等于已经与 API 面板的任务 ID / 实际扣费逐条对账。
- 命名/整理默认采用本批模型，不沿用你的日常辅助模型设置，报告必须注明这一差异。
- 截图和隔离测试数据留在本地，失败 ZIP 只打包白名单文字证据并脱敏，不递归打包用户数据、Cookie、浏览器目录或文件产物。转交别人前仍需检查。

结果状态：passed 仅代表执行项通过；failed 为明确失败；incomplete 为未执行/环境阻塞；cancelled 为取消；planned 只是预览。成功断言后进程崩溃、报告不完整、运行期间代码变化，都不能当成通过。

内部退出码：0通过或明确计划模式，1失败，2不完整，130取消。pnpm外层可能归一化非0退出码，应同时看 report.json。

## 安全边界与仍需人工的部分

- 数据目录、浏览器会话、工作区和占位 Provider 都隔离；主进程 fetch / Chromium 限制外网，模型只能经过批准的预算网关。
- 这不是操作系统级沙箱。原生工具和子进程仍需信任；仅运行合成题库，建议专用测试账号。不要把不可信网页/第三方技能加入付费批次。
- 不启动个人已保存的微信/定时任务，不改变线上渠道、远程策略或普通用户数据。旧助手继续只读，不替换 OpenCode 原生执行循环和压缩机制。
- 还未自动执行安装包安装/覆盖升级、Mac实机、真实微信扫码和登录验证。
- Office读入/另存、关键数据/Excel公式、原件hash、分块记忆/容量/压缩证据、可选裁判与账单关联的执行器已补齐；真实四家模型、200K规模与文件排版的效果仍要在本期工具完成后验收，代码存在不等于效果已通过。
- release/deep必须明确子集；deep还需核实有效上下文上限、资料字符数、实测输入门槛、压缩要求。只在深度档显式同意后使用近似输入估算，配合服务端测试Key额度；达不到门槛不放行。
- 裁判只用三个合成样本作初步校准，不是专业知识/开放式语义的可靠性保证；专业与视觉质量仍抽检。
- GitHub手动工作流尚未推送/运行，Mac效果不能依据本机 Windows 结果宣布通过。

## 本轮实际验证和顺手修复

已跑通本地真实界面和完整实际执行器，未发送付费模型请求。实测发现并修复三处产品问题：

1. 极快的助手流结束时，未等待渲染消息队列处理完就销毁生命周期，可能出现“后台完整、界面空回答”。现在先等待队列结束，并新增回归测试。
2. Windows退出时，异步资源清理没有被Electron等待，可能触发原生进程异常。现在退出先等清理（有总时限），重复关闭不重复清理，再正常退出，并新增回归测试。
3. 本地服务并发启动时可能重复监听端口，失败请求又清掉成功实例引用，导致助手误判服务未启动。现在启动、停止、重启串行处理，失败不污染后续操作，并新增真实loopback并发/端口冲突测试。

这些修复不是对上游稳定性的承诺。真实四模型、真实渠道、付费成本仍需选定配置与预算后再验收。

## 整批发版验收与人工交接

1. 先把代码检查与构建做好，代码稳定后才预览实际模型批次。
2. 用tests/quality/acceptance.release.example.json创建本地配置，填本次安装包resources、平台/架构/预期版本；liveConfig引用选好模型及限制的tokens/money配置。未提供的必测平台与真实模型会列为阻塞。
3. 以下命令先只预览，不读Key也不扣费：

~~~powershell
pnpm quality:acceptance "local/quality-configs/release.json" --dry-run
~~~

核对后用同一命令加--approve完整摘要。只有配置了liveConfig、其计划完整、显式批准整批且环境变量有指定Key时，才会发付费请求。建议先做一批便宜模型quick，再扩展范围。

已有同一源码摘要、同档位并通过的代码report.json可填codeReport复用，避免把20分钟的全量测试再跑一遍。源码、报告或包变化必须重新预览；若CODE阶段重建导致在线构建摘要变化，也需重新预览，不能自动放宽批准。

离线整批示例不包含任何付费调用：

~~~powershell
pnpm quality:acceptance tests/quality/acceptance.offline.json --dry-run
~~~

依赖与构建已就绪时，pnpm quality:ci可直接执行仓库内固定的零付费整批（不接受付费配置）。必须用pnpm脚本入口启动，不能换成pnpm exec tsx后丢失子检查需要的pnpm入口。

整批目录另有release-gate.md、child-reports.json、manual-checks.md、manual-results.template.json。先修自动失败/阻塞，再按人工清单操作。填写人工模板副本并签收：

~~~powershell
pnpm quality:analyze signoff "本次报告目录" "人工结果.json"
~~~

签收绑定runId与代码摘要。人工通过不能覆盖自动失败；不改写自动report.json。releaseReady只是已登记范围已通过，不自动提交、打tag、部署或发布。

## 安装包与费用分析

~~~powershell
pnpm quality:package "dist/win-unpacked/resources" windows x64 1.1.73
pnpm quality:analyze reconcile "本次target目录/calls.json" "usage-logs.csv"
pnpm quality:analyze compare "旧在线报告目录" "新在线报告目录"
~~~

包检查核对实际版本、ASAR/内核hash、三个内核资源和本机执行；Mac另校验bundle链接，配置requireSignature时必须在Mac做codesign。现有Windows解包资源已验证，不等同于本次全部改动已重新打包或真实覆盖升级。

对账只认模型响应返回的请求ID与服务端导出ID精确匹配。ID缺失/异步日志未落库保持usage_pending；不按相近时间强行凑账。CNY报价与USD账单没有汇率不能硬比金额；缓存读写合计与后台缓存字段核对，输入仍包含缓存。
