# 自动质检工具：使用说明

更新：2026-10-23。在 Zen-AI 项目目录运行，提前安装项目依赖。真实模型验收使用独立测试窗口和数据，不借用日常会话、软件已保存的 Key，也不会发布软件。

## 1. 日常代码回归

先预览本次未提交改动对应的检查计划：

~~~powershell
pnpm quality:changed --project ai --base HEAD --dry-run
~~~

实际执行选中的检查（可以直接运行，不必先预览）：

~~~powershell
pnpm quality:changed --project ai --base HEAD
~~~

HEAD 是当前最新提交，因此比较的是尚未提交的改动。已经提交的最近一次改动可用 HEAD~1（需要存在上一条提交）。共享依赖、工作流或未知源码改动会扩大为 全量；只有文档改动可能没有源码检查。

直接跑客户端和相邻 Zen-API 面板的全量发布检查：

~~~powershell
pnpm quality:release --bun "C:/Users/admin/.zen-ai/bin/bun.exe"
~~~

只检查客户端时加 --project ai。工具只执行检查、测试和构建，不提交、不打 tag、不部署。

## 2. 本地模拟界面自检（不调用付费模型）

~~~powershell
pnpm build
pnpm quality:ui
~~~

自动操作真实 Electron 界面，用本地模拟模型检查双入口、发送/回答、真实附件上传、文件读写、原件保护和正常退出。进一步检查验收执行器自身可用 pnpm quality:smoke。模拟通过只能说明被测流程跑通。

原生工具审批另可运行 `pnpm exec tsx scripts/quality/native-write-ui-smoke.ts`：通过真实界面验证原生 read → write 的单次批准、拒绝、取消和原件保护。只使用隔离目录与本地模拟模型，不产生付费调用。

真实模型的基础文件任务按结果验收，不强制模型走同一种工具路线：独立检查合计、产物文件和原件。只会单次批准路径完全匹配的新文件 native write；遇到 bash 等未授权权限，会通过对应界面的“取消”拒绝，允许模型改用安全的文件工具，最多拒绝 3 次，反复申请或最终没完成仍判失败。拒绝过程、后续调用及 Token 均保留；拒绝本身不算文件任务通过。原生权限专测仍使用原来的严格 guard。维护者可运行 `pnpm quality:ui --tool-shell-fallback`，验证真实 UI 拒绝命令、命令未执行、模型继续读文件并生成正确结果，全程零付费。

错误路径自检可在构建后运行 `pnpm quality:smoke failures`：用本地接口复现 HTTP 500、空响应、错误事件及回答中断，检查真实对话界面显示失败，且失败后不继续向上游重发本轮请求。不会调用付费模型。

## 3. 真实模型快速验收：一条命令

~~~powershell
pnpm quality:check
~~~

人工只做三次输入：

1. 输入专用测试 API Key，回车。输入内容以星号显示。
2. Provider 地址直接回车，默认使用 `https://zenai.925636.xyz/v1`；要测试其他服务时输入对应的完整地址再回车。地址输错会原地提示重新输入，不会静默改用默认地址。
3. 从实际模型列表输入序号，例如 1 或 1,4,9，回车。选几个就测试几个，不再固定三个，也不要求凑齐某些家族。

命令会先自动构建当前开发版本，然后完成模型列表获取、配置、预检、代码/构建摘要绑定、实际测试和报告输出。无需手工设置环境变量、保存配置文件、复制批准摘要或再输入启动测试命令。选完范围即自动运行；启动时会明确提示可能收费，q 或 Ctrl+C 可以取消。

默认覆盖 AI 对话 chat、新版助手 assistant。每个模型都做两轮预算更正对话；每个模型的助手入口再做真实读取 JSON、计算合计、另存文件和原件保护检查。

测试启动时会明确关闭隔离 AI 对话助手的 Top-P，不发送该采样参数，由服务端采用默认值；无需在测试窗口手动关闭，也不依赖日常安装包中的开关状态。本地 `quality:ui` 同时检查双入口的实际请求未携带 `top_p`。

请求数、Token 和超时仍有限制，会按实际计划轮次显示本批上限。达到限制提前停止，未测项保留，不能算通过；费用未知不记为零，也不承诺人民币金额上限。不要边修改源码边跑验收。

单请求输出预留默认 8192 Token，包含上游计入的推理 Token，不只是可见回答文字。需要调整时用 `pnpm quality:check --output-reserve 16384`（允许 1～32768）；这不会自动提高整批累计输出上限，也不会修改已有高级配置文件。`--max-output-tokens` 仍只控制整批累计输出；预留大于整批上限时预检拒绝执行。较小的原生请求输出限制会保留，不会因预留提高而扩大命名等请求。上游若没有遵守所传限制，已产生用量无法撤销；工具按实际用量记账并停止后续请求，报告标记 `budget-gateway/request-token-limit` 并显示已用/预留，而不是把它当作模型服务故障或忽略推理 Token。

维护者可在构建后运行 `pnpm quality:ui --tool-python-cwd`，通过真实双入口界面与本地模拟模型验证：5033 输出 Token（含 4687 推理）在 8192 预留内不会被误拦截；Python 指定工作区外目录时仍拒绝，返回纠正说明，随后改用安全工具完成文件与原件保护检查。不需要准备 Python 或调用付费模型；该自检不代表真实 Grok 文件任务已通过。

等待回答时按实际情况显示“等待模型响应”“工具正在处理”或“等待工具权限确认”，状态变化及每 15 秒打印用时和本轮底层请求次数。quick 的另存文件用例只允许通过可见按钮单次批准预先指定的隔离目录新文件；原件、已有文件、其他路径或额外权限不会自动放行，也不修改用户的权限策略。

503、429 等可重试故障会等待产品原生重试的最终结果；工具本身不另起重试循环，每次实际请求均计入调用数、Token 和费用预留。恢复必须有相同请求的后续成功证据，失败尝试仍保留在报告中；不可重试错误、最终失败或“完成但无正文”均明确判为失败。默认原生响应头/流空闲上限 120 秒、单次请求上限 180 秒；验收网关默认 185 秒，让原生错误优先返回，显式设置更短预算仍生效。超时不是通过无限等待解决。

自动生成话题/会话名称是非关键辅助请求：客户端明确标记用途，命名失败或被客户端超时取消只记“通过（有警告）”，保留产品的本地标题，不中断已成功的主回答及后续轮次，也不误记为“原生重试后恢复”。请求若已发往上游，仍完整计入次数及费用预留，未知用量不当作零。主回答、工具、上下文整理和用途不明的请求仍严格判断；模型越权、预算/次数超限、用户整批取消等也不会因为命名标记而被放行。只有自动命名请求、没有主任务成功调用证据时不能算通过。

调用及拒绝记录包含脱敏后的请求方法、接口路径和用途；不保留 URL 查询参数。命名适配器若尝试质检网关不支持的 `POST /v1/responses`，仍拒绝转发并单列命名警告，不开放任意新接口。`quality:ui` 用本地模拟让两个入口的命名请求失败，验证正常回答及后续轮次不被阻断；主回答 400 和原生 503 重试也仍独立验证。

某模型、入口最终失败后，停止该会话，后续轮次保留为未测，再继续计划中其他模型和入口，不跳过失败问题拼接连续对话。用户取消、整批超时、全局预算耗尽或隔离实例清理失败时停止整批。HTTP 错误保留真实状态码、可取得的请求 ID 和有限长度的脱敏消息，便于核对服务端日志。

调用证据分别记录响应头等待、首段内容时间，以及故障来源/阶段（上游、验收网关、调用方取消等）。收到响应头不等于已收到模型正文；网关会立即转发真实响应头，不用虚假心跳掩盖等待。正常退出以子进程 exit=0 且无信号终止为准；退出未知、异常退出或强制终止仍算清理失败。

命名的主动取消/15 秒超时不额外触发网络探测。真实网络故障的连通性检查带独立用途标记；预算网关只在本地处理带标记的 GET `/api/status`、GET `/v1/models`。本地 status 明确返回“不支持确认上游健康”，只记诊断警告，不伪造上游正常、不产生付费转发；未知路径、方法和模型生成请求仍拒绝。维护者可用 `pnpm quality:ui --naming-timeout` 重现真实 15 秒命名超时，检查双入口主回答、后续轮次和正常退出，全部使用本地模拟接口。

应用退出时依次停止后台服务，再显式关闭已存在的助手数据库；并发初始化和关闭有独立回归。验收工具至少等待应用自身的 20 秒清理期限，并预留 5 秒退出传播时间；即使 Playwright 连接提前断开，也不会只等 2 秒就强杀正在正常清理的应用。数据库关闭异常、原生崩溃等仍算失败，不能通过忽略非零退出码来获得通过结果。

若失败时任务仍在生成或等待权限，工具先核对隔离实例身份，再通过现有暂停/取消审批按钮停止任务，确认停止后才关闭应用。停止失败、异常退出和强制清理分别保留证据；退出码记录强制清理前的状态，避免把工具强制终止误判为产品自身崩溃。单次重跑通过不能抹去已经捕获的间歇性原生崩溃，仍需定位后回归。

退出清理逐项记录开始、结束和耗时，最终等待日志写完。未安装的 OVMS 不再调用 PowerShell；已安装的停止命令只针对 Zen AI 的运行文件，并有 5 秒超时。浏览器工具退出统一等待，关闭过的实例不重复清理，未使用的隐私会话不在退出时临时创建。维护者在生产构建完成后可执行 `pnpm quality:exit`，连续验证 5 次真实进程退出与完整清理日志；可附加次数（1～20）。该命令只检查本地启动/退出，不调用付费模型；等待审批时退出另由 `pnpm exec tsx scripts/quality/native-write-ui-smoke.ts` 覆盖。

使用过的隐私浏览器会话可运行 `pnpm quality:ui --tool-shell-fallback --browser-private`：实际打开本地网页、读取页面内容，退出时验证浏览器清理及正常进程退出，不使用外部网页或付费模型。2026-10-22 本地回归已通过 347 项相关测试、连续 10 次启动退出、5 项原生审批界面用例，以及含隐私浏览器的双入口界面自检；历史间歇性原生崩溃本轮未复现，但不能据此断言唯一根因已被完全证明，后续真实模型验收仍保留退出检查。

只跑一个入口可直接指定：

~~~powershell
pnpm quality:check --entries assistant
pnpm quality:check --entries chat
~~~

### 验收专用 Zen Python（2026-10-22）

含助手文件/计算任务的验收批次，会在任何模型生成请求之前，自动准备并验证验收自己的 Zen Python。不会读取、复制或修改正常软件的 Python、聊天记录或 Provider 配置，也不依赖系统 Python。纯 AI 对话验收、纯文字成本实验不因 Python 缺失而被阻塞。

- 首次：复用产品的私有 Python 安装逻辑；可以下载官方运行包，必要时在专用工具目录准备 UV 和依赖。下载不调用模型，不消耗模型 Token。
- 后续：复用 `local/quality-runtimes/` 中按平台、架构、Python/依赖配置区分的缓存；每批仍实际导入全部 10 个依赖，验证 JSON 计算、Excel 保存重读和原件不变，不只看“文件存在”。
- 仅挂载运行时：每个模型/入口的用户数据、测试文件、会话和凭据仍独立。被测产品会再次检查自己是否识别到这套 Python。运行时隔离不是操作系统文件/网络安全沙箱。
- 准备失败：本批记为“环境阻塞”，不发送模型生成请求、不冒充模型失败或验收通过；不会用 Pyodide 顶替，也不偷偷放开 shell 或降低结果校验。
- 同一缓存不允许两批同时使用或修复。异常退出若无法确认子进程已终止，将保留占用文件并给出路径；先确认相关进程已退出，再移除提示的占用文件，不要直接清空缓存或正常软件的数据目录。

只想免费准备/检查环境，可在项目目录运行（不需要 Key、Provider 或模型）：

~~~powershell
pnpm quality:python
~~~

成功后会显示“验收 Zen Python 已就绪”。这不是必须手动增加的步骤：日常继续使用原来的 `pnpm quality:check` 即可自动执行。首次下载可能需要数分钟，等待期间每 15 秒提示进度；后续通常只需运行依赖和读写检查。

环境证据保存在本次报告目录的 `python-environment.json` / `python-environment.log`，包括解释器路径、实际依赖版本、是否复用、计算和文件读写结果；`python-preflight/` 仅包含合成检查文件和独立日志，无测试 Key。

维护者可用以下免费界面回归，验证“缓存挂载 → 产品识别 → OpenCode → 真实 MCP python_execute → 文件合计及原件保护 → 正常退出”的完整链路：

~~~powershell
pnpm quality:ui --tool-managed-python
~~~

模型响应由本地模拟服务提供，Python 工具与文件操作真实执行；这证明验收工具链可用，不代表真实模型已通过文件任务。Windows 本地安装、重复使用及实际工具链已验证；Mac 实机仍需单独验证。

## 4. 文件、历史和记忆验收

quick 通过后按需运行：

~~~powershell
pnpm quality:check release
~~~

仍然输入 Key、Provider 和任意数量模型，然后选择：

- 模块：直接回车默认全选 files、history、memory。也可只输入英文单词，例如 `files`（附件读取、另存与原件保护）、`history`（会话重载）或 `memory`（资料理解、两次更正和回忆）；多选可写 `files,memory` 或 `files memory`，不需要输入中文说明。
- 选择 files 时，文件格式同样直接回车默认全选 json、docx、xlsx、pptx、pdf、png、jpg。只测部分时输入格式名，例如 `xlsx` 或 `json,docx,xlsx,pptx,pdf`；同时验证大附件与损坏文件路径。
- 模块和格式均支持大小写英文、中文/英文逗号或空格分隔，也可输入 `all` 全选；选错会在原地提示重新输入，不必重新输入 Key。输入 `q` 或按 Ctrl+C 取消，不会自动改成全选或启动生成。
- 全选包含 png/jpg，因此仍需额外确认 Provider 的图片按输入 Token 计费，并填写每请求图像 Token 预留。确认计费方式后可填建议值 `8192`；这是预算预留，不是价格、实际用量或人民币费用保证。必须填 1～200000 的整数，留空、填 0、小数或无效内容只会在原地中文提醒并重新输入，不退出、不要求重输 Key，也不会启动模型测试。
- 图片计费不确定时输入 `b` 返回文件格式选择，例如改选 `json,docx,xlsx,pptx,pdf` 暂不测图片；返回后再选图片仍需确认并填写预留，不会悄悄忽略图片测试。输入 `q` 或按 Ctrl+C 取消整批。Key 和模型仍需明确输入，模型列表不会默认全选。

首次完整测试时，输入 Key，API 地址按回车，再选好模型；在“测试模块”和“文件格式”两步各按一次回车。确认图片按 Token 计费后，图片预留填 `8192` 即可继续。`quality:configure` 高级配置向导也使用相同的默认 API、模块/格式选择和图片预留重填规则；其他付费确认与限制不变。

基础对话覆盖所有所选模型。文件读入/另存、历史和记忆等关联用例组固定分配给模型，连续资料与更正不会中途换模型。报告会列出每个模型实际测试的用例，未分配组合不代表通过。

更深入的容量/压缩测试是独立选项：

~~~powershell
pnpm quality:check deep
~~~

deep 还需核实上下文上限、资料字符数、实测输入 Token 门槛和压缩要求，逐模型保持完整会话。未达到容量或真实压缩门槛记为未验证，不能仅凭字符数宣称通过。

### 输入预检与流式失败诊断（2026-10-23）

日常 `quality:check` 和新生成的 `quality:configure` 限量配置，常规输入预检采用 `tokenx` 近似估算 ×2 安全余量，再加每请求图像预留和 4096 协议余量。不会再直接把中文 UTF-8 字节数当成 Token 数，也不会为了通过测试删掉历史消息、附件工具记录或重置记忆会话。默认单请求输入预留仍为 128000，实际用量超限仍失败并停止后续请求；未知用量仍按完整批准额度占用。本方法不是精确 Tokenizer 或硬费用上限保证，建议测试 Key 仍配置服务端额度。

旧 JSON 配置未填写 `execution.inputSizing` 时，继续保留 `utf8-bytes` 保守筛查，不会悄悄放宽原有批准范围。确认费用未知的 `tokens` 批次可显式改成 `estimated-tokens` 后重新预览、批准；金额 `money` 批次不接受该常规近似模式。`deep` 继续采用单独明确确认的近似估算，不叠加常规 ×2，以免挡住真实容量/压缩阈值。预检策略会进入批准摘要及对比指纹，不同策略的报告不能直接当作同条件实验。

当输入预检拦截时，报告会说明预检值/预留值、UTF-8 字节数、近似 Token、安全倍数、图像和协议余量；`calls.json` 的 `rejected[].inputSizing` 保存同样的数字，不保存文本或工具内容。已发送请求的 `calls[].inputSizing` 同样记录数字依据。被拦截代表“工具未发送”，不是模型或软件已经无法记忆。

常规 `release` 文件验收使用近似预检时，隔离 AI 对话实例会采用与批准输入预留匹配的受限测试窗口，避免产品默认 200K 窗口先保留大段资料、再被较小的网关额度拦截。默认输入预留 128000、输出 8192、无图片时测试窗口为 70144 Token；图片预留会进一步扣除。实际值在终端和 `plan.json` 的 `assignments[].contextWindowTokens` 明示。测试仍上传完整的大附件、使用产品自身的整理及本地兜底，不裁剪样本、不改写出站消息、不提高付费额度。该结果只证明受限窗口下的文件处理，不代表真实 200K 容量通过。新版助手、纯记忆、`deep` 容量和 `cost` 对比不套用此测试限制；旧配置的字节预检也保持不变。

当流式失败时，报告会附上响应结构摘要；`calls[].response` 保存固定类别、字节数/分块数、SSE/JSON 事件数、有无正文/工具调用/用量、完成标记和是否正常读到 EOF，不保存原始响应、任意事件名或原始响应头。例如：

- `empty-body`：HTTP 成功但响应体没有内容。
- `empty-output`：收到完成标记，却没有回答正文或工具调用；只有推理文字也不算回答成功。
- `missing-completion`：没有有效完成标记，可能是截断或不完整输出。
- `incompatible-protocol`：请求 SSE 却返回普通 JSON/HTML，或上游直接返回 Gemini、Anthropic、Responses 等原生格式，而不是本批批准的 OpenAI chat/completions 格式。工具只识别、记录，不偷偷改协议或自动发新请求。
- `malformed-json` / `transport-interrupted`：数据损坏/编码异常，或响应未读完就断开、超时、取消；结合原有错误来源、阶段、HTTP 状态和请求编号定位。

正常 OpenAI SSE 允许 `finish_reason` 或 `[DONE]` 作为结束依据，但必须确有正文或工具调用、无错误且读流正常结束；不会仅凭 HTTP 200、`[DONE]` 或后台显示有 Token 就判通过。原生协议/渠道真实问题仍需按新报告核对，补充诊断并不代表旧的 Gemini 失败已经证明修复。

真实大附件复测还发现并修复了 AI 对话的一个整理边界：当本轮用户消息也纳入 checkpoint 时，不能只发送 system 摘要而丢掉 user 消息，否则 Gemini 兼容渠道可能返回 `contents is not specified`。现在会保留有长度约束的最新用户问题；重试已整理的同一问题也不会退化为 system-only 请求，不会为了重试再次附带整份大附件。远端摘要和本地兜底均有对应回归。该修复不修改 OpenCode 的原生循环或压缩。

## 5. 报告与凭据

命令开始和结束都会打印本次报告目录，例如：

~~~text
C:\Users\admin\Documents\project\Zen-AI\local\quality-reports\interactive-时间-编号\
~~~

一般只需把 report.md 发给维护者排查；需要详细证据时提供同目录的 report.json、日志和失败证据文件。目录内主要文件：

- report.md / report.json：实际执行结果。
- plan.json：本批预检计划与模型分配，不含 API Key。
- build.log：自动构建日志。
- setup-error.txt：构建、选模或预检阶段出错时的原因；此时可能尚未生成 report.md。
- target-编号-入口/：调用记录、截图、文件等具体证据。

API Key 只在本次命令的进程中临时使用，不写配置、报告、终端历史或应用设置，也不传给被测应用。完成、出错或取消后清理本次引用；进程结束后不留给父 PowerShell。Provider 地址是连接地址，本身不是密钥，但不要在 URL 中附带 Key。

如果以前手工设置过父 PowerShell 的 ZEN_QUALITY_SELECTED_KEY，它不属于新命令创建的凭据，子进程无法清除父进程变量；可在原窗口执行一次：

~~~powershell
Remove-Item Env:ZEN_QUALITY_SELECTED_KEY -ErrorAction SilentlyContinue
Remove-Variable qualitySecret -ErrorAction SilentlyContinue
~~~

以后使用 quality:check 不需要以上设置或清理步骤。

## 7. 随功能演进调整验收

工具可以继续扩展，但新功能的正确行为需要明确写入用例。增加逻辑时同步完成：

1. 明确输入、操作、预期结果，以及失败和取消时应怎样处理。
2. 为逻辑补单元/集成回归；需要真实交互时在 scripts/quality/matrix.ts 或 scenarios.ts 加用例。
3. 在 tests/quality/manifest.json 登记检查组和源码路径影响规则，让 quality:changed 选中它们；未知路径仍扩大检查。
4. 用本地模拟接口先验证执行器、判定器和报告，再按需运行真实模型验收。
5. 报告必须区分通过、失败、未测、环境阻塞与待人工确认，避免新增功能被旧用例“顺带算通过”。

自动验收覆盖的是已登记的断言，不能保证所有基础功能和未来逻辑都没有问题。安装/升级、Mac 实机、真实登录及 Office 视觉版式等仍按需验证。
