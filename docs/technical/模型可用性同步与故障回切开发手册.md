# 模型可用性同步与故障回切开发手册

日期：2026-10-16。范围：Zen API、Zen AI；不改变 OpenCode 原生任务循环和上下文压缩。

## 已确认规则

1. 远端策略管理长期默认模型及有序文字备用列表；渠道实时状态决定能否调用。
2. 模型列表与实际路由采用相同的有效渠道判断，包含用户/密钥分组、密钥限制、渠道状态、路由成员状态；任一有效渠道存在即保留，全部不可用即隐藏。
3. 高优先级失效仍尝试有效低优先级；启用的模型路由不能从已禁用成员绕回普通渠道池。
4. 独立同步策略版本、可用状态；实时变更通知触发完整刷新，五分钟轮询、联网/唤醒重连补同步兜底。失败响应不是有效空列表。
5. 故障按预配置顺序选择有效备用，不擅自选择其他 Provider、其他 Key 或未配置高价模型；名单耗尽则留空并保留用户输入和历史。
6. 保留原始选择意图与当前实际模型。系统临时替换不能丢失用户偏好；恢复后安全回切。用户主动另选模型则取消旧的回切意图。
7. 默认跟随后台推荐；用户明确选择的正常模型不覆盖。用户选 D、D 故障临时用 B，D 恢复后回 D，不回默认 A。
8. 每次选择从意图模型/优先模型重新开始，随后顺序备用；B 失效时 A 已恢复应选 A，不机械跳 C。恢复回切需稳定观察，反复波动退避。
9. 运行中任务参数固定，不中途换模型、不重发失败任务、不打断输出。空闲设置及下一轮/下一任务使用新选择。
10. 覆盖对话、快速、翻译、命名、新助手、微信及定时任务；旧助手只读历史不改写。只修复受影响的位置。
11. 仅对受管 Zen API Provider 生效，不影响第三方同名模型；开发者可绕过助手放行名单，但不能绕过有效渠道。
12. 图片、音视频、向量模型不进入文字备用链；AI 对话整理模型保留三模型/本地 checkpoint 独立兜底，新助手保留原生压缩。
13. API 成功返回完整空列表方可判定不可用；断网、401、余额/个人限流、解析失败不作全局模型禁用判断。
14. 自动禁用/恢复沿用现有故障分类、阈值和探活；手动禁用不自动恢复。通知不暴露渠道凭据和内部路由。

## 实现与配置

### 默认值与备用列表

继续使用现有远端策略，不新增一套配置后台或数据库迁移。原“备用模型顺序”字段 `assistant.fallbackModels` 作为通用文字备用列表，按管理员填写的先后顺序使用。已同步修改面板中英文说明。

示例：默认对话模型 A、快速模型 D、翻译模型 A，备用列表 B、C、A。每个位置保留自己的意图：A 不可用时尝试 B、C；D 不可用也尝试 B、C，但 D 恢复后仍回 D。重复名称会去重；不把列表外的模型当兜底。

备用模型仍需满足当前 Key 权限、分组、真实渠道状态以及对应功能的放行策略。不能因为在备用列表里就绕过权限。图片、音视频、向量用途根据已有用途元数据及名称规则排除；自定义别名无法可靠反推出模型用途，管理员应只填写文字模型。

用户主动选定的模型成为该位置的新意图，包括主动选中当前临时 B。后台发布新版本策略时仍沿用原有“覆盖用户选择”等开关；同版本健康刷新不反复覆盖默认值。

### 同步与回切时机

- `GET /api/client/models`：使用当前 Provider 的 Key 获取完整、鉴权后的实时可用模型快照；只有成功且带权威标记的完整响应可替换模型列表，`[]` 是有效空列表。
- `GET /api/client/model-events`：无凭据、无模型明细的 SSE 变更信号。服务端共享两秒修订检查，客户端收到信号后合并 250 毫秒内的连续通知，再刷新策略和完整快照。
- 启动、Provider 凭据变更、网络恢复、窗口重新可见时刷新；正常每五分钟补查。SSE 断线采用一分钟起、最长五分钟的重连退避。
- API 自动恢复采用双层观察：渠道首次探活成功后仍保持自动禁用，随后每隔 1 分钟复测，至少覆盖完整 3 分钟（首次成功 + 后续 3 次成功）才启用；任意失败重新计时。手动停用、删除或修改渠道不能被旧探活结果恢复。
- A 经 API 恢复可用后重新显示在可选列表；当前 B 仍正常，则再观察 A 持续可用至少 5 分钟，在空闲边界回切。客户端每 15 秒检查一次回切，因此不是精确到第 5 分钟。正常无抖动时，从 API 首次探活成功到回切至少约 8 分钟，另加探测耗时、同步与等待空闲的时间。
- 恢复反复波动时观察时间翻倍，最长 15 分钟。若 B 也失效而 A 已可用，立即优先选择 A，不继续死等稳定期或机械跳到 C。
- “稳定”指后台允许使用的状态持续稳定，不代表客户端又发了付费探测。API 复用原有真实模型测试：常规定时探活发现第一次成功后，单独按一分钟节奏复测观察中的渠道，不等待原来可能为十分钟的常规间隔。请求不重叠；过长调度间断、重启及更换 Key/测试模型/地址后重新观察，不能累计过期成功。慢响应本身与调度中断分别判断。
- 自动探活和自动恢复全局开关、渠道级探活开关继续有效；图片渠道未明确开启时不自动进行付费测试。管理员手动启用仍是明确人工覆盖，不必等待自动观察。API 观察只保存在内存，重启后重新验活，不延用旧的绿色状态。

推送是低延迟失效通知，不保证网络异常时零延迟。无论推送是否连通，五分钟轮询仍保留。断网、鉴权失败、错误 HTML、协议解析失败不会被解释为“全部模型不可用”。

### 任务与历史保护

正在运行的模型输出、工具操作不因同步而中断；已开始的请求不会被重新提交。新任务、后续一轮使用实际可用模型。某次请求刚好撞上故障时，仍可能收到原始失败；这不意味着所有其他用户都必然免于同一时间窗口内的失败。

所有备选都不可用时，实际选择留空，保留输入、原偏好和历史，阻止无效新请求；不会改用其他 Provider，也不会改用未配置的贵模型。快速/翻译/命名等新请求在全局设置因其他运行任务暂缓更新时，也单独检查可用候选。

故障期间新建的 AI 对话及新助手会话继承原始默认偏好，新助手的规划/小模型也保留各自偏好。历史消息、历史模型标签、文件、OpenCode 原生会话与压缩机制不改写。旧助手仍只读。

客户端多个 Key 时使用可用模型交集，避免轮换到另一个 Key 后权限失败；不为实现兜底偷偷换 Key。第三方 Provider 不参与本机制。恢复意图独立保存在本地元数据中，不改变现有 Redux/Dexie 数据结构。

## 部署顺序与人工验收

先部署 Zen API，再使用包含本改动的 Zen AI。旧客户端不会凭空获得实时回切能力；新客户端连接旧 API 时不会把 404 当成空列表。本文不表示代码已经部署到服务器。

反向代理需允许 `/api/client/model-events` 流式响应，不缓存、不缓冲，并放行 CORS。通知流不应放到需要网页登录的路径。若代理不支持 SSE，轮询仍可工作，但更新不会同样及时。

请在测试环境及专用 Key 上操作，避免停掉生产中所有用户正在使用的渠道。将 A、B、C 替换为实际不同的文字模型，后台默认设 A，备用顺序设 B、C。

| 操作 | 预期 |
| --- | --- |
| A 有两个有效渠道，只停一个 | A 保留，继续走剩余有效渠道 |
| 禁用 A 全部渠道，包括路由成员自动禁用/渠道手动停用 | A 从列表消失，空闲默认及受影响会话改 B |
| 同模型优先级 10 不可用、9 仍正常 | 模型保留且实际走 9，不误判整个模型不可用或逃逸路由 |
| B 也全部停用 | 继续选择有效 C；不选其他 Provider 的同名 B |
| A 首次探活成功，B 正常 | API 仍禁用该渠道；每分钟复测，观察满 3 分钟后才重新可见 |
| A 通过 API 观察，B 正常 | 客户端再稳定观察至少 5 分钟，空闲位置回 A |
| A 恢复时 B 也故障 | 下一次选择直接尝试 A，不机械改 C |
| A 恢复又很快故障 | 再用备用，并延长下次观察时间，避免反复跳动 |
| 用户临时 B 时手动选 D，或明确选 B | 新选择成为偏好；A 恢复不覆盖它 |
| 所有默认和备用都停用 | 空选择、可查看历史/保留草稿；不会偷偷用高价或第三方模型 |
| 正在输出/执行工具时停用该模型 | 当前任务不强行中断或重发；空闲后修复，下一轮用备用 |
| 故障期间新建两个入口的对话，再恢复 A | 新会话也能随原默认恢复，不把 B 永久固化 |
| 故障期间发布新默认 C | 按原覆盖策略接受新默认，不再受旧 A 的回切记录绑住 |
| 断网/401/代理返回错误页面，然后恢复网络 | 不清空原模型；恢复后重新同步完整快照 |
| 重启、电脑睡眠唤醒、隐藏窗口后返回 | 重新同步并继续回切；不丢原偏好 |
| 开发者模式及另一个 Provider 同名模型 | 开发者不能使用无有效渠道的模型；第三方不被本机制修改 |
| 微信提问、桌面续聊、定时任务 | 同一新助手入口使用实际可用模型，任务只执行一次、用量记录实际模型 |

测试提示词可使用“你好，只回复测试成功”“把刚才的话改成更口语化的两句话”；验证运行中任务时可发“请写一篇较长的中文故事，不需要创建文件”。无需为了本功能额外生成附件。

## 必测场景

- 部分禁用、全部禁用、低优先级可用、路由成员禁用、不同分组和密钥权限、多 Key 部分失效。
- 默认与备用同名/重复、备用连续失效、所有候选失效、A 恢复且 B 失效、用户选择取消回切。
- 正常输出/工具运行不受影响；故障更新不自动重发；历史模型记录保持原样。
- 网络失败不清空、有效空快照清空、旧快照乱序、冷启动/重启/唤醒/断线恢复、连续通知合并。
- 多 Provider 同名隔离、开发者权限、备用用途分类、默认配置版本不被健康刷新反复应用。
- 手动禁用不会被恢复机制打开；故障恢复抖动退避；客户端不额外发付费探测。
- API 首次成功不恢复、快速连点不缩短三分钟、失败重计、调度中断/重启/配置变化作废、多 Key 只恢复已验证的自动禁用 Key、诊断写入不能覆盖手动状态。客户端旧版短观察元数据也执行新的五分钟下限。
