# 临时 20 轮缓存与成本对比

此实验按需运行，不属于日常自动验收。复用隔离界面与调用统计设施，但使用独立命令、题库与报告。默认每个所选模型在 chat 和 assistant 各连续执行同一份 20 轮题库，入口之间使用独立会话。

## 运行

~~~powershell
pnpm quality:experiment --prompts "docs/experiments/cache-20-turns.txt"
~~~

随后依次输入隐藏的 API Key、Provider 地址和任意数量模型序号，自动构建、预检并开始测试。完成、失败或取消时清理本次凭据并打印报告目录。只测助手时：

~~~powershell
pnpm quality:experiment --prompts "docs/experiments/cache-20-turns.txt" --entries assistant
~~~

题库是 UTF-8 文本，可复制示例自行编辑。每轮标题“第1轮”到“第20轮”独占一行，后面写该轮完整用户提示词，顺序不得缺失、重复或为空。整段内容会发给模型，不要在文本里写 Key、参考答案或不希望发送的附注。原有“### 第N轮 + text代码块”的 Markdown 题库也兼容，并只读取提示词代码块。

每轮动作由文本决定，连续对话保留历史；同一会话不会切换模型来掩盖失败。可重试故障等待产品原生重试，每次尝试均计入预算与成本记录。最终失败时停止该模型、入口的会话，余下轮次保留为未执行，再继续计划中其他模型和入口；全局预算、取消或超时仍会终止整批。没有单独断言的开放式回答只表示执行完成，其语义效果仍需复核。

## 前后两批比较

在两个待比较版本分别运行同一命令，选择相同模型、入口、限制和节奏；保持题库内容一致。记下两次打印的目录：

~~~powershell
pnpm quality:compare "第一次报告目录" "第二次报告目录"
~~~

比较会核对题库、型号、入口、价格/预算模式、输入输出边界与节奏。条件不一致、失败、不完整或缺用量时，不能给出可靠的节省结论。相同条件下的观测也不代表已经固定上游渠道或证明版本因果。

无报价模式只统计输入、输出、缓存和请求等观测，费用保持“未核算”。要比较实际金额，可由维护者基于核实的测试 Key 报价配置 money 模式，或者导出服务端账单，用请求 ID 对账；不能把 Token 下降直接当成金额下降。

## 可选限量参数

需要扩大或缩小实验规模时可在同一条命令后增加参数，不需要手动保存配置：

~~~powershell
pnpm quality:experiment --prompts "docs/experiments/cache-20-turns.txt" --max-requests 160 --max-input-tokens 10000000 --max-output-tokens 160000 --input-reserve 128000 --pause-ms 20000
~~~

这些是数量/Token/节奏限制，不是人民币金额保证。达到上限会停止，未执行轮次保留；辅助命名、压缩和工具循环同样计入。默认间隔 20 秒，也不会强制制造缓存命中。
