# AI 对话实时搜索方案

## 目标

让用户无需理解搜索提供商或手动判断信息是否过期。AI 对话默认采用“自动搜索”：普通知识问题直接回答，天气、新闻、价格、赛程、政策、人物职位等实时问题自动联网，并在回答中展示来源和查询时间。

## 产品入口

输入框保留搜索按钮，点击后提供三种模式：

- 自动：默认值。检测到实时或需要核验的信息时联网。
- 开启：本轮强制联网，适合研究、对比和查证。
- 关闭：本轮禁止联网，适合隐私内容或纯离线讨论。

界面只呈现这三种意图，不要求普通用户选择 Tavily、Exa、Bing 或模型原生搜索。具体通道放在高级设置中。

## 执行架构

### 1. 实时意图路由

在调用主模型前做低成本判断。以下问题默认强制搜索：

- 天气、空气质量、灾害预警
- 新闻、近期事件、人物当前职位
- 股票、汇率、商品和产品价格
- 体育比分、赛程、交通和营业时间
- 法律、政策、软件版本和产品规格
- 用户明确要求“搜索、查一下、最新、今天、目前、核实”

路由以本地规则为第一层，轻量模型判断为补充层。规则命中时不能被模型的“不需要搜索”结论覆盖。

### 2. 通道选择

按可靠性动态选择，不按模型品牌硬编码：

1. 已验证可用的模型原生搜索。
2. 用户配置的搜索 API，如 Tavily、Exa、Bocha、智谱或 SearXNG。
3. 无密钥搜索通道，作为基础回退。
4. 所有通道失败时明确提示搜索失败，不让模型把旧知识伪装成实时结果。

每个 Provider 记录搜索能力探测结果。OpenAI-compatible 地址不能仅因模型名像 GPT 就假定支持原生搜索。

### 3. 结构化实时工具

天气优先接入结构化天气工具，而不是只抓搜索摘要。后续按价值补充汇率、金融行情、体育赛程等专用工具。结构化工具失败后再回退到通用网页搜索。

### 4. 证据与回答

- 搜索结果先去重、排序并过滤低质量页面。
- 实时回答必须携带来源、查询时间和必要的地区/时区信息。
- 关键结论尽量由两个独立来源交叉验证。
- 搜索摘要与模型常识冲突时，以新鲜、可追溯的来源为准，并说明不确定性。

## 体验状态

对话状态依次显示“判断是否需要搜索”“正在搜索”“正在整理来源”。完成后展示引用数量。发生回退时不弹重复错误卡片，只在最终状态中说明使用了备用通道或搜索失败。

## 实施顺序

### P0：自动搜索闭环

- 新增自动/开启/关闭三态，默认自动。
- 增加本地实时意图规则，天气等问题强制进入搜索。
- 统一原生搜索和外部搜索的能力判断与回退。
- 回答展示来源和查询时间。
- 搜索失败时禁止无来源地编造实时答案。

### P1：质量和稳定性

- 增加 Provider 搜索能力探测与缓存。
- 搜索查询改写、并行检索、结果去重和质量排序。
- 增加短时缓存，降低重复天气和新闻查询的延迟与费用。
- 完善搜索过程状态和诊断信息。

### P2：垂直实时工具

- 天气与预警。
- 汇率、股票和商品行情。
- 体育赛程与比分。
- 地点营业时间和交通信息。

## 首轮验收

1. “上海今天会下雨吗？”不点搜索按钮也会自动查询，并标明时间与来源。
2. “最近一周 OpenAI 有什么新发布？”自动搜索并按事件发生时间整理。
3. “解释牛顿第二定律”不触发联网。
4. 强制开启搜索后，普通问题也会检索并给出引用。
5. 关闭搜索后，不发出任何联网搜索请求。
6. 模型原生搜索不可用时自动切换外部通道，不直接让整轮对话失败。
7. 所有搜索通道失败时，明确说明无法确认实时信息，不输出伪实时答案。
