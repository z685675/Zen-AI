# 智能助手生成文件全局质量设计

> 状态：已实现，作为 PPT、Word、Excel、PDF 与 Markdown 的持续质量基线
> 更新日期：2026-08-11
> 文档导航：[Zen AI 开发文档索引](./README.md)

## 1. 目标

智能助手无法预知用户会生成经营报告、科研材料、投融资演示、课程讲义、知识库还是技术文档。因此，质量规则不能绑定某个文件名、行业主题或示例数据，而应绑定：

1. 文件格式的不变量。
2. 内容意图，例如趋势、对比、说明、决策或引用。
3. 可观察的最终交付结果。
4. 所有生成方式共同经过的交付边界。

## 2. 已出现问题

### 2.1 PPTX

- OOXML 关系、notes 部件、主题复用、Shape ID 或负尺寸异常导致 PowerPoint 要求修复。
- 文本容量与版式不匹配，出现文本框溢出、遮挡、错位或异常小字号。
- 连续修改使用临时脚本，破坏原有 Shape 边界或主题关系。
- 页面只有标题和项目符号，缺少真正的结构、对比、流程、图表和视觉证据。
- 多种视觉风格共用同一套“标题加等宽方框”骨架，只替换主题色，造成不同模型、主题和文档类型看起来仍像同一份模板。
- `visual` 字段目前主要表达设计方向，并不等于已经嵌入真实图片。
- 把“参考截图”和“原生 PPTX 模板”混为一谈会造成错误承诺：截图只能近似恢复视觉语言；只有 `pptx_template` 才复用 PPTX 原始母版、版式、占位符和媒体。
- 新主题与来源模板结构差异较大时，机械复用来源页会造成信息过少、语义错位或为了填槽而保留旧内容；系统需要在原生复用与自适应设计之间自动分流。

### 2.2 DOCX

- Markdown 作者格式直接显示为 `#`、`**`、代码围栏或表格分隔线。
- 正文被重复追加为单列表格，标题出现两次。
- 动态目录或字段在打开时触发更新、外部链接或安全警告。
- 自定义修改破坏字段缓存、关系或 Word 原生结构。
- 当前稳定 Markdown-to-DOCX 路径不具备完整图片资产输入契约，不能把图片占位文字当作已嵌入图片。

### 2.3 PDF

- 中文字体缺字、乱码或无法选择搜索。
- 表格跨页截断、空白页、页脚占用正文或长文本越界。
- 显式文档标题与相同的首个 H1 重复绘制。
- 不支持的 Markdown 块被当成普通正文，代码围栏或强调符号泄漏到页面。
- 扫描 PDF 的 OCR 可以恢复阅读顺序，但纯文本输出不能等同于版面复刻。

### 2.4 Markdown

- 过去只有写文件能力，没有专属交付校验。
- 代码围栏未闭合、标题层级跳跃、表格列数不一致或本地链接失效时仍可能报告完成。
- Markdown 是最终交付格式时应保留语法；转换为 Word/PDF/PPT 时则必须转换成目标格式原生结构。

### 2.5 OCR 文本

- 同时加载简体、繁体和英文模型会让简体原文混入繁体字；默认应只启用简体中文和英文，繁体按需显式开启。
- 单一系统 OCR 在中英混排、浅色小字或复杂背景上可能漏字、粘连英文单词或丢失段落，因此中英混排需要双引擎比较，弱结果才追加高对比度识别。
- 图片预处理不能无条件强锐化或二值化，否则细小中文笔画会被抹掉；默认使用方向校正、透明背景展平、小图放大和温和增强。
- TXT/Markdown 只交付阅读顺序、换行、段落和页边界，不冒充坐标级版面复刻；多栏、表格和精确位置恢复属于后续结构化能力。
- OCR 必须返回逐页质量信息。低可信结果可以交付供人工核对，但不能静默标为完全成功。

## 3. 五层质量架构

### 3.1 内容模型

- 先确定文档类型、受众、目标和结构，再选择输出格式。
- 用语义字段表达标题、段落、列表、表格、图表、备注和资产，而不是让生成器猜测长字符串。
- 展示标签与源数据键分离；作者格式与最终格式分离。

### 3.2 稳定生成器

- 普通 Office/PDF/Markdown 输出优先走 `mcp__assistant__create_file`。
- Node 生成器负责确定性包结构，Python 负责分析、检查和确有必要的高级处理。
- 自定义生成器不能绕过相同的最终校验。

### 3.3 底层交付校验

`create_file` 在写入用户目录前统一检查：

- 非空缓冲区和 UTF-8 文本安全。
- Markdown 围栏、基础表格和危险链接。
- OOXML 必需部件、XML、内容类型和关系目标。
- PPT 页数、Shape ID 和负尺寸基线。
- PDF 头、EOF、可解析性和页数。

工具结果中的 `verified` 只有在这些检查通过后才为真，并返回具体 `checks`、`warnings` 和 `details`。

### 3.4 格式深度校验

- PPTX：主题、母版、版式、关系、文本框策略、显式字号、空页、占位文案和外部关系。
- DOCX：字段、目录缓存、打开时更新、Markdown 泄漏、重复源稿、空正文和标题次数。
- XLSX：公式、缓存、图表数据、循环引用、外部链接和视觉密度。
- PDF：字体、文本提取、空白页、危险动作、标题次数和 Markdown 泄漏。
- Markdown：编码、标题层级、代码围栏、表格和本地链接。

### 3.5 渲染验收

包结构正确不代表视觉正确。高风险、自定义生成或连续修改的 PPT/PDF/Word 仍需渲染检查：

- 是否裁切、重叠、错位或出现空白页。
- 字号、留白、对齐和分页是否可读。
- 图片、图表和字体是否真实显示。
- 默认缩放与常用桌面软件打开结果是否一致。

## 4. 当前完成度

已完成：

- `create_file` 统一底层交付校验。
- PPTX、DOCX、XLSX、PDF 的格式专属校验。
- Markdown 内置 Skill 与严格校验器。
- PDF 标题去重及有序列表、引用、代码块转换。
- PPT 外部关系、空页、替换字符和 Markdown 泄漏检查。
- Word 空正文、原生标题结构、替换字符和标题次数检查。
- PPT、Word 和 PDF 共用受控本地图片资产契约；图片统一校正方向并转换为 PNG，再以内部媒体部件嵌入。
- 图片引用、未使用资产、媒体部件数量、内部关系和 PPT 图片 Shape 均进入统一交付校验。
- PDF 默认执行真实页面截图与像素检查，拦截空白页并提示靠近页面边缘的可疑内容。
- PPT/Word 支持分层渲染：优先无界面 LibreOffice；严格模式下 Windows 可调用本机 PowerPoint/Word 导出 PDF。无法渲染时明确返回 `unavailable`，不伪装成通过。
- PPTX、DOCX、PDF 共用 29 种文档级视觉风格与自动推断规则；可按 `document_type`、标题和内容自动选择，也支持显式风格、明暗/打印模式及品牌色覆盖。
- PPT 模板和 deck-spec 校验器不再自动为每页轮换孤立强调色；默认由文档级风格生成协调色阶，避免所有模型输出相似的蓝灰商务模板。
- PPTX 有界文本框不再使用会隐藏末尾字符的省略号溢出策略；生成器写入明确的自动缩放比例，模板文字替换会清理该属性，严格校验会阻止带省略号截断风险的成品交付。
- PPT 风格进一步拆分为独立布局语言，封面几何、页面导轨、主次关系、留白、形状和阅读路径随风格变化；默认企业风也采用叙事型主次分栏和开放式结构，不再以等宽方框作为万能容器。
- PPT 的论证结构与视觉风格独立解析：系统内部从简报、金字塔、叙事、教学、展示结构中自动选择故事组织方式，再用视觉语言表达；普通用户无需知道结构名、风格 ID 或 Skill 名称。
- PPT 的 14 类布局语言均深化到流程、时间线、图表和图片页：企业叙事、高管决策、咨询排版、正式报告、技术、产品、数据、强视觉、品牌、编辑、活泼、人文自然、高端和极简不再共用同一几何骨架。
- PPT 在视觉语言之上新增结构型、空间型和动势型三类构图画像。系统结合文档类型、场合、受众、内容密度和情绪自动选择，同一编辑、品牌、活泼、人文自然或极简语言可按年度报告、空间作品集、发布会/艺术节等不同语境改变封面、章节页、洞察页、图片页和通用页面导轨，而不是只换颜色。
- PPT 新增关系网络、四象限矩阵、分时日程和旅程/空间路线四类语义版式，并在工具协议、自动识别、Skill 规划、deck-spec 校验和 OOXML 渲染之间使用统一内容契约，复杂信息不再被迫退化为卡片或流程页。
- 品牌、文化、展示、活动、场所、作品集和产品发布类演示新增视觉资产规划要求：有可靠素材时通过 `assets` 与 `image_asset_id` 嵌入多张主题相关图片；无可靠素材时保留可用的排版回退，不用 `visual` 描述冒充真实媒体，也不因缺少图片直接阻断基础生成。
- 图片页按布局语言选择画幅、裁切/完整显示策略、图层顺序、说明区和阅读路径；真实图片参与 Shape ID、元素边界和渲染校验。
- PPTX 支持参考 PPTX 或页面截图生成新演示：参考 PPTX 可提取页面比例、主题字体、主辅色、明暗模式、图片页比例/覆盖率、图表节奏、文字密度、版式多样性和最接近的布局语言；截图除原始尺寸、角落背景和调色板外，还分析有效内容占比、视觉重心、边缘密度、纹理、摄影覆盖、构图偏向、留白节奏和表面处理。
- 使用参考 PPTX 时由参考稿主导布局语言，模型根据新主题猜测的 `visual_style` 不再覆盖参考方向；图像密集参考稿必须准备新主题相关图片，不能复用无关照片或用 `visual` 文本冒充真实媒体。
- 参考生成结果会返回参考类型、代表页、布局置信度和页面比例兼容性。PPTX 参考返回 `pptx-reference-composition` 构图相似度；截图参考返回 `pptx-reference-design-language` 设计语言相似度，避免成品只像颜色、不像构图。代表页只强调配色与字体，整套 PPT 的图片/报告页节奏和明暗比例始终按全稿分析，避免深色封面污染全部页面。
- 参考 PPTX 被解析为全幅摄影页、摄影章节页、图文页、图表报告页、密集报告页和开放报告页等页面原型，并按原稿节奏驱动输出。相似度低于 70、图片比例严重下降、版式多样性塌缩、明暗节奏错误或图片素材多样性不足均直接阻断交付。
- 参考/模板画像新增可执行的设计语言：配色策略、对比度、字体尺度、对齐倾向、形状语言、信息密度、图片处理、构图偏向、空间节奏、装饰密度、表面处理和页面节奏。画像同时返回目标文字密度、版式多样性、图片/图表/明暗比例，不再只给模型主辅色和页面类型。
- `pptx_template` 新增 `adaptive-design`：当新故事的多类核心页面不适合来源模板几何时，自动改用提取出的设计语言驱动 14 类内容适配版式；来源保持只读，结果明确报告 `exact_package_reuse: false`，并继续通过参考构图相似度闸门。
- 新增原生 PPTX 模板引擎：`edit-copy` 在完整副本中修改指定页面并保持未修改页字节不变；`new-deck` 从来源页面重组新演示，保留原始母版、版式、主题、媒体、图表和关系。
- 原生模板文本优先映射标准标题、副标题和正文占位符，也支持按 Shape 名称/原文字精确替换及保守几何回退；改写保持原形状边界、样式和有界缩放。为页面指定 `image_asset_id` 时可替换该来源页面积最大的图片，同时保留图片 Shape 的裁切、坐标和尺寸。
- 原生模板生成新增规划前检查：助手先读取每页的封面/章节/列表/网格/分栏/指标/图表类型、可容纳条目数和图片要求，再从新主题重新构建故事线并映射页面。模板负责视觉语法，不再把来源内容当成固定槽位逐页照搬。
- 模板预检新增每页来源正文密度与安全目标区间。高密度来源页如果只填入少量短句，会在写文件前阻断并要求助手内部补足证据、解读和行动，或改用更稀疏版式；不把修改提示词的责任转给用户。
- 重复内容区按语义和空间结构联合映射，通用 `TextBox` 不再误抢首条内容；年份标题不会被当作指标拆分，模板语义图标会中性化，原图表固定坐标轴会自动解除。内容超出容量时优先重映射，其次自动续页，不静默截断。
- 原生模板输出使用兼容 Office 的 ZIP 重打包并清理 Notes 关系，必须可由 PowerPoint 直接打开；需要“打开并修复”的文件视为校验失败。
- `preserve_content` 可将指定 PPTX 来源页不改写地复制到新演示，用于视觉保持型页面克隆；来源文件始终只读，输出必须使用新路径。
- 增加 14 类跨风格构图回归测试：同一组核心页型逐类校验流程、时间线、图表和图片页的专属构图标记、真实媒体、Shape ID 唯一性及全部元素边界。
- deck-spec 严格校验新增信息不足、版式类型数、构图家族数、单一版式占比和连续构图重复检查；长演示不能仅通过换色重复同一组方框。
- Office/PDF 渲染检查新增全稿中位像素密度、内容有效区域和底部留白异常值，能提示非首尾页异常稀疏或垂直失衡；章节页可保留有意留白。
- 模板引擎覆盖重复复用同一来源页、多母版/多版式、标准 PowerPoint 占位符、主图片替换和未授权路径；多图片指定替换、SmartArt/动画编辑和截图转可编辑对象仍会明确拒绝或保留为后续能力，不伪报成功。
- DOCX 保持明亮可编辑，通过原生标题、引用、代码和表格表达风格；PDF 通过固定版页面导轨、标题标记、面板和表格表达更强视觉差异。

下一阶段：

1. 让 Python、第三方库和自定义 OOXML 生成的文件自动进入同一交付闸门，而不是只依赖 Skill 主动调用。
2. 建立跨格式的生成清单：源内容、生成器、校验报告、渲染结果和最终文件一一对应。
3. 在不引入误判的前提下继续增强 PPT/Word 渲染图的文字重叠、裁切和最小字号检测。
4. 支持同一输出包内混合原生来源页与全新生成页，并扩展图片占位符、SmartArt 和动画对象编辑；截图仍不冒充可编辑对象克隆。

## 5. 交付原则

- 不以“文件存在”代替“文件可用”。
- 不以“Office 可以修复”代替“生成正确”。
- 不以“模型说已完成”代替校验结果。
- 不用某个行业示例推导所有用户数据的业务含义。
- 未经过真实媒体嵌入时，不声称已经加入图片。
- 无法自动判断的视觉结果应明确标为待人工或渲染验收，而不是静默通过。
