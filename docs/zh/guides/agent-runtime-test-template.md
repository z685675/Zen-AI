# Zen AI 当前版本发布验收手册

> 更新日期：2026-07-30
> 适用范围：AI 对话、统一上下文、Auto Runtime、多协议模型、工作区与会话、内置 Skill、文件生成、图片嵌入、渲染验证、托管 Python、本地 OCR
> 测试原则：只验收当前已经完成的功能；每项按顺序执行，失败时停止并记录。

## 1. 测试前准备

### 1.1 启动开发版

在 PowerShell 中执行：

```powershell
cd C:\Users\admin\Documents\project\Zen-AI
corepack pnpm dev
```

开发版使用独立数据目录，不显示正式版历史数据属于正常现象。

### 1.2 准备空工作区

1. 结束正在运行的智能助手任务。
2. 清空 `C:\Users\admin\Documents\zenai-test2`。
3. 在智能助手设置中把该目录添加并设为“当前工作区”。
4. 另建 `C:\Users\admin\Documents\zenai-test-switch`，用于工作区切换测试。

首次执行任务后自动出现 `.claude`、`.agents` 等隐藏目录是正常的，它们用于内置 Skill。普通文件任务不应在工作区根目录生成 `node_modules`、散落的 `.js/.json` 脚本或多份无用草稿。

### 1.3 测试模型

- 模型 A：`gpt-5.6-luna`，存在时应为官方助手默认模型。
- 模型 B：任选一个当前可用的 Claude 系列模型；Provider 类型可以是 OpenAI。
- 模型 C：任选一个当前可用的 Grok 系列模型；官方 xAI Provider 或 OpenAI-compatible 面板均可。
- 模型 D：任选一个当前可用的 Gemini 系列模型；原生 Gemini Provider 或 OpenAI-compatible 面板均可。
- 全程不手动选择 Claude Code 或 Codex，用户界面只使用 Auto。
- 除明确要求“继续修改”的项目外，每个编号新建一个对话。
- 除 T08 的 Skill 诊断外，所有任务都只描述用户目标，不在提示词中指定 Skill 名称，用于验收自动识别与编排。

每项只记录：`通过 / 失败 / 跳过`，失败时补充截图、文件名和诊断包编号。

## 2. 设置与工作区

### T01 空工作区启动

操作：启动开发版，打开官方智能助手和模型下拉框。

通过标准：

- 智能助手可以打开，模型下拉不为空。
- 设置页可以正常进入，不因工作区为空或被删除而失效。
- 普通设置中没有 Claude Code/Codex 手动切换项。
- 如果本地存在 `gpt-5.6-luna`，官方助手和新对话默认选择它。
- 智能助手设置中的模型标记为“新对话默认模型”，不会覆盖已有对话。
- 未配置模型时显示明确的配置提示页，而不是空白、卡死或崩溃。

### T02 多工作区切换

操作：

1. 在可访问目录中同时保留 `zenai-test2` 和 `zenai-test-switch`。
2. 只点击一次，把 `zenai-test-switch` 设为当前工作区；等待按钮完成，不再来回切换。
3. 立即关闭设置并在当前会话发送：

```text
请在当前工作区创建 workspace-switch-check.txt，内容只写当前工作区的绝对路径。完成后告诉我文件的绝对路径。
```

4. 确认文件位置后，只点击一次切回 `zenai-test2`，再发送同样的提示词。

通过标准：

- 当前工作区标识在服务端更新完成后立即变化，更新期间按钮显示处理中且不能重复点击。
- 第一次文件只写入 `zenai-test-switch`，第二次只写入 `zenai-test2`；不需要额外来回切换或先发送一条消息激活。
- 切换工作区不会清空模型列表、模型选择或 Agent 设置。
- 后续文件只写入当前工作区，除非提示词明确指定其他授权目录。
- 继承助手默认工作区的会话同步切换；曾经在会话设置中单独定制过目录顺序的会话保持自己的设置。

## 3. Auto、会话与状态

### T03 模型 A 普通对话

新建对话，在首页“本次对话模型”下拉中选择模型 A，然后发送：

```text
请用三点说明：一份真正可交付的商业演示文稿，和“标题加项目符号”的普通幻灯片有什么区别。每点不超过 50 字。
```

通过标准：

- 回复完整且只收口一次；任务结束后“正在处理”及时消失，不再追加一段迟到回复。
- 任务完成后，会话列表自动生成简洁、可辨识的话题名，不继续显示“未命名”。

### T04 会话模型隔离与 Provider 兼容

保留 T03 的模型 A 对话，新建另一个对话，在首页“本次对话模型”下拉中选择模型 B，然后发送：

```text
在当前工作区创建 model-b-check.md，内容为：
# Model B OK
- mode: auto
- workspace: zenai-test2
完成后读取文件并原样告诉我三行内容。
```

消息发出后切回 T03，再在两个对话之间切换一次。

最后再新建第三个空白对话，不手动选择模型，观察首页“本次对话模型”。

通过标准：

- T03 始终显示模型 A，T04 始终显示模型 B，两个会话互不覆盖。
- 第三个新对话重新使用官方助手的新对话默认模型 A，不继承模型 B，也不回退到历史 Claude 默认值。
- 即使模型 B 通过 OpenAI 类型 Provider 导入，也能由 Auto 正常执行。
- 文件真实存在，回复与文件一致，不出现 runtime/provider 类型冲突提示。
- 一个会话正在执行任务时，该会话的模型按钮暂时不可修改；切换其他会话不改变运行任务启动时使用的模型。

### T04-GX Grok 与 Gemini Agent 兼容

分别新建两个对话，全程保持 Auto。第一个选择模型 C 并发送：

```text
请在当前工作区创建 grok-agent-check.md，内容必须正好为：
# Grok Agent OK
- runtime: auto
- capability: file-tool

创建后重新读取文件，并告诉我文件名、总行数和第二行内容。
```

第二个选择模型 D 并发送：

```text
请在当前工作区创建 gemini-agent-check.md，内容必须正好为：
# Gemini Agent OK
- runtime: auto
- capability: file-tool

创建后重新读取文件，并告诉我文件名、总行数和第三行内容。
```

两个文件任务都通过后，分别在原 Grok 和 Gemini 对话中继续发送下面的提示词。不要手动输入任何 Skill 名称：

```text
请制作一份 4 页的“小学生家庭阅读计划”PPTX：
1. 封面
2. 每日 20 分钟阅读流程
3. 一周阅读打卡表
4. 家长陪伴建议

采用清爽、适合家长会展示的视觉风格，生成后检查文件可打开、页面内容没有明显遮挡，并告诉我最终文件名。
```

通过标准：

- 两个模型都能正常开始、调用文件工具、完成回复并及时结束处理状态，不只是进行普通文本聊天。
- Grok 的复杂工具上下文即使首字较慢，也不能在 Runtime 已完成初始化后约 45 秒被提前中止；等待期间只保留一个运行状态。
- 两个 Markdown 文件真实存在，均为 3 行；回复中的行数和指定行内容准确。
- Grok/Gemini 通过 OpenAI-compatible 面板导入时不要求改变 Provider 类型；原生 Gemini Provider 也能出现在模型列表并执行任务。
- 两个模型都能根据自然语言目标自动进入演示规划和 PPTX 生成流程，无需用户记住 Skill 名称；生成的 PPTX 可直接打开且不要求修复。
- 动态加载工具后可以继续完成后续模型轮次，不出现 `tool_reference`、`Cannot read properties of undefined (reading 'type')` 或本地 500。
- 不出现“仅支持 GPT/Claude”“Anthropic Messages 不兼容”“Codex 只支持 OpenAI 模型”等底层协议错误。
- 每个任务只出现一个最终状态，不重复回复、重复写文件或连续弹出错误卡片；失败时必须出现明确错误，不能只留下空白助手消息。

若本机暂时没有模型 C 或模型 D，只跳过缺失模型对应的半项并记录；另一模型仍需单独完成验收。

- 最多出现一个最终取消/失败提示，不连续弹出多张错误卡片。

## 5. PPT 重点验收

### T10 生成完整 PPTX

新建对话并发送：

```text
请基于当前工作区 sources 目录中的两份材料，为“夜航书房：24 小时社区学习与轻办公空间”制作一份 10 页中文商业演示文稿。

要求：
1. 先在内部完成页面规划，再生成真实 PPTX，不要要求我提供任何内部能力名称。
2. 文件名：夜航书房_品牌与商业方案.pptx。
3. 风格成熟、现代、有编辑感；使用深绿、珊瑚红和中性色形成层次，不要整套只有一种颜色。
4. 页面包含：封面、用户洞察、核心问题、目标人群、服务方案、空间与服务流程、商业模式、模拟经营看板、12 个月路线图、结论。
5. 至少包含 1 页数据图表、1 页流程图、1 页时间线和 1 页对比布局。
6. 不要只是标题加项目符号；注意中文层级、留白、对齐和内容密度。
7. 只交付一份最终 PPTX；生成后执行完整性校验，校验失败不得报告完成。
```

通过标准：

- PowerPoint 直接打开，不出现“发现内容有问题”“需要修复”或其他警告。
- 正好 10 页，页面类型有明显变化，图表、流程、时间线和对比页真实存在。
- 无文字重叠、越界、乱码、异常错位或大面积空白。
- “空间与服务方案”等概念长句不得被当作大号数字塞入指标卡；必要时应自动使用卡片或洞察布局。
- 12 个月路线图的阶段说明必须完整留在边框内；内容较长时应使用宽行路线图，而不是把长段文字塞进窄节点。
- 中文成品中没有 `Key insight`、`Translate this number into a decision` 等英文占位文案。
- 视觉质量达到可继续人工修改的商务成稿水平，而不是文字排版样稿。
- 正常流程优先使用内置 Node 生成器；不应先报“没有 Python”再临时换方案。

### T11-R 参考风格生成

把一张风格特征清楚的 PPT 页面截图放入工作区，命名为 `ppt-style-reference.png`，新建对话并发送：

```text

提取可用的配色、明暗关系、排版密度和构图语言，但不要把截图铺成页面背景，也不要声称像素级克隆。
内容包含封面、用户问题、会员方案、服务流程、权益对比和行动建议。
输出：夜航书房_参考风格方案.pptx，并完成严格视觉校验。
```

通过标准：参考截图保持只读；PPTX 可直接打开，整体视觉与参考方向可辨认且内容仍可编辑；工具结果说明参考类型、置信度与实际采用的布局语言，不把近似重建描述为原生模板复用。

若改用一份包含较多图片或图表的真实 PPTX 作为参考，再增加以下验收：新主题使用足量且彼此不同的语义相关图片，不能复用无关来源照片，也不能用一两张图反复填充；工具结果包含 `pptx-reference-composition`、相似度分数、参考/输出图片页比例、明暗比例和版式多样性。分数必须达到 70；图像密集参考稿没有可用新图片或任一关键节奏严重退化时，任务应要求补充素材或停止交付，不能生成弱近似稿并声称完成。

### T11-N PPT 模板智能适配与原生复用

先使用一份包含多种版式、图片和图表的真实 PPTX，另起对话只发送普通用户会说的两句话，不增加任何技术约束：

```text
请把工作区中的“国家公园生态系统监测年度报告.pptx”作为原生 PPT 模板，
制作一份“青少年心理健康生态支持年度观察 2026”。
```

通过标准：助手不要求用户补充母版保留、页面映射、图片替换、源文件保护、输出命名或校验规则；内部先调用模板预检并取得设计语言和逐页密度目标。由于新主题与来源结构差异较大，应优先选择 `adaptive-design`，继承配色策略、字体尺度、对齐、形状语言、图片处理和页面节奏，同时按照心理健康主题重新设计内容适配版式，不能机械照搬来源目录、数字、图标、图片语义或逐页顺序。工具结果明确 `pptx_template_strategy: adaptive-design`、`exact_package_reuse: false`，并通过参考构图相似度门槛。来源文件保持不变，结果可直接打开且不提示修复。

再测试结构相关的主题：

```text
制作一份“大熊猫国家公园栖息地连通性监测与修复年度报告 2026”。
```

通过标准：该主题与来源报告结构兼容，应使用原生 `new-deck`；新稿按来源页原型、容量和正文密度区间映射内容，保留母版/版式美感但不保留旧数据和无关图片。高密度页面不能只剩标题和少量短句；应包含结论、证据、解读或行动。不得出现孤立空卡、旧图表数据、只显示一根柱、文字截断或错位。
