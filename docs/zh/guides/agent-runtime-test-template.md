# 智能助手网页访问与登录接管专项验收手册

> 状态：当前专项回归基线
> 更新日期：2026-08-11
> 本手册只验收网页访问和登录接管能力，不作为智能助手全部功能的唯一验收入口。
> 其他功能入口见 [Zen AI 开发文档索引](./README.md)。

## 1. 测试前准备

启动开发版：

```powershell
cd C:\Users\admin\Documents\project\Zen-AI
corepack pnpm dev
```

进入“智能助手”，确认：

- Agent 运行模式保持 `Auto`；
- 模型使用 `gpt-5.6-luna`；
- 不要手动切换 Claude Code 或 Codex；
- 提示词只使用下面的自然语言，不要写 Runtime、MCP、Skill 等内部名词。

准备一个你本人有权限访问、且确实需要登录的网站。账号和密码只在网页中输入，不要发送给助手。

每项只记录：`通过`、`失败`或`跳过`。失败时保留截图、任务详情和诊断包。

## 2. 测试一：读取公开网页

在智能助手中发送：

```text
请打开这个网页，帮我看看南京明天的天气，告诉我会不会下雨、最高温度和最低温度，并把来源发给我：
https://www.weather.com.cn/weather1d/101190101.shtml
```

预期：

- 助手确实打开网页并读取内容；
- 回答根据网页信息整理，不是凭记忆猜测；
- 回答中有可以点击的来源链接；
- 不会反复打开同一个网页；
- 任务最终正常结束，不会一直显示“正在打开网页”或“正在处理中”。

如果网页打不开，助手应明确说明原因，不能编造天气和来源。

## 3. 测试二：访问需要登录的网站

把 `<网站地址>` 换成你本人有权限访问的学校、公司或个人网站，然后发送：

```text
请打开这个网站，帮我找一下里面关于本学期课程安排的资料：
<网站地址>
```

如果页面要求登录：

1. 观察助手是否打开了可见的浏览器页面；
2. 在网页中自行完成登录，不要把账号密码发给助手；
3. 登录完成后点击继续按钮；如果没有按钮，就发送“我已经登录好了，请继续”；
4. 等待助手读取页面并回答。

预期：

- 助手明确告诉你需要登录，并停下来等待；
- 不会反复打开登录页，也不会一直卡在打开网页；
- 登录后继续使用原来的页面和任务，不会重新开始；
- 能够读取登录后内容并给出回答；
- 回答结束后状态正确收口，并提供页面地址或来源。

如果网站不需要登录，直接读取成功也算通过。

## 4. 测试三：深度研究访问公开网页

在输入框点击“深度研究”，发送：

```text
帮我研究一下个人 AI 助手最近有哪些变化，看看现在大家最常用的功能是什么，还有哪些需求没有被很好解决，最后给我一份清楚的总结。
```

预期：

- 助手能够访问多个必要网页并整理资料；
- 不会陷入反复打开网页的循环；
- 研究结果有来源链接；
- 研究完成后可以继续追问，不会把普通追问再次当成新的研究；
- 最终状态从处理中变为完成，不会一直挂起。

## 5. 测试四：深度研究遇到登录

点击“深度研究”，然后发送：

```text
请结合这个网站里的资料，帮我整理一份关于本校科研项目的简要报告：
<网站地址>
```

如果出现登录页面，按测试二的方式在网页中登录，再点击继续。

预期：

- 研究任务能够暂停等待登录，而不是循环打开网页；
- 等待登录期间不会快速消耗研究时限；
- 登录完成后能够继续研究并保留前面的任务目标；
- 如果没有完成登录、网页没有权限或网页无法访问，助手会诚实说明缺失原因；
- 不会编造登录后页面中的内容。

如果你不登录，或者主动关闭网页，也要观察任务能否在合理时间内以清楚的失败状态结束，而不是一直处理中或连续弹出错误卡片。

## 6. 本轮通过标准

本轮只要确认以下几点即可：

- Auto + gpt-5.6-luna 能够读取公开网页；
- 网页内容能被总结，并提供可回溯的来源链接；
- 遇到登录时能让用户在可见网页中自行完成登录；
- 登录后能继续原任务，不丢失上下文；
- 网页打不开、登录取消或权限不足时，能够明确结束，不循环、不编造、不重复弹错。

出现网页循环、登录后无法继续、没有来源链接、虚构网页内容或任务无法收口时，停止测试并反馈。
