# 个人 Skill 导入与定时助手验收手册

> 适用版本：Zen AI v1.1.63 及后续开发版
> 更新日期：2026-08-11
> 范围：个人电脑、Auto 模式、当前工作区
> 不需要手动切换 Claude Code/Codex，也不需要在提示词中写 Skill 名称。

## 测试前准备

1. 打开开发版，确认已经导入至少一个可用 Provider 和模型。
2. 新建一个专用测试工作区，例如 `ZenAI-personal-test`，不要使用重要资料目录。
3. 智能助手保持 `Auto`，确认当前模型可以正常完成一次普通文件任务。
4. 定时任务需要一个允许自动执行的助手和已经授权的工作区。创建时明确选择执行模型；未开启开发者模式时只能看到产品允许的三款模型。
5. 定时任务测试期间保持 Zen AI 开发版运行；关闭软件或电脑关机时不会在后台补跑。

## 一、个人 Skill 导入

### 1. 导入本地文件夹

准备一个最小 Skill 文件夹，里面有一个 `SKILL.md`，内容可以是：

```markdown
---
name: test-writing-style
description: 将普通文字整理成清晰的标题、结论和行动项。
---

# Test Writing Style

当用户要求整理文字时，先提炼结论，再列出行动项。
```

在设置中进入“技能”，选择“从文件夹安装”，选中这个文件夹。

预期结果：

- 技能能够导入，名称和说明正确显示。
- 第三方 Skill 初次导入默认是停用状态，不会未经确认直接进入 Agent 工作区。
- 打开详情可以看到 `SKILL.md` 和文件树。

### 2. 启用并在任务中使用

在该 Skill 详情页打开启用开关，然后在智能助手中发送：

```text
请把当前工作区的 notes.txt 整理成一份简洁的会议结论，先写结论，再写行动项和待确认问题。
```

预期结果：

- Agent 能正常回答或生成文件，不需要用户写出 `test-writing-style` 这个名称。
- Claude Code 和 Codex 都能看到同一份已启用 Skill。
- 当前工作区会出现 `.claude/skills/test-writing-style` 和 `.agents/skills/test-writing-style` 的可用链接或等效挂载。
- 禁用 Skill 后重新执行，不应继续把它作为可用 Skill 使用；工作区中原本真实存在的 Skill 文件夹不能被删除。

### 3. ZIP 和安全边界

把同一个 Skill 压缩为 ZIP，再导入一次，确认更新不会产生重复条目。另准备一个包含 `../outside.txt` 的恶意 ZIP 进行导入。

预期结果：

- 正常 ZIP 可以导入并复用同一个 Skill 记录。
- 含绝对路径或目录穿越条目的 ZIP 被拒绝，应用不应在工作区或 Skill 数据目录外写入文件。
- 卸载后，数据库列表、全局 Skill 存储和两个 Runtime 的链接都清理干净。

## 二、个人定时助手

### 1. 创建一次性任务

进入智能助手首页的“定时任务”，新建一个一次性任务。任务内容直接使用自然语言：

```text
在当前工作区创建 scheduled-check.md，写入当前时间、任务已执行和一句“这是定时助手测试”。完成后读取文件并告诉我文件内容。
```

把执行时间设为几分钟后，保存任务。

预期结果：

- 任务立即出现在列表顶部，状态为活动，并显示下一次执行时间。
- 过去的日期和时间不能保存。
- 到时间后 Agent 使用所选模型和 Auto Runtime 在指定工作区执行，生成的会话和文件都属于这个任务。
- 一次性任务成功后变为已完成，不会重复执行。
- 只有实际会话已经创建、出现在左侧会话记录并进入完成状态后，运行日志才显示成功。
- 任务详情能看到最近结果和运行日志；点击“查看会话”会关闭任务窗口并直接打开对应会话。

### 2. 手动执行与暂停恢复

再创建一个间隔 1 分钟的任务，提示词使用：

```text
读取当前工作区的 scheduled-check.md，告诉我文件的最后修改时间和最后一行内容。
```

先点击“立即运行”，确认本次运行完成后暂停任务，再点击“恢复任务”。

预期结果：

- “立即运行”会创建本次独立运行记录和独立会话，不会重复触发同一轮执行，也不会阻塞设置页面。
- 暂停后不再产生新的运行记录；恢复后重新计算下一次执行时间。
- “恢复任务”和“立即运行”使用不同的图标、提示和行为：恢复只恢复调度，立即运行才会马上执行。
- 同一任务的每次执行都创建新会话，不复用上一轮上下文，也不会串入其他任务或普通对话。

### 3. 失败任务

创建一个一次性任务，提示词为：

```text
请读取当前工作区中一个确定不存在的文件 missing-for-scheduler-test.txt，并告诉我失败原因和下一步怎么处理。
```

预期结果：

- 任务不会卡在处理中，运行日志会记录失败原因。
- 一次性任务失败后保持暂停，可修正提示词或文件后手动重跑。
- 周期任务的单次临时失败不会立即永久删除；连续失败达到保护阈值后才自动暂停。
- 不设置固定总时长上限；连续 15 分钟没有模型输出、工具调用或状态变化时才按卡住失败处理。

### 4. 重启恢复

创建一个尚未到期的间隔任务，关闭并重新打开开发版，再回到“定时任务”。

预期结果：

- 任务配置、状态、下一次执行时间和历史日志仍然存在。
- 活动任务在应用启动时自动恢复调度，不需要重新点击保存。
- 软件关闭期间不应声称任务已经执行；重新打开后按保存的计划继续。

### 5. 一次性任务复用与执行日志

选择一个已经完成的一次性任务，验证详情页：

- 可以点击“再次执行”，不需要重新填写任务内容；新的日志标记为“手动”，并记录本次实际使用的模型。
- 可以点击“转为重复任务”，选择每天、工作日、每周或每月的时间；转换后任务恢复为活动状态，原来的执行记录仍然保留。
- 执行日志位于任务状态下方，最新记录排在最前面；运行中会自动刷新。
- 点击日志结果可以查看完整的成功内容或失败原因，而不是只能看到截断摘要。
- 进入由定时任务创建的会话时，会话名称旁显示定时任务标识。

应用在任务运行过程中关闭后重新打开，确认遗留的“运行中”记录会明确显示为应用关闭导致任务未完成，不会一直停留在处理中。

### 6. 等待用户操作

创建一个需要登录网页或确认高风险操作的任务。任务运行后切换到 AI 对话、翻译或设置页面。

预期结果：

- 运行日志进入“等待用户操作”，不能误报成功或失败。
- 无论当前位于哪个功能页面，应用都会弹出中文提示，并提供打开任务会话的按钮。
- 打开后直接进入对应会话；用户完成确认后，任务继续运行并最终收口为成功或失败。

## 通过标准

Skill 导入、启停、卸载和 ZIP 安全边界全部通过，且启用的 Skill 能被 Auto 任务实际使用；定时任务能够创建、按时或手动执行、为每次运行创建独立会话、准确记录终态与日志、暂停恢复、等待用户操作、失败可解释并在重启后恢复。出现工作区越权写入、任务重复执行、错误后永久卡住、历史日志丢失、错误标记成功、查看会话失效或任务串会话，均视为阻断问题。
