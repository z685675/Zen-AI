# 双入口 20 轮连续对话：运行与复核

本文件是操作者和报告复核者的参考卡，不是模型提示词。测试只读取同目录的 `cache-20-turns.txt`，不要将本文件作为 `--prompts` 传入。

## 启动

在 Zen-AI 项目目录运行：

~~~powershell
pnpm quality:experiment --prompts "docs/experiments/cache-20-turns.txt"
~~~

默认同时测试 `chat` 和 `assistant` 两个入口，无需填写 `--entries`。在 PowerShell 中显式指定双入口时，必须写成 `--entries "chat,assistant"`，保留逗号两侧为同一个参数。

依次输入专用测试 API Key、Provider 地址、一个或多个实际模型序号，即自动构建和执行。模型由操作者从接口返回的列表中选择，本参考卡不固定型号。

每个模型在 AI 对话（chat）和智能助手（assistant）各建立独立会话，连续执行相同的 20 条用户提示词；同一会话中保留历史，不换模型，不在每一轮重新建会话。

| 所选模型数 | 每模型每入口 | 入口数 | 计划用户轮次 |
| --- | --- | --- | --- |
| 1 | 20 | 2 | 40 |
| 3 | 20 | 2 | 120 |
| 4 | 20 | 2 | 160 |

用户轮次不是底层请求数，命名、压缩、工具循环等请求另外计入同批统计和限制。默认每轮间隔 20 秒；响应时间单独记录，不把这段固定间隔当成模型响应速度。

可重试故障等待产品原生重试，每次尝试均保留并计入预算；最终失败后停止该会话，保留剩余轮次为未执行，再继续其他模型和入口。全局预算耗尽、取消、整批超时或隔离实例清理失败时停止整批。

本轮比较两个入口的默认行为，不把智能助手强制切为 Plan。输入相同不代表系统提示、工具清单或压缩策略相同，这些属于被比较的入口行为。若决定以后使用 Plan 承载聊天，仍需另测该模式。

## 题库范围

纯文本连续对话，覆盖记忆、信息更正、基本计算、摘要和前后核对。题库要求不联网、不生成文件；观察智能助手是否仍产生额外工具或辅助请求，并将实际消耗计入。

测试初始化固定关闭 AI 对话的 Top-P；隔离助手的温度默认不启用，不读取日常安装包里的个人设置。

## 报告与比较

终端在启动和结束时打印本次 `local/quality-reports/interactive-...` 目录。重点文件：

- `report.md`：完成、失败和未执行项。
- `cost-summary.md` / `cost-summary.json`：按模型、入口汇总实际调用、已知输入、输出、缓存，以及第 1、5、10、20 轮累计观测。
- `live-observations.json`：逐轮回答、首字出现时间 `firstTextMs`、回答完成时间 `totalMs`。
- `target-<序号>-chat/calls.json`、`target-<序号>-assistant/calls.json`：各模型、入口的底层请求与可取得的请求 ID，可供服务端用量对账。

同一批报告即可按相同模型比较 chat 与 assistant，无需再把两个入口拆成两次运行。`quality:compare` 用于比较两批报告，不是本次双入口实验的必需步骤。

当前交互命令不要求填写模型价格，金额显示“未核算”，不代表免费。实际金额应结合对应测试 Key 的服务端账单与请求 ID 核对；输入 Token 已包含缓存，不能把缓存再重复相加。缓存冷暖、上游路由和服务端计价可能影响本次观测。

先确认每个所选模型的两个入口均完成 20/20 轮，再综合扣费、已知 Token、缓存、底层调用数、首字速度、完整回答速度及本参考卡的正确性核对。失败、超限、缺用量或中途停止的组合保持未完成，不据此宣布成本胜负。
