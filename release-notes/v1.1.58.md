# Zen AI v1.1.58

本次版本重点升级官方智能助手的 Auto Runtime、模型兼容、内置 Skill、会话体验和文件生成质量，同时收录 `v1.1.57` 之后完成的备份恢复、微信接入、公告中心与客户端体验改进。

建议仍使用 `v1.1.57` 及更早版本的用户升级到本版本。

## 重点修复

- 修复全新电脑首次安装后，因默认助手尚未配置模型导致首页崩溃、设置页无法进入的问题。
- 修复全新安装后，在空模型、空 Provider 或默认助手未就绪状态下，首页输入栏、模型选择、对话设置面板可能崩溃的问题。
- 修复导入 Provider 并启动 API 服务后，智能助手仍提示“先配置模型服务”，需要退出重开软件后才能进入的问题。
- 修复跨电脑恢复备份后，旧电脑用户名残留在内部数据路径中，导致官方智能助手和微信接入无法创建工作目录、无法正常使用的问题。
- 修复 `v1.1.53` 在导入备份并自动重启后，启动阶段可能卡死、窗口无法打开的问题。
- 修复跨电脑导入备份后，微信接入复用旧电脑登录凭证或旧 channel，导致扫码入口不弹二维码、历史会话和当前在线连接混在一起的问题。
- 修复图片生成页通过 `Ctrl+V` 粘贴图片时，部分场景会重复粘贴两张图片的问题。
- 修复 Provider 自动同步模型列表时，可能把手动设置为“图像生成”的模型流程类型刷为空，导致图片生成不可用的问题。

## 备份恢复

- 跨电脑恢复备份后，会自动迁移应用内部路径，包括智能助手可访问目录、会话路径、消息内容、消息元数据、定时任务结果、任务日志，以及笔记中的内部文件链接。
- 智能助手启动时增加路径自愈：即使历史数据中仍残留旧机器的 `Data/Agents` 路径，也会在创建目录前映射到当前电脑的 Zen AI 数据目录。
- 前端本地数据库和持久化状态增加恢复迁移，修正附件、消息块、话题、笔记路径在跨电脑恢复后的旧路径引用。
- 优化恢复后的路径迁移性能，对大型会话消息先做快速候选判断，避免在大体积消息内容上触发高 CPU 扫描。
- 内部路径迁移增加完成标记；没有新的恢复任务时，不再每次启动都重复扫描 `agents.db` 和笔记文件。
- 路径迁移仅处理 Zen AI / Cherry Studio 应用内部 `Data` 目录路径，不会改写微信临时目录、用户文档目录、下载目录等外部文件路径。

## 微信接入

- 恢复备份时会清理导入数据中的微信登录 token，并将恢复来的微信 channel 标记为离线。
- 会话列表会显示恢复来的旧微信会话为离线状态，历史对话仍可查看，但不再代表当前电脑在线接入。
- 点击“微信扫码接入”时，如果没有当前可用的在线微信通道，会新建一个微信 channel 并弹出新的二维码。
- 新扫码成功的微信 channel 才代表当前电脑正式在线使用。
- 微信通道设置页保留“重新扫码”操作，可在会话过期、手机微信切换绑定电脑、或跨电脑恢复备份后手动刷新二维码。

## 智能助手

### Auto 与模型兼容

- 优化智能助手内置 Agent 初始化流程：手动启动或重启 API 服务前会自动补齐内置智能助手，避免模型配置已就绪但助手列表仍为空。
- 智能助手统一使用 Auto 模式：用户只选择模型，Claude Code 或 Codex 由系统根据真实接口能力、模型特征和运行状态自动选择。
- 模型 Provider 类型、实际接入协议和 Agent 底座完成解耦。通过 OpenAI 类型 Provider 导入的 Claude 模型不再因为 Provider 标签被提前拒绝。
- 智能助手普通模式的模型列表收敛为 `gpt-5.6-luna`、`grok-4.5` 和 `gemini-3-flash-preview` 中当前可用的模型；开启开发者模式后仍可选择全部模型进行兼容性诊断。
- 智能助手新增本地协议桥接：Grok、Gemini 以及仅提供 OpenAI Chat 的模型无需额外安装对应 CLI，也可以在 Auto 下继续使用 Claude Code 的任务编排、文件工具、MCP 和内置 Skill；原生 Gemini Provider 同时纳入 Agent 模型列表。
- 修复 Grok 在 Claude Code 通过 `ToolSearch` 动态加载文件工具或内置 Skill 后，协议桥误读 `tool_reference` 工具结果并返回 500 的问题；未知工具结果类型现在会安全保留并继续任务，不再中断整个 Agent 循环。
- 修复 Grok 等协议桥模型已完成 Runtime 初始化、但因复杂工具上下文首字较慢而被统一 45 秒保护提前中止的问题；启动超时与首个可见结果超时现已分离。无输出的候选切换前会先终止旧尝试，所有候选失败时显示明确错误，不再留下空白助手回复。
- Anthropic 渠道继续由 Claude Code 直连，GPT/OpenAI Responses 继续优先使用 Codex；协议桥接只在模型渠道与 Runtime 原生协议不匹配时启用，不改变现有优化路径。
- 模型列表不再按底层 Runtime 隐藏模型；历史 Provider、OpenAI-compatible 网关和协议元数据未知的渠道均保留真实兼容性尝试机会。
- 修复通过 OpenAI 类型导入 New API 面板时，Grok 等模型虽然带有网关端点元数据，AI 对话仍误用通用 `openai-compatible` 适配器的问题；现在保留模型声明的实际协议和用户 Provider URL，同时使用网关适配器组装请求，兼容校验更严格的上游渠道。
- Provider 返回非成功 HTTP 状态时会记录脱敏的请求字段、错误参数和上游请求编号，便于区分渠道拒绝与网络中断；日志不会记录 API Key、完整提示词或附件内容。
- 默认助手、快速和翻译模型统一升级为 `gpt-5.6-luna`；已有用户升级或重新导入含该模型的 Provider 时会覆盖旧的 `gpt-5.4` / `gpt-5.4-mini` 默认值，让后续新对话自动使用新模型，历史智能助手会话保持原模型。
- 普通 AI 对话新增话题级模型快照：新建或复用空对话时使用当前默认模型；用户在首页切换模型后，当前对话立即生效并成为后续新对话的默认选择，但不会反向改写其他已有对话。升级前已有内容的对话继续沿用原助手模型，不会被 Luna 批量覆盖。
- 修复旧版模型设置数据在升级后被误解释为“新对话默认值”，导致首个会话使用 `gpt-5.6-luna`、后续新建会话又回退到 Claude 的问题；迁移只修正官方助手默认值，不改历史会话。
- 智能助手设置中的模型改为“新对话默认模型”；修改默认值或重启应用都不再批量覆盖历史会话的模型。
- 复用尚未发送消息的空会话时，会先对齐当前新对话默认模型，避免复用旧空会话时带回过期模型。
- 新建对话首页新增“本次对话模型”下拉，可以在发送第一条消息前覆盖 `gpt-5.6-luna` 默认值。
- 每个会话独立保存自己的模型，在 A/B 会话间切换不会串模型；运行中的会话会锁定模型选择，并继续使用任务启动时的模型快照。
- 智能助手初始化会等待 Provider 和模型状态就绪，避免启动阶段暂时读到空列表后出现模型下拉为空或默认模型迁移失败。
- Claude Code 与 Codex 均兼容各自平台原生可执行文件；缺少依赖、模型配置无效等启动前错误会立即返回，不再长时间停留在“正在处理”。
- 修复同一会话切换模型或底层 Runtime 后错误复用旧 SDK 线程 ID 的问题；Codex 本地会话不存在且尚未输出时会自动新建线程恢复一次。
- Auto 只允许在没有文本、工具调用和文件副作用前尝试一次备用 Runtime，避免重复回复、重复工具调用或重复生成文件。

### 工作区、会话与任务状态

- 优化智能助手本地路径识别，避免把桌面、文档、下载等目录误写到 `C:\mnt\data`。
- 支持配置多个可访问目录，并可将任一目录设为当前工作区；切换或移除工作区不会清空模型列表和 Agent 设置。
- 修复工作区切换后当前会话仍短暂使用旧目录、需要来回切换或多发一次消息才生效的问题；切换操作现在等待服务端持久化和会话缓存刷新，并同步仍在继承助手默认目录的会话，单独定制过目录顺序的会话保持不变。
- 增加失效工作区路径自愈，兼容目录被移动、删除或从其他电脑恢复后的历史 Agent 和会话数据。
- 用户消息发出后立即保存新会话，不再等待模型开始回复后才出现在会话列表。
- 收紧智能助手会话自动命名：任务完成后优先生成摘要标题，标题模型失败时从首条指令或附件名兜底，并自动修复历史列表中已有内容的“未命名”会话。
- 自动命名改为后台执行并正确同步分页列表缓存，不再延长任务处理状态；用户手动设置的话题名不会被自动覆盖。
- 输入框草稿按 Agent 和会话独立保存，在不同任务之间切换时不再串入其他会话。
- 返回正在执行的会话时自动定位到最新消息和进度附近，不再默认回到对话顶部。
- AI 对话右侧跳转轴改为每个完整问答回合一个节点，悬浮时以深色问题和浅色回答显示内容预览；超长对话支持独立滚动、较早回合提示和未渲染历史跳转，离开底部后可从输入框上方一键返回最新消息。
- 统一流式事件顺序和终态处理：成功、失败或取消后忽略迟到事件，避免完成后继续显示“正在处理”或再次追加回复。
- 任务状态栏以最终助手消息和工具状态共同收口；工具中途失败但任务成功恢复时显示成功，真正失败时只显示一次最终错误。
- 修复同一错误在流处理、Runtime 和 UI 多层重复上报时连续生成多张错误卡片的问题。
- 优化智能助手任务状态和错误兜底提示，缺少运行依赖时给出更明确的修复建议。
- 新增智能助手诊断包导出能力，便于后续排查用户侧问题。

### 内置 Skill 与文件生成

- 官方助手内置十个生产力 Skill：Skill 发现、演示规划、PPT、Word、Excel、PDF、Markdown、研究报告、中文内容创作和会议纪要。
- 用户无需记忆 Skill 名称；官方助手会根据“做 PPT、生成 Word、分析 Excel、整理会议纪要”等自然语言目标自动选择并组合相关 Skill。
- 同一份内置 Skill 自动同步到 Claude Code 的 `.claude/skills` 和 Codex 的 `.agents/skills`；源 Skill 更新后会通过指纹自动刷新旧工作区。
- `find-skills` 改为优先审计真实内置能力，并能说明 Skill 中的脚本、模板、参考资料和校验器，不再只给出泛化推荐。
- 新增统一文件生成工具，Claude Code 与 Codex 使用相同的 PPTX、DOCX、XLSX 和 PDF 参数、权限检查与交付结果。
- PPTX、DOCX、PDF 新增 29 种共享视觉风格，可根据自然语言主题、受众、标题和文档类型自动选择；用户无需记忆 Skill 名称或风格 ID。
- `create_file` 新增 `visual_style`、`document_type`、`style_mode` 和 `brand_theme`，并在结果中返回最终风格、来源和模式。品牌色可覆盖调色板，同时保留对应布局语言。
- PPT 模板不再自动轮换蓝、绿、黄、紫单页强调色，默认使用文档级协调色阶；封面构图、页面导轨、卡片形状、背景和字体会随正式、编辑、教育、自然、科技、高端等风格一起变化。
- PPT 视觉风格从“主题换色”升级为 14 类独立布局语言：企业叙事、高管决策、咨询排版、正式报告、技术、产品、数据、强视觉、品牌、编辑、活泼、人文自然、高端和极简会改变封面、流程、时间线、图表、图片页的几何与阅读路径；默认企业风也不再回退到标题加等宽方框。
- PPT 在视觉语言之上新增结构型、空间型和动势型构图画像，会根据报告/分析、建筑/场所/作品集、发布会/艺术节/活动等语境自动改变封面、章节、洞察、图片和页面导轨；同一编辑或品牌风不再永远复用一套简约骨架。
- PPT 新增关系网络、四象限矩阵、分时日程和旅程/空间路线版式。复杂关系、优先级、活动安排和体验路径可使用专属语义结构，不再统一退化成卡片或流程页。
- 品牌、文化、展示、活动、场所、作品集和产品发布类演示会主动规划主题相关视觉资产；真实图片必须通过 `assets` 与 `image_asset_id` 嵌入，缺少可靠素材时保留可用排版回退，不再用设计说明文字冒充图片。
- PPT 新增独立的论证结构推断：助手会在简报、金字塔、叙事、教学和展示结构中自动组织故事，再独立选择视觉风格；用户无需记住 Skill、结构名或风格 ID。
- PPT 新增参考风格生成：用户可直接提供 PPTX 或页面截图并用自然语言要求“按这个风格做”。PPTX 可指定代表页强调配色与主题字体，同时仍按全稿继承图片/报告页节奏、明暗比例和最接近的布局语言；截图会近似分析配色、构图重心、留白、边缘/纹理特征、摄影覆盖和表面处理，并用这些结果驱动布局而非只换颜色。
- 截图参考新增 `pptx-reference-design-language` 相似度检查，成品会比较构图偏向、空间节奏、装饰密度、表面处理、对齐和形状语言；无法恢复的字体、图标、精确坐标和母版仍会明确说明。
- 参考 PPTX/截图始终只读，生成结果写入新文件并返回参考类型、代表页、置信度和页面比例兼容性；参考风格模式不会误报为精确模板克隆。
- 修复参考 PPTX 被新主题的自动风格推断覆盖、最后只保留相似配色的问题；参考稿现在优先决定布局语言，模型同时传入的主题推断型 `visual_style` 会被忽略并记录原因。
- 参考 PPTX 新增全稿构图画像与交付闸门，覆盖全幅摄影、摄影章节、图文、图表、密集/开放报告页原型，以及图片比例、文字密度、明暗比例和版式多样性；指定深色封面不再把整套输出变成深色。
- 参考生成结果新增 `pptx-reference-composition` 与 0-100 相似度详情；低于 70 分、图片比例严重下降、版式多样性塌缩、明暗节奏错误或重复图片过多均直接阻断。来源图片不会为了凑媒体密度被盲目复用到无关主题。
- 新增原生 PPTX 模板模式：可在完整副本中修改指定页并保持其他页字节不变，也可按来源页重组新演示，精确保留原母版、版式、主题、媒体、图表和关系。
- 原生模板的新主题生成支持最小自然语言请求：用户只需说明来源模板和新主题，助手会自动推断故事线、页数、输出名和页面映射，替换无关图片，保护来源文件，并在交付前校验及内部重试，无需用户编写工程化约束。
- 原生模板工作流新增模板预检工具：助手会先识别每页的内容类型、排列方式、条目容量、图片要求与图表类型，再围绕新主题重新规划内容和页面映射；不会因为模板页顺序或固定槽位而照搬来源内容。
- PPTX 模板/参考画像新增配色策略、字体尺度、对齐倾向、形状语言、信息密度、图片处理与页面节奏，并返回每页安全正文密度区间；高密度来源页只填入少量短句会在写文件前被拦截。
- `pptx_template` 新增 `adaptive-design`：新主题与来源页面结构不匹配时，自动保留来源设计语言并改用内容适配的原生 PPTX 版式，不再为了“像模板”机械套用旧页面；结果会明确标记并非原包复用。
- PPT 严格规划新增版式类型、构图家族、单一版式占比和连续重复检查；渲染验收新增全稿密度异常与底部留白失衡提示。
- 修复通用文本框误占首条内容、年份标题被拆成数值、三栏标题与正文错位、模板语义图标残留、图表固定纵轴只显示单柱等问题；超容量内容会优先换用合适版式或生成续页。
- 原生模板 PPTX 改用 Office 兼容重打包，并完整移除重组后失效的 Notes 关系；生成文件应可直接打开，不再依赖 PowerPoint“打开并修复”。
- 原生模板支持标准 PowerPoint 标题/副标题/正文占位符、Shape 名称/原文字精确替换、多母版、多版式和同一来源页重复复用；`preserve_content` 可不改写 slide XML 地克隆来源页，`image_asset_id` 可在保留原裁切和边界的情况下替换来源页主图片。
- 截图仍只用于近似视觉重建，不会铺成背景冒充可编辑像素克隆；图片占位符替换、SmartArt 和动画编辑会明确提示当前不支持。
- PPT 的 `visual` 字段恢复为纯设计提示，不再在缺少结论时被当成可见正文，避免英文设计指令混入中文成品。
- Word 风格保持明亮可编辑，映射为原生标题层级、字体、引用、代码和表格；PDF 支持更强的固定版明亮、深色及灰度打印表现。
- 文件写入前新增统一交付校验；`verified` 现在包含 UTF-8/Markdown、OOXML 部件/XML/关系/内容类型和 PDF 页数等真实检查结果，不再只确认文件存在。
- PPT 创作增加页面规划、图表、流程、时间线、对比布局和视觉质量约束，不再以标题加项目符号作为可交付结果。
- PPTX 生成器补齐主题、母版、版式和 OOXML 关系，移除容易触发 PowerPoint 修复的无效 notes 部件，并校验重复 Shape ID、关系目标和母版结构。
- PPTX 增加按内容语义选择版式和文本容量保护：长句不会再被误放进指标卡，密集流程与时间线自动改用宽行路线图，所有文本框启用边界内缩放，并阻止英文生成器占位文案混入中文成品。
- PPTX 新增严格视觉结构校验，连续修改或自定义脚本生成的页面若使用会撑大文本框的自动适配、遗漏显式字号或存在潜在遮挡，将在交付前被拦截。
- PPTX 校验新增危险外部关系、空页、Unicode 替换字符和可见 Markdown 作者标记检查。
- DOCX 将内部 Markdown 正确转换为 Word 原生标题、列表、强调、链接、引用和表格，修复文末重复附加整份 Markdown 源稿的问题。
- Word 校验会阻止可见的 `#`、`**`、Markdown 表格线、重复标题和疑似原始源稿表作为最终交付。
- Word 校验新增空正文、原生标题结构、Unicode 替换字符和可见标题次数检查。
- Excel 支持多工作表、公式、冻结窗格、筛选、数字格式、条件格式和图表，并在交付前校验工作簿结构。
- Excel 公式校验新增直接、间接、跨工作表及范围型循环引用检测，避免工作簿打开后要求修复或报告循环公式。
- Excel 图表会根据分类数和数据点密度自动关闭全量数值标签，小型图表则把标签固定在柱体外侧；严格校验会阻止数字覆盖坐标轴或在图形底部堆叠。
- Excel 新增原生折线趋势图与自适应非零纵轴，并核对 `SUMIF`/`SUMIFS` 的公式缓存；筛选标签错误导致的全零序列、空趋势和 `0–1` 空坐标轴会在交付前被拦截。
- PDF 支持可搜索中文、多页内容、跨页表格、文本提取和扫描 PDF OCR，并在交付前校验页数和文本。
- PDF 支持有序列表、引用和代码块，自动去除与显式标题重复的首个 H1，并可阻止 Markdown 作者标记泄漏。
- 新增 Markdown 内置 Skill 与严格校验器，覆盖 UTF-8、标题层级、代码围栏、表格列数、危险链接和本地链接目标。
- Skill 脚本从实际安装目录执行，不再把 `scripts`、`node_modules` 或散落的生成脚本写入用户工作区根目录。
- PPTX、DOCX、PDF 新增统一的工作区图片资产契约，包括方向校正、PNG 转换、文件与像素限制、替代文本、缺失引用检查和未使用资产提示。
- Word、PDF 和 PowerPoint 可以真实嵌入本地图片；PPT 图片页使用内部媒体关系、独立 Shape ID 和有边界的图片版式。
- PDF 新增页面级渲染、空白页和页面边缘内容检查；Office 输出明确区分已渲染、不可用和已跳过，并支持 LibreOffice 或 Microsoft Office 严格导出验收。

### 托管 Python 与本地 OCR

- 新增面向所有用户的 Zen AI 私有 CPython 3.12 环境。它位于应用数据目录，不依赖、不修改用户系统 Python、PATH 或全局包。
- 首批内置数据与文档包覆盖 pandas、NumPy、Excel、图表、Word、PPT、PDF 和图片处理等常用生产力任务。
- Office 文件继续优先使用稳定的 Node 生成器；Python 用于数据分析、Skill 脚本和交付校验，普通文件生成不需要等待 Python 初始化。
- Claude Code 与 Codex 共用 `python_execute`、`ocr_file`、`create_file` 和环境诊断工具。
- 图片 OCR 默认使用简体中文和英文，繁体中文需要明确选择；Windows/macOS 先使用系统能力，中英混排会比较 Tesseract，其他内容在系统结果偏弱时回退，普通候选都偏弱时再追加一次高对比度识别。扫描 PDF 支持逐页渲染识别。
- OCR 的 TXT/Markdown 输出会保留可用换行、空行、段落和页码，并清理明显的汉字间异常空格；精确字体、坐标、分栏和表格复刻不属于纯文本输出范围。
- OCR 会校正图片方向、透明背景和小图分辨率，并返回逐页质量分、候选数及低可信页；存在低可信页时明确标记“带警告完成”，不再把可疑结果描述为完全成功。
- OCR 默认本地运行，不要求配置第三方 OCR API，也不会为任务临时安装未知 Python 包。

## 统一上下文管理

- AI 对话不再按照固定的 1、5 或 10 轮截断历史；旧设置只保留数据兼容，不再影响实际请求。
- 系统会根据模型和 Provider 返回的容量动态计算安全输入预算。未声明容量的 New API 模型默认按 256K 规划，其他未知模型按 200K 保守规划。
- 长对话接近安全线时自动生成结构化检查点，保留最近原始对话；完整历史、文档文本、OCR 文本和长工具结果继续保存在本地。
- 超长粘贴文本、多个大文件和大量图片会采用切块、OCR、分批视觉分析和资料召回，避免直接截断或一次性塞满模型窗口。
- OpenAI 兼容、Anthropic 和 Gemini 请求继续使用已有 Prompt Cache 能力；稳定历史前缀与版本化检查点可提高缓存复用，但缓存不会被当作无限上下文。
- 智能助手保留 Claude Code、Codex Runtime 原生的 session、resume 和压缩机制；应用只预检本轮超大输入并召回本地资料，避免重复压缩整段历史。
- 模型高级设置可覆盖上下文容量和最大输出容量，用户填写的字段不会被后续 Provider 模型同步覆盖。
- 清空或删除对话时，会同时清理对应的本地检查点和上下文资源，避免遗留无效缓存。
- Word、PDF、PPTX、XLSX 资料会保留可获得的页码、幻灯片号、工作表、单元格范围、表格和章节定位，旧资料召回同时使用精确关键词与轻量本地语义匹配。
- 修复 New API/OpenAI-compatible 渠道中的 PDF 被按 Base64 二进制体积估算、普通多页 PDF 被误判为超大上下文并请求失败的问题；兼容渠道改为先在本地提取带页码文本，确认支持原生 PDF 的官方协议仍使用原生文件输入。
- 图片 OCR、缩略图和视觉描述按内容哈希缓存；重复使用同一图片或 Office 文件时会复用解析结果，输入框上方可查看处理进度及缓存、压缩、召回统计。
- 多模型候选回答改为按会话隔离并在发送后清空，避免候选模型跨会话残留或被误认为会话主模型自动切换。
- 资料与上下文状态不再覆盖整个模型生成过程；资料准备完成后立即显示就绪，普通模型或网络失败也不再误报为上下文处理异常。状态详情明确区分已索引资料、解析缓存、历史整理、相关资料调用和容量重试。
- 当中转渠道的真实上下文容量低于声明值时，系统会在尚未输出内容的前提下自动降低预算并仅重试一次，不会先弹失败卡片再继续运行。
- Claude Code 或 Codex session 丢失、Runtime 切换时，智能助手会使用本地检查点和最近对话恢复一次；超大 Agent 工具结果会完整保存为本地资源，避免撑满后续请求。
